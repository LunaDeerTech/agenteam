# Add Skills

Use this guide when the task needs reusable instructions that are not already available in the current skill directory.

1. Check the skills currently available to you. A name or description in a management directory does not grant access to its files or permission to use it.
2. If useful instructions may already exist, use only the search, retrieval or file capabilities actually available and authorized for this task. Do not invent a tool, a network bypass or another user's credentials. If the needed capability is unavailable, report that dependency and stop that path.
3. If no suitable existing package is available, write or summarize the relevant experience as clear instructions. Prepare a package with exactly one root `SKILL.md`. Include references, scripts or assets only when they are needed. Keep every path relative to the package; do not include escaping paths, links, device files or secrets.
4. Send the package through the platform's available, authorized skill installation capability. Supply a controlled business file reference or the supported text-file input, not an object-storage key, signed URL or local server path. A downloaded file or uploaded object is not proof that a skill was installed.
5. Wait for a confirmed immutable skill revision. Retry or look up the same accepted operation when its result is unknown. Do not replace a same-name skill implicitly; an update must identify the existing skill and the expected version.
6. Installation publishes to the Project library. It does not assign the skill to an Agent. Request assignment separately through the current authorized configuration or assignment capability, identifying the target Agent. If you lack this permission, ask the authorized user or agent to perform that step.
7. Read and use only revisions authorized by your current execution and assignment. Do not silently switch an existing execution binding to a newer library revision. Keep a user's explicit disable or removal intact.

This guide grants no tool, model, mount, network or command-execution permission. Central does not execute package scripts or install their dependencies as part of installation. Follow the normal approval and runtime controls whenever a later task actually uses such resources.
