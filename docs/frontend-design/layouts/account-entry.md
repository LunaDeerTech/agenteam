# 账号入口布局

> **v1 历史布局/业务参考。** 新页面设计以 [v2 页面蓝图](../redesign/page-blueprints.md)与[目标设计系统](../redesign/target-design.md)为准；下文旧视觉、宽度和占位要求不再作为重设计约束。业务字段和流程需核对当前架构、工作项及源码，不能仅凭本历史文档判定已实现。

> 业务来源：[账号认证架构](../../architecture/platform-infrastructure/authentication/README.md)。本页仅定义可见页面、字段和反馈。

## 1. 页面职责与区域示意

登录、邀请注册、找回和重置使用独立居中面板，不显示已登录导航。

```text
产品标识 / 当前页面标题
┌────────────────────────────┐
│ 步骤说明                   │
│ 表单与字段错误             │
│ 主操作 / 返回登录           │
│ 投递结果或链接失效提示     │
└────────────────────────────┘
```

## 2. 栏目、字段与操作

| 页面 | 字段 | 操作及反馈 |
| --- | --- | --- |
| 登录 | 邮箱、密码 | 登录 / 找回密码；无公开注册入口 |
| 邀请注册 | 邀请邮箱只读、用户名、显示名、密码、确认密码 | 验证链接后显示表单；用户名占用提示更换，成功提示返回登录；失效提示联系管理员 |
| 找回密码 | 邮箱 | 提交请求；202 受理后显示投递渠道说明；底部返回登录；不公开 token 或账号存在性 |
| 重置密码 | 新密码、确认密码 | 有效链接才可提交；成功返回登录，失效可重新发起找回 |

初始化、邀请有效期和撤销、注册消费、密码与 Session 规则均以[账号生命周期](../../architecture/platform-infrastructure/authentication/account-lifecycle.md)为准，不在布局中另行定义。

用户名与显示名分开说明：用户名全站唯一，允许英文字母、数字和连字符，大小写不区分；它用于可读项目路径，登录仍使用邮箱。设密表单统一提示 15–128 个字符、允许中文和空格、不强制字符组合；弱密码和其他校验错误来自服务端，输入不自动截断或去除首尾空格。

登录连续失败达到服务端规则时，在原表单中展示验证码/人机挑战；按返回结果更新挑战及错误，不显示递增等待或固定冷却倒计时。

## 3. 默认选择与导航

根路径和受保护路由先查询 Session；未登录或无法确认时进入登录页，不显示受保护内容，内部仍区分匿名与查询失败。直接打开普通登录页时，有效 Session 进入首页或合法返回目标，其余情况显示正常表单。首屏 Session 查询失败保持静默，不展示技术检查或放弃按钮。

登录成功进入系统首页或经重新授权的指定目标。管理员首次登录显示改密建议及个人设置密码页入口，可以继续使用系统。邀请邮箱不可通过表单修改；已登录账号访问另一身份邀请时提示身份不匹配，不自动绑定。

## 4. 投递、加载与异常

链接验证中显示加载，网络失败可重试；提交中禁重复操作。字段错误就近展示，成功后清空密码输入。

登录提交时确保完成必要的 Session/匿名 CSRF 准备，并在业务请求前验证；找回在用户点击提交后才开始该准备流程。准备和提交期间在主按钮显示加载状态；失败保留输入，在按钮附近显示一条简短错误，字段错误仍就近展示。结果未知时保留原请求材料，只能明确重试原请求；必要的离开确认保持，不把首屏简化当作放弃未知命令。

找回只在真实 202 受理后显示中性的 SMTP 或日志渠道说明，不因邮箱是否已注册、具体投递结果而泄漏账号存在性；保留邮箱，允许沿既定流程再次请求，底部保留返回登录入口，不展示恢复链接或 token。仅 SMTP 未配置时说明由有权访问后台日志的人协助转交；已配置但发送失败不切换日志。投递诊断和重试由授权管理入口展示，公开回执仍遵守同一隐私边界，详见 [SMTP Delivery](../../architecture/platform-infrastructure/authentication/smtp-delivery.md)。

重复请求不暗中延长仍有效链接。密码重置成功后提示重新登录；管理员也使用相同找回流程，不提供专用管理员重设入口。

## 5. 窄屏

面板单列适配可用宽度，长邮箱换行，按钮和返回入口保持可达，不产生页面级横向溢出。
