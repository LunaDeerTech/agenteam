# 界面设计逻辑

> 状态：2026-10-14 统一页面设计规则。基于已定样式与领域布局，将 Linear 的低噪声操作界面和包豪斯的功能、比例、几何秩序落实为页面组合规则；不表示现有页面已全部实现或验收。

## 1. 来源与目标

本页负责**信息怎样组织、空间怎样分配、操作在哪里完成**。[样式规范](styles/README.md)负责颜色、字体、控件和动效，[页面布局](README.md#3-文档索引)负责对象、入口、默认选择与领域流程，架构及工作项负责权限、状态和 API。新页面先选本页模板，再落实对应布局；不从 API 字段表或 Debug 示例拼出整页，也不为“统一”重写已有工作台。

项目表式列表、独立创建弹窗、固定导航、禁止眉题及共享 token 已有正式要求；现有页面偏离这些要求属于落实问题。本次补齐的是页面类型、宽度角色、信息取舍和操作载体的共同选择逻辑，不重新包装已有要求为新产品决定。

目标是专业、简洁、精致且便于持续工作的应用：用户能迅速认出当前位置、主要对象、当前状态和下一步。简洁来自信息优先级和稳定结构，不是去掉字段标签、必要说明、边界或恢复入口。

- **Linear 的取舍**：使用石墨灰阶、克制强调色、紧凑控件、细分隔和清晰选中态；标题、内容与动作有稳定对齐关系。避免大面积品牌色、每项独立重阴影、四处卡片套卡片。
- **包豪斯的取舍**：用网格、比例和少量圆/方/线组织功能。几何标记可用于品牌、对象类型或空态锚点，不成为每段的装饰，不用颜色和形状假造业务分类。已有状态色优先，不另加红黄蓝主题。
- **克制有边界**：每个区域仍有识别、分组和交互反馈。避免把页面做成一列无层次文字，也避免为填满空白添加统计、活动或尚未提供的功能。

不使用 eyebrow（标题上方装饰性眉题）；不引入远程字体、每页独立控件主题或持续装饰动画。具体值继续引用 [typography-and-density](styles/typography-and-density.md)、[colors-and-themes](styles/colors-and-themes.md) 和 [components-and-interactions](styles/components-and-interactions.md)，不在本页复制 token 表。

## 2. 页面骨架与类型

系统导航固定在顶部；项目工作台保留其下的项目导航。页面内部侧栏负责当前范围的选择，主区完成当前任务，辅助区解释当前对象；这三者不能各自变成一套全局导航。

```text
固定系统导航：品牌 / 系统入口                         当前账号
项目导航：仅项目工作台存在
────────────────────────────────────────────────────────────
        页面外边距
        [可选范围侧栏]  当前页标题               主动作
                        筛选 / 视图工具栏
                        主要内容           [可选辅助详情]
                        分页 / 继续加载
```

图中的侧栏和辅助区按任务选择，不要求每页三栏；全局搜索等入口仅在业务能力已提供时显示。保留 [应用框架](layouts/application-shell.md) 的导航顺序和 [项目工作台](layouts/project-workspace.md) 的项目边界。

| 页面类型 | 主区职责与结构 | 侧栏 / 辅助区 | 典型映射 |
| --- | --- | --- | --- |
| 集合列表 | 标题与主动作 → 筛选 → 可比较的行 → 分页；不自动选择第一项 | 默认无侧栏；确有长期分类时才增加 | 项目、用户、Provider、产物目录、Inbox |
| 实体工作台 | 稳定范围选择 → 当前对象/视图 → 连续操作；内容使用剩余视口 | 侧栏选择项目内对象；辅助区显示所选对象详情，可独立滚动 | 任务 Kanban/Explore、会议 |
| 设置表单 | 当前栏目标题 → 按目的分组的字段/只读状态 → 保存与取消 | 保留固定宽度的设置菜单；编辑区有阅读宽度 | 个人资料、系统配置、项目配置 |
| 阅读与编辑 | 对象标题/模式 → 正文；编辑器使用明确保存/退出入口 | 目录用于选择，元信息与引用按需展开；阅读正文有行宽约束 | 知识文档、产物预览、Task Plan |

模板可组合：设置内的 Provider 目录使用集合列表，进入编辑后使用设置表单；知识库外层是工作台、内层是阅读/编辑。以当前任务决定区域，不为复用组件而强行套成同一种页面。

## 3. 信息优先级与动作

每个可见字段都应帮助用户**识别对象、比较或判断、理解状态、执行下一步**。页面设计先列出这四类必要信息，再映射真实领域字段；服务端返回不等于默认展示。

1. 名称/标题是首要入口；一段短描述补充用途，位置或对象关系提供上下文。
2. 会影响当前操作的状态紧邻对象；时间、类型、大小等仅在本任务需要比较时成为列表列。
3. UUID、version、操作 ID、存储引用、内部错误码等默认留在需要排障或审计的详情。确有复制、定位或恢复用途时标明字段含义，提供完整值；不要把技术值当列表装饰或用户必须理解的步骤。
4. 可读名称不能代替稳定身份或授权；隐藏字段只改变呈现，不删除并发/恢复材料。权限、失败和未知状态必须保留真实含义。

页头采用标题在左、当前主要动作在右。常规单任务区域只有一个高强调动作；次要动作使用普通或文字按钮，危险动作与日常创建/保存分开。刷新、每页数量和清除筛选不与“新建”争抢主按钮层级。按钮按内容占宽，不因父级 grid 默认 stretch 铺满整页；只有适合触屏的窄屏表单才主动使用全宽按钮。

当前路由叶子使用一个页面级 `h1`，分区使用下级标题，外壳不重复输出页面标题；弹窗使用自身有名称的标题。只读页面不必硬放一个彩色主按钮。

筛选属于列表工具栏，页容量和上一页/下一页属于列表底部。保持既有显式提交或即时筛选契约；需要提交时区分输入中的条件与已应用条件。没有全量检索契约时不新增看似搜索全库、实际只过滤当前页的输入框。数量注明是当前页还是总量，服务端未提供总数时不虚构页数。

## 4. 宽度、对齐与密度

以下是本次统一的**工程布局默认值**，不是用户逐项指定的样式值，也不新增全局 CSS token。各页面在所属容器实现；确需偏离时在对应布局说明内容理由，不能让窗口宽度或临时数据随意决定比例。

| 容器 | 桌面默认约束 | 空间不足时 |
| --- | --- | --- |
| 集合列表 | 居中外容器最大 1120px，包含左右各 24px 内边距；标题、工具栏、行内容与分页共享对齐线 | 左右内边距 16px，行按信息优先级重排 |
| 设置 | 外容器最大 1200px；菜单 216px、间隔 24px；右侧内容最大 800px | 不挤压字段，菜单转覆盖面板，表单单列 |
| 工作台 | 外层使用可用宽高；范围侧栏默认 248px，具体页面可在 216–280px 内选定一个宽度；辅助区默认 280px | 优先收起辅助区，再将侧栏转覆盖面板，保持主任务可用 |
| 阅读正文 | 主阅读列最大 800px并在所属主区居中；代码/表格可在自身容器滚动 | 正文适应可用宽度；不靠缩小字号容纳长行 |
| 简短创建/编辑弹窗 | 使用现有 `UiDialog` 的最大 560px；正文与操作区分开 | 使用组件已有视口边距和最大高度，正文滚动，操作可达 |

不对整个 `app-content` 设置列表的最大宽度；Kanban 和多区工作台需要自己的空间。桌面侧栏使用固定宽度或明确断点值，不默认提供拖拽分栏，不让两栏无限按比例拉伸。超宽屏增加页外留白，不能同时放大控件、描述行长与侧栏。需要用户调节宽度的专业编辑器另在其页面说明用途与上下限。

页头到工具栏使用 24px，工具栏到列表使用 12px；不同内容分区使用 24px，同组字段或对象信息按已有 8/12/16/24px 尺度组合。页面、控件和弹窗各管自身内边距，避免容器层层叠加 24px。页头只保留一处页面标题；进入弹窗后使用弹窗标题，不再包一张同名卡片。

单行紧凑目录以现有 `--row-height` 为最小值；含名称和描述的常规列表以 64px 为起点、垂直内边距 12px。它们都是最小密度而非固定裁切高度；长名称、必要错误和触屏操作可使行自然增高。对象名称使用既有 14px/600 层级，状态/辅助信息服从已有字体规范。宽度不足优先调整结构，不一律缩小字体或挤成多列。

## 5. 操作载体与关闭规则

先判断任务是否需要持续空间、是否依赖底层上下文、能否在一次清晰提交中完成，再选择载体。字段数只是辅助，不能以“超过几个字段”机械切换页面。

| 载体 | 适用任务 | 组合规则 |
| --- | --- | --- |
| 页面 / 工作台主区 | 需要长时间阅读编辑、独立导航、多个阶段或持续比较的任务 | 保留当前范围与返回路径，明确保存/退出；复杂流程不能靠不断叠加模态实现 |
| Dialog | 边界清晰的创建、短编辑、选择和危险确认 | 独立标题、正文、footer；项目创建固定用此方式，不在列表行或工具栏下展开完整表单 |
| Drawer / 辅助面板 | 查看或处理当前列表/看板对象，同时需要保留来源位置 | 关闭返回原选择与滚动位置；窄屏可占满可用空间；不会自动变成新全局导航 |
| 内联编辑 | 当前对象的短小属性，保存影响清晰，邻近上下文足够 | 有明确开始、提交、取消和错误；不把独立新建流程塞进列表或把整页永久变成表单 |
| 锚定菜单 / Popover | 少量动作、值选择或简短说明 | 不承载多字段完整任务；保持共享控件已有语义与键盘行为 |

已定领域场景可有合理组合：Task 详情在 Kanban 中用抽屉、Explore 中用主区；产物的页内预览保留列表来源和原返回焦点；已有文本产物/知识编辑弹窗保留其完整读取、草稿及原请求恢复流程。长文编辑后续是否迁入主区，按编辑连续性和内容空间单独落实，不能仅为符合模板而丢失恢复能力或默默改交互。

一次创建或编辑至少明确以下阶段：

- **打开与输入**：聚焦首个有效输入；字段标签、帮助、错误相邻。草稿是否需放弃确认按实际后果与领域规则处理；完整表单默认不因点遮罩而丢失输入。
- **提交中**：禁止重复提交，保持操作位置与等待说明。关闭、Escape、遮罩和路由离开统一经过业务关闭策略；关闭界面不等于取消服务端工作。
- **已接受/结果未知/失败**：显示真实阶段及可用下一步。未知时保留原请求恢复入口，只执行领域允许的查询/恢复；不自动另建对象、换 key 或宣称完成。
- **完成**：只有业务完成条件成立才显示成功。反馈与进入目标遵循对应业务契约；创建已接受不等于已可使用。关闭、身份或上下文切换后的迟到响应不能强制跳转、复活旧内容或抢焦点。
- **关闭与切换**：按上述领域关闭策略，需要放弃确认时提供继续编辑/放弃；存在未决写入时解释本地离开与服务器结果的关系。关闭后回原触发入口，入口消失时回所属区域标题；权限变化按既有规则撤下私有内容。

组件能力须以 [公共组件接口](../development/frontend/components.md#浮层) 为准：当前 `UiDialog` 没有通用 `size` 或 `beforeClose` prop，不能仅在文档中假设已支持宽弹窗。其关闭按钮会请求更新 `open`；业务有关闭门禁时，使用受控 setter 把关闭意图交给 owner，不能直接绑定可写状态绕过规则。`data-autofocus` 用于初次打开；输入切换为结果面板后的焦点由页面在当前身份/当前请求仍有效时安排。正常关闭保留组件实例，让共享层管理器完成焦点恢复；`fallbackFocus` 仅作为触发位置失效后的后备。

## 6. 列表、表格与卡片

| 形式 | 选择条件 | 呈现重点 |
| --- | --- | --- |
| 紧凑列表 / 表式行 | 主要任务是识别名称、扫读描述、查看少量状态并打开对象 | 单一列表容器、细分隔、稳定名称起点；不为每一行增加大圆角和阴影 |
| 语义表格 | 用户需要跨行比较多个同类属性 | 可见列头、对齐列、caption；大表局部横向滚动；不把分页/排序能力从外观推导出来 |
| 卡片 | 单个对象具有独立内容层级，或空间位置本身有意义 | Task 看板、预览、审批等；组内一致，信息足够才使用，不以卡片数量填空白 |

名称入口保留真实链接语义，次要行操作使用按钮。不要在可点击整行中嵌套冲突的交互，也不要无键盘等价地给普通 div 加点击。可点击名称、状态列及尾部入口在各行对齐；删除中无合法目标时不保留伪入口。

描述在列表中一行或两行截断，完整内容通过可访问的查看入口取得；截断名称须有完整可访问名称/提示，不能仅依赖鼠标悬停。无描述可留空或使用必要的轻量占位，不重复生成成屏的“未填写描述”。详情和编辑正文保留完整内容。

状态徽标只表达真实的生命周期、可用性或处理状态，颜色与文字同时表达；普通属性不全都变成 pill。活跃与归档的权重弱于正在处理或失败；不能把“已接受”“正在归档”“未知”涂成已完成的绿色。繁忙/只读的原因放在相关动作或区域，不要求用户解读内部操作 ID。

## 7. 状态与恢复的呈现层级

状态属于原区域：整页身份检查影响页面可见性，列表失败放列表，字段校验放字段，单个详情读取失败不拆除导航或清空其他独立区域。成功遵循已有按钮反馈规则，不增加底部成功 toast。

| 情况 | 用户应看到什么 | 下一步 |
| --- | --- | --- |
| 首次读取 | 保持页头/区域结构的行骨架与等待文字，避免内容跳动 | 阻止依赖未加载数据的操作 |
| 真正空集合 | 简洁几何标记（可选）、一句事实、短说明；不占据巨大海报区 | 该范围允许创建时给创建入口 |
| 筛选无结果 | 明确是当前条件没有结果，保留筛选 | 清除/调整筛选；不冒充系统无任何数据 |
| 读取失败 | 就地原因与重试；保留已授权且仍可展示的旧完整数据时标明“上次读取”，不混成最新 | 按原查询重试；权限拒绝不能保留旧私有内容 |
| 已接受 / 正在处理 | 当前阶段与可执行操作，保持对象可识别 | 查询/等待/取消仅按领域已提供能力显示 |
| 结果未知 / 版本冲突 | 未确认或冲突事实，保留输入与原意图 | 查证原结果或明确处理新版本；不自动重发/覆盖 |
| 无权限 / 对象已失效 | 撤下不可访问内容，显示真实不可用状态 | 返回所属集合或合法入口，不能伪装成空列表 |
| 部分功能不可用 | 在相应操作/区域给出简短可理解原因 | 保留其他真实可用操作；不补造演示结果 |

文案先描述用户关心的事实，再给动作，如“尚未确认创建结果 → 查询创建状态”。错误中不输出内部堆栈、凭据或完整技术请求；需要排障的安全标识放明确诊断详情。既有真实错误和恢复限制不能因视觉精简而隐藏。

## 8. 响应式、主题与可访问性

- **重排次序**：先让工具栏/操作组换行，再隐藏非必要辅助区或转覆盖面板，最后将列表行与表单改为纵向组织。桌面固定侧栏变窄屏菜单，不变成挤占正文的微型栏。断点由可用主区决定；项目列表 650px 以下采用堆叠行，设置沿已有 760px 侧栏切换，其他工作台在对应布局记录所需断点。
- **滚动职责**：应用内容、目录、正文、辅助区只有各自必要的滚动；外层与内层不重复截断同一正文。窄屏不允许页面级横向溢出，Kanban/代码/宽表的滚动限定在其容器；100dvh 和实际导航高度留出操作空间。
- **窄屏触达**：视觉控件沿已有 token，交互区域按需扩大到至少 44px；不为了密度把图标按钮挤在一起。弹窗正文可滚动，标题、关闭与操作可达；屏幕键盘出现时仍能看到当前输入与提交入口。
- **主题**：全部使用现有语义颜色，浅深主题信息权重一致；分隔线、选中态、焦点与错误不能在暗色消失。正文/说明满足 4.5:1，必要识别图形、边界及焦点至少 3:1；不依靠颜色单独表达状态。
- **键盘与阅读顺序**：视觉和 DOM 顺序一致；链接负责导航、按钮负责动作；图标按钮有名称。原生表单标签/错误关联，真实 table/list 语义，避免只加 ARIA 而无完整键盘行为。模态锁焦点，背景不可操作，关闭可恢复；焦点环不能被容器裁掉。
- **验证尺寸**：至少覆盖 390、834、1024、1440px，另用 1920px核超宽留白；检查两种主题、200%缩放、长中英文名称和减少动效。它们是布局检查目标，不表示已有这些测试或真实设备证据。

## 9. 项目列表范例与落地检查

项目页使用集合列表模板：限宽主区；“项目”标题和“新建项目”主动作；状态筛选与轻量刷新；名称/简短描述、生命周期、进入入口组成表式行；分页及每页数量在底部。普通列表不显示版本/操作 UUID，不额外添加成员、日期、虚构总数或全库搜索。

“新建项目”打开独立 Dialog，填写名称和可选描述；未完成创建的查看/恢复仍使用同一任务容器，不能在页面插入完整创建区。完成是否进入工作台、失败与原请求恢复遵循 [系统页面](layouts/system-pages.md) 和项目创建契约。空集合给创建入口，筛选无结果给清除条件；窄屏名称/状态同排，描述次排，操作保持可达。

其他页面的映射以第2节表格为起点：[设置框架](layouts/settings-shell.md)承担固定菜单与受控表单；[任务](layouts/tasks.md)保留树/看板/详情的不同职责；[会议](layouts/meetings.md)以消息和输入为主，详情可折叠；[知识库](layouts/knowledge-base.md)用目录选择和阅读列；[产物](layouts/artifacts.md)保留集合到内容的明确返回路径。相同控件复用，不抹平领域差异。

每次新增/完善页面，在对应工作项或评审说明中用几句话交代页面类型、主要任务、宽度与滚动、主动作载体和状态恢复；不新建重复设计档案。实现及评审使用下面的短清单：

1. 当前范围、主要对象与下一步能否一眼识别；展示字段是否支持用户判断，而非照搬 DTO？
2. 是否选定页面模板并约束主区/侧栏宽度；标题、工具栏、列表和分页是否对齐，超宽是否仍有合理行长？
3. 创建/编辑载体是否符合任务；主次动作清楚，正文与操作区分离，关闭/提交门禁一致？
4. 加载、真空态、筛选空态、旧数据、失败、未知、冲突和权限变化是否各有真实呈现与合法动作？
5. 浅深、窄屏、长内容、键盘焦点和恢复是否可用；截断有完整信息入口，背景与滚动是否正确？
6. 是否复用已有组件/主题，实际 CSS 变量是否已定义，且未假设不存在的 props、API 或业务功能；局部合理例外是否在所属布局说明？
7. 是否实际查看代表截图并走关键交互；报告是否明确区分设计目标、静态实现、接口 fixture 和真实后端验证？

本页是持续适用的设计与评审规则；共享实现入口见[页面组合与滚动](../development/frontend/components.md#页面组合与滚动)。具体页面的实现范围、工程检查和浏览器/真实后端验证以对应工作项及交付记录为准，不能由规则存在、代码改造或候选截图推定已通过验收，也不能将接口 fixture 结果当生产验收。
