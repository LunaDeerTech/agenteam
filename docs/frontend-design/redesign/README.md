> 2026-10-15；本轮完成新设计规范、调研与规划，样板定稿及产品实现未开始。审计基线为本地 `work` 分支 `ce2f8467`，不代表其他功能分支或当前生产环境。所有后续实施阶段均为“未开始”。

本次目标是重新设计完整页面和连续操作体验：对标 Linear 的信息层级、空间比例、排版、表面层次和交互完成度，解决当前界面呈现为字段、控件与分隔线堆叠的问题。仅换颜色、收窄间距或减少边框不构成完成。

## 本轮边界与文档优先级

本轮修改相关规范、技能/角色入口及调研文档素材，不修改 `web/src/`、测试、依赖、后端、OpenAPI 或业务状态机。调研截图使用现有正式页面及隔离 fixture，只能证明指定视口中的呈现，不能证明真实服务、权限、生命周期或生产集成通过。

后续重设计任务按以下顺序使用来源：

1. 用户本轮方向及固定信息层级；正式架构中的权限、生命周期、数据完整性和恢复约束。
2. 本目录重新建立的 **v2 正式设计规范**：信息结构、页面组合、组件职责和状态/交互规则从现在起指导后续设计；F0 用完整页面样板校准精确颜色、尺寸与视觉细节。
3. 当前源码及正式架构/工作项中的业务字段和能力边界；旧布局仅作历史业务参考，冲突时核对实际实现与正式契约。
4. 旧视觉规范、CSS token 与 Debug 组件作为迁移输入。它们是本轮审计对象，不能以“符合旧规范”判定新设计合格。

旧规范保留为历史材料；[处置矩阵](audit.md#4-旧规范处置矩阵)解释被替代的视觉策略和继续有效的业务约束。本轮直接建立 v2，不逐条修补 v1。F0/F1 校准 v2 视觉值并同步实际 CSS/组件；旧青蓝强调色、26px 标题、统一尺寸和包豪斯表述不再约束新设计。新规范是后续工作的正式来源，不表示样板已验收或产品已迁移。

## 实现快照与后续集成

本地路由有 36 个正式叶子定义，覆盖账号、系统首页、项目列表、个人设置、系统设置、项目空间及其已接入功能；另有 3 个重定向、404 和仅开发环境可用的 `/debug`。[页面蓝图](page-blueprints.md)逐项覆盖。

本地快照没有正式 Meeting、Inbox、全局搜索、Task Explore、Memory 或 MCP 路由。既有 [M3 恢复记录](../../../.agent-state/current.md)记载了其他功能分支的成果；本轮没有把这些历史分支记录当成本地可运行页面，也没有否定它们的已有成果。后续取得实际集成版本后进入 F7 适配；这些依赖不阻塞已存在页面的重设计。

本轮规划完成不等于 M3、完整前端、真实端到端或生产发布完成；原任务台账中的接受范围、失败和 STOP 保持各自含义。

## 技能与后续启动方式

后续从 [agenteam-frontend-redesign](../../../.agents/skills/agenteam-frontend-redesign/SKILL.md) 开始，按任务复用设计、Vue 开发、测试工程与独立验收技能；具体阶段绑定见[执行计划](implementation-plan.md#2-技能与职责入口)。技能负责避免遗漏和偏离，页面效果与真实行为仍需实际验证。

F0 须先把项目列表、任务工作台与复杂设置页的完整效果做实，再冻结可复用规则。任何阶段都不能用静态样板、截图 fixture 或一个成功控件来替代该阶段要求的真实功能验收。
