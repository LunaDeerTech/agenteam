## 本轮边界与文档优先级

F0 修改本目录的设计正文、独立原型、浏览器 harness，以及本次授权归位的可复用技能方法与来源；不修改 `web/src/`、产品依赖、后端、OpenAPI 或业务状态机。样板使用按真实字段构造的合成数据；原三类基础样板曾与正式 Vue 页以相同 fixture 对照。当前先以正式 Vue 的 general 页为基线；旧 F0 没有此页，不能声称它提供了同内容前后对照。原型交互与截图证明各自浏览器范围，不证明真实服务、权限、生命周期或生产集成通过。

后续重设计任务按以下顺序使用来源：

1. 用户本轮方向及固定信息层级；正式架构中的权限、生命周期、数据完整性和恢复约束。
2. 本目录重新建立的 **v2 正式设计规范**：信息结构、页面组合、组件职责和状态/交互规则是返修起点；受用户反馈影响的结构与第 8 节视觉值待完整页面重新验证，不能继续当作已接受基准。
3. 当前源码及正式架构/工作项中的业务字段和能力边界；旧布局仅作历史业务参考，冲突时核对实际实现与正式契约。
4. 旧视觉规范、CSS token 与 Debug 组件作为迁移输入。它们是本轮审计对象，不能以“符合旧规范”判定新设计合格。

旧规范保留为历史材料；[处置矩阵](audit.md#4-旧规范处置矩阵)解释被替代的视觉策略和继续有效的业务约束。本轮直接建立 v2，不逐条修补 v1。F0/F1 校准 v2 视觉值并同步实际 CSS/组件；旧青蓝强调色、26px 标题、统一尺寸和包豪斯表述不再约束新设计。新规范是后续工作的正式来源，不表示样板已验收或产品已迁移。

原 `ce2f8467` 快照有 36 个正式叶子定义；原 11 个正式路由、17 个视口/主题组合的 fixture 视觉抽样继续作为历史证据，不改写为新主线的全站覆盖或通过结论。现行[页面蓝图](page-blueprints.md)已按 `3fc44101` 的增量更新为 **40 个正式叶子（36+4）**，项目设置由10增为11叶；3个重定向、404和开发 `/debug` 不计入正式叶子，Agent Memory是内嵌面板而非新路由。

**主线衔接：** `origin/main@3fc44101` 已包含正式交付的 M3，接受范围见 [M3 工作项](../../development/work-items/m3-knowledge-memory-collaboration.md)。新主线路由已有项目 `meetings/:meeting_id?`、`inbox`、`settings/mcp` 及 `/mcp/oauth/callback`；Agent 设置已有 Memory 面板，不能再称这些功能在当前 main 不存在。此前主线衔接仅据新 router、Agent 页面和正式 M3 摘要核对这项变化，没有重新进行产品或全站视觉验收。全局搜索、Task Explore 等其他目标仍按实际代码和契约判断。

F0 已按当前 API 与页面核对新增页面/面板，并制作独立样板；F1—F6 按当前导航/Session协调、MCP工具审批、Knowledge四格式文件及PDF能力修订保真要求，F7明确负责现有Meeting、项目Inbox、MCP/OAuth与Agent Memory的重设计，F8依赖F2—F7并覆盖全部40叶及内嵌面板。新增样板曾纳入原 F0 浏览器检查；正式产品迁移仍须在对应实施阶段实看，不能以样板替代；这不影响沿用M3各自固定输入的既有功能证据。此前主线衔接只发布规划文档与既有技能/角色配置；原 F0 曾获得限定输入下的内部独立检查通过；用户实看后否定设计，该结论不能代表当前设计接受，F0 已重开且不启动产品重构；M3 的完成来自其正式交付记录，不来自本轮设计审计，原接受范围、失败和未覆盖事项保持各自含义。
