# 前端设计 v2：目标设计系统

> 这是后续重构采用的正式设计规范，信息结构、组合方式、组件职责和状态/交互规则已在本轮建立；产品实施状态为“未开始”。精确颜色、尺寸和视觉细节仍须 F0 完整样板校准，下列数值是本项目候选，不是 Linear 官方精确 token，也不是本轮已经修改的 CSS。

## 1. 设计方向

内容应先于界面装饰被看见：首先辨认当前项目和对象，其次看到状态与可执行动作，再按需要查看配置和诊断。精致感来自字体层级、比例、对齐、表面区别、交互反馈和真实内容在一起的效果；边框数量、颜色克制或统一组件只能支持这个结果。

目标采用 Linear 2026 参考中的低存在感导航、明确 location bar/view bar、浅而连续的内容表面、清晰的名称入口与局部属性编辑。保留本项目的双层导航范围：系统导航负责系统首页/项目列表与账号；项目 header menu 负责项目内功能。不会复制 Linear 侧栏造成另一套组织层级。

配色先验证中性灰阶与清晰状态，再比较低饱和蓝紫、青蓝等少量强调色候选。强调色只承担主动作、焦点和选中语义；不能用全站彩色侧栏或所有状态一律 pill 制造层次。F0 同时检查浅深主题，完整页面确定最终强调色；不沿用旧色即视为违规的判断。

## 2. 应用框架与空间职责

```text
┌──────────────────────────────────────────────────────────────────────┐
│ agenteam    首页    项目                          [可用的系统设置]  账号 │ 系统层
├──────────────────────────────────────────────────────────────────────┤
│ ‹ 项目  /  项目名 ▾       概览  会议  待办  任务  知识库  产物  设置 │ 项目层
├──────────────────────────────────────────────────────────────────────┤
│ 当前视图 / 面包屑                        筛选   视图切换   主要动作 │ 视图层
├────────────────┬───────────────────────────────────┬─────────────────┤
│ 范围目录（可选）│ 主要内容                          │ 对象属性（可选）│
│                │                                   │                 │
│ 独立滚动       │ 主要工作区滚动                    │ 按需展开        │
└────────────────┴───────────────────────────────────┴─────────────────┘
```

会议与项目待办已在 `3fc44101` 的项目导航接入，须纳入当前重设计；待办不是跨项目的全局 Inbox。首页和项目列表没有项目层；账号页使用独立框架。项目 header menu 保持可识别的横向功能菜单，项目名称/路径表达归属，不把对象目录提升为第三套全局菜单。项目名的下拉只承担已有合法项目操作/导航；没有稳定契约时先用普通名称和返回链接。

- 系统层保持稳定、轻量；项目 header 让当前项目比系统品牌更容易辨认。目标初值分别约 44px、48px；视图工具栏约 40px，按内容存在，不为凑齐三条横线额外添加空条。
- 已在项目 header 表达的项目名不在内容区再写一遍大标题；当前视图/文档仍有唯一页面级标题。面包屑承载父子对象路径，页标题承载任务，两者不机械重复。
- 项目列表和设置使用适当行宽；任务、知识和会议使用剩余视口。表面切换、间距与字重先表达区域，分隔线只用于真正边界。
- 页面级滚动只归一个主容器。工作台可有目录、正文、属性区各自滚动，必须保证滚轮落在某区只移动该区，页头和主要操作仍可达；不可外层与内层同时裁切同一正文。
- 窄屏保留系统层级和项目上下文：系统入口折叠菜单，项目菜单可横向滚动并保留当前选中；目录/详情转单一覆盖面板或全宽内容，关闭返回原对象和位置。

## 3. 初始尺度与验收指标

| 项目 | F0 初始候选 | 判断方法 |
| --- | --- | --- |
| 字体 | 继续优先本地系统字体；正文 14px/约 1.5 行高，次要文字 12–13px；中文不能靠过细字重降噪 | 同一完整页面用真实中英文、长名字和段落比较；次要信息仍可读 |
| 标题 | 系统/集合页 22–24px，工作台对象标题 18–22px，分区 14–16px；不所有页固定同一个大标题 | 首屏主要对象与动作清楚，嵌套视图无重复大标题 |
| 控件 | 桌面常用高度 30–32px，密集局部控件 28px；交互命中范围独立于可见轮廓 | 键盘、鼠标及触屏实际可操作；390px 宽主要触控目标不少于 44px |
| 行密度 | 紧凑可比较列表约 40–44px；名称+描述列表约 56–64px，必要内容自然长高 | 常规对象可在一屏扫读，错误与长名称不被固定高度裁掉 |
| 间距 | 以 4px 为基准；同组 4/8/12px、分区 16/24px、页面边距 24–32px | 同组显著近于异组；避免层层 24px 累积和孤立控件 |
| 容器 | 集合约 1080–1200px；表单正文约 680–760px；阅读正文约 720–820px；工作台全宽 | 1920px 不把短字段无限拉长；1024px 不压缩成不可读多栏 |
| 侧栏/详情 | 设置菜单约 208–224px；资源树约 232–264px；属性面板约 280–320px | 主任务空间不足先收辅助区；用户不必为了阅读拖动布局 |
| 圆角/阴影 | 输入与按钮约 5–7px，浮层约 10–12px；阴影用于真实浮起层，不在每行重复 | 模态/菜单能从页面辨认，列表不碎成一堆相同卡片 |
| 色彩与边界 | canvas、content、subtle、hover、selected、overlay 分语义；弱线不承担全部分组 | 浅深主题均可识别区域；去掉装饰线后信息结构仍成立 |
| 可访问性 | 正文/说明对比度至少 4.5:1；必要图形/焦点至少 3:1；状态不只靠颜色 | 用最终 token 实测，不能因为“像 Linear”降低对比度 |

数值最终只保存在正式 token 与对应规范，页面不另造同义局部变量。F0 可以按真实内容调整上述区间；验收记录调整理由，不能把这些初值再次冻结为无需页面验证的结论。

## 4. 页面组合与组件职责

| 模式 | 目标组合 | 重构边界 |
| --- | --- | --- |
| 集合 | 精简标题+主动作、就地筛选、连续列表/表格、底部分页 | 复用真实列表/分页模型；不添加当前页伪搜索或虚假总数 |
| 设置 | 分组菜单、栏目标题/短说明、按目的分组字段、就近保存、独立危险区 | 复杂实体采用目录→详情/编辑；不把所有新建和编辑表单常驻堆叠 |
| 工作台 | 稳定项目上下文、局部视图栏、范围目录、主内容、按需详情 | 树、看板、会话不能强塞进普通居中卡片 |
| 阅读/编辑 | 标题/模式切换、正文、可收起元信息、明确保存/返回 | 长文本优先获得完整工作空间；迁移必须保留原草稿与请求恢复 |
| 短任务 | 名称清楚的 Dialog，正文与 footer 分离，提交反馈在任务内 | 关闭、Escape、遮罩、路由离开共用业务关闭规则 |
| 对象详情 | 桌面抽屉或主区，窄屏全宽；来源、焦点与滚动可恢复 | 导航保留稳定对象身份；不能用纯临时选中替代可直达链接 |

基础组件继续以 `web/src/components/ui/` 为归属；需在 F1 核对组件现有接口后扩展，不在设计稿中假设已有 `size`、`beforeClose`、拖拽分栏或全局命令面板。业务 API 客户端、composable、Session/Project guard 和请求协调者优先保持；只有清楚的视图职责边界才能拆分，不能因换布局重写并发与恢复协议。

## 5. 信息与动作优先级

名称/标题是主要入口，状态靠近对象，关键阻塞与下一步紧邻动作。默认列表仅显示用户比较所需的信息；ID、version、请求标识、技术码移至明确命名的“详细信息/诊断”区，审计页按用途保留稳定身份。必要安全信息、权限原因、错误和 Unknown 不折叠到用户找不到的位置。

每个任务区域最多一个高强调主动作，次要动作使用中性按钮/菜单；“刷新”“每页数量”“清空筛选”不抢创建与提交。危险操作与常规操作隔开，并明确对象及影响范围。图标按钮有可访问名称，不能靠 tooltip 才知道核心操作是什么。

创建与编辑不等于同一种布局：短新建使用 Dialog；持续编辑在主区；单属性可内联；多实体管理先选对象再编辑。列表不能在空态、顶部工具栏、行内和详情同时重复多个同等强度的新建入口。

反馈归属具体任务。保存中、已接受、已完成、失败、Unknown 和冲突分别呈现；保存按钮附近可以显示短结果，但长流程与结果未知必须有持久的区域反馈及恢复入口。允许根据任务重写旧“所有成功只能在按钮”规则；不引入抢焦点、自动消失而丢失关键事实的通知。

## 6. 状态、键盘与窄屏统一要求

| 状态/场景 | 目标呈现与操作 |
| --- | --- |
| 首次加载 | 页头与结构保持，按内容显示骨架/等待；不先闪真空态 |
| 真空集合 / 筛选无结果 | 前者给事实和已有创建入口；后者保留条件并可清除；不绘制假数据 |
| 读取失败 / 部分失败 | 错误在所属区域，有明确重试；独立已授权区域保持；旧数据若允许展示须注明 |
| 401/403/404 / Session checking | 按现有 guard 撤下私有内容或受控等待，不伪装空列表、不保留旧身份数据 |
| 写入中 / 已接受 | 限制重复提交，显示当前阶段；离开界面不宣称服务端取消 |
| Unknown / conflict | 保留原意图和草稿；只给领域允许的 lookup/重新读取/确认动作，不自动换 key 重试 |
| 归档 / 删除 / 运行中只读 | 在相关区域明确原因；不提前隐藏未完成删除的对象，不把已取消执行自动重启 |
| 键盘 | Tab 顺序与视觉一致，菜单箭头/Escape完整，链接/按钮语义正确；模态锁焦点与恢复；危险动作不靠 hover |
| 390px / 200% 缩放 | 无页面级横溢；工具栏重排，属性面板先收，表格/代码/看板仅局部横滚；输入、关闭和提交均可达 |
| 长内容 / 动效 | 名称有完整可访问文本，正文不全局截断；动效仅服务状态切换并响应减少动效 |

## 7. 怎样判定“像 Linear 且适合本项目”

F0/F1 必须提供同一数据、同一视口的整页前后对照，参考 [Linear 研究](linear-reference.md)对应的空间与任务模式。逐项检查：当前位置能否立即辨认、主要对象是否先于边框/表单被看到、动作是否与对象相邻、首屏是否有合理密度、次要信息是否退后但仍可达、连续操作是否无需频繁开关重叠面板。

以项目列表、任务工作台、复杂设置页三个样板同时成立作为系统有效的证据。只有 token 表、一个漂亮空态、Debug 控件或单张无真实内容的截图，不能作为后续全站迁移依据。
