# 前端设计 v2：分阶段执行计划

> 2026-10-16 用户已授权从零重建 Vue 前端，不再等待全站 HTML F0 完成。旧 `web/` 归档为 `web-crape/`，新 `web/` 不复用旧 API 客户端、Session、权限或业务实现；必要后端接口随具体页面任务重新设计。当前先共享 UI、AppShell、单一 SettingsShell 与已定路由骨架，先系统设置，未讨论正文只有标题和空区域。

原 40 个叶子定义与产品蓝图继续用于核对页面归属；Agent HTML 和旧前端保留作对照，其历史技术/交互结论不证明新工程。原 F0—F8 编号保留为领域分组，旧串行依赖与“只改展示层、保留客户端”的实施方式由本轮方向替代。

## 3. 所有阶段共用的实施与退出规则

- **输入明确。** 记录基线、当前路由、真实数据/操作能力、参考样板和唯一写者。M3 已合入主线的范围从当前代码核对，其他分支成果须先取得实际集成代码，不从历史状态表拼页面。
- **新工程边界明确。** 新 `web/` 从零实现，不复用 `web-crape/` 的 API client、Session、权限、composable 或业务实现。后端接口只随具体页面任务设计，当前骨架不预置旧请求协调、登录守卫或隐含业务流程。
- **产品目标与接入分开。** 已确认的 Owner/admin、生命周期、结果不确定、Secret 等产品约束仍须在相应页面设计中落实；旧实现成熟度不能删减目标。未讨论正文保持标题和空区域，不用旧代码、假表单或静默成功填补。
- **同输入看整页。** 对照同 fixture、同 viewport、同主题与相同展开状态的旧页/新页；代表完整页面同时检查真实内容、长内容和异常。Fixture 只证明视觉/特定交互，写入/授权/恢复另用相关真实链路。
- **验收按影响。** 运行受影响的工程检查和关键行为测试；共享组件变更检查其消费者。权限/完整性/Secret/Unknown 等实际风险由非作者验证。既有证据在输入未变时复用，不为改间距重跑无关全站后端矩阵。
- **退出明确。** 作者自查及适用独立审查结论齐，达到阶段视觉与功能条目，失败/未验证范围被列明，相关规范与当前状态一致。视觉失败必须返修，不能以类型检查通过代替。无需在每个子步骤请求用户重复确认。
- **回退有边界。** 新工程按明确范围交付；旧 `web-crape/` 仅作归档，不与新工程混合运行或形成两套现行组件。后续接入真实写操作时，代码回退不能清除已经产生的服务端事实。

原 Agent 四 Tab HTML 的限定内部检查与受影响返修保留于[样板说明](prototype/README.md)。本轮的新 Vue 框架、工程检查与独审须独立记录；以下 F0 章节保存旧样板目标与结果，F2—F8 保存后续页面设计输入，不表示当前已启动正文迁移。

## 4. F0：完整页面样板与视觉系统定稿

**依赖/范围：** 当前 v2 规范；实际已存在的项目列表、任务、复杂设置和内容页面。开工时补核截至 `3fc44101` 已集成的 Meeting、项目 Inbox、MCP、Agent Memory 页面/面板对导航、样板和共享组件的影响，不重新全量审计或扩大旧 fixture 结论。文件范围为本目录及后续指定的独立设计样板材料；若需要交互原型，使用明确归属的隔离演示入口，不接管正式路由或后端。

**原 HTML 返修范围（历史）：** 保留 general 用户反馈后的开放表单、项目设置共同宽页头/左起点，以及 Agent 初始列表→独立详情→返回的身份、位置/焦点与草稿保护。当前补齐 Agent 明确产品目标：列表比较与浏览、Preset/初始化、模型推理、工具/Core、完整 Mount 与 Secret/Skills、Memory 字段和历史、结果恢复闭环；详情按基本配置/能力与资源/记忆/审计四 Tab 分工，保存边界与完整清单以[项目设置蓝图](page-blueprints.md#53-项目设置11-个叶子)为唯一来源。审计只承载可复用授权的查看/撤销，不是设置变更日志。本轮候选已完成所述功能测试、独审与受影响返修；覆盖、实际输入和限制统一见[样板说明](prototype/README.md#agent-目标与样板覆盖)。此为 Agent 限定内部结果，仍待用户实看，不代表全 F0 或用户接受。Agent 删除生命周期和手工 Memory 纠正仍未定。MCP 仅改页头，不扩其他页面或推进 F1。方法见[前端重设计技能](../../../.agents/skills/agenteam-frontend-redesign/SKILL.md#从一个完整页面建立方法)。

**视觉验收：** 每个样板明确映射 L1—L8 的相关结构；不是只有色板、组件墙或截取局部。主内容、状态、主动作可立即辨认；基础三类及新增协作/连接样板使用同一系统仍有适合任务的密度；新页面必须实际查看，旧11路由fixture不能代证。Dashboard 有用且没有虚构聚合指标，任务首屏由任务主导，设置不叠成 API 字段墙。

**功能验收/退出：** 每个动作标注正式产品规则、接续依赖与合成边界；不能用已有接口范围删减本轮获授权的目标，也不能把样板成功当真实服务结果。检查四 Tab 的独立保存、Preset/初始化实际结果、完整浏览、授权撤销、Unknown 可确认终态，以及加载/失败/只读/冲突、关闭、键盘、浅深/窄屏/原生缩放与减少动效。旧三 Tab 证据只按未受影响输入复用，新增内容需有实际检查；样板与 token 的接受状态分别记录，不预称用户认可或 F1 开始。无需把每个视觉细节变为单独用户审批。

**非目标/回退：** 不做全站产品迁移，不修改真实业务接口或自行定义未定生命周期，不冻结未经完整页面验证的色值。候选不合格时在样板范围调整，不影响现有产品。

**原 F0 的限定检查结果（历史）：** [隔离样板](prototype/README.md)已提供三类基础与两类 Dashboard、Knowledge 四格式、Meeting、项目 Inbox、MCP/OAuth 和内嵌 Memory 的可操作页面；额外产物页只保持已有导航完整。当时采用的共享视觉值保留于[目标设计系统](target-design.md#8-f0-可实现视觉值与组件使用决定)，当前待重新校准；所有读写反馈均标注样板边界。作者自查、[浏览器 harness](prototype/test-README.md)与[独立视觉审查](prototype/review/README.md)分别记录。当时最终定向组通过基础 21/21、PDF/四格式/token 4/4、MCP/OAuth 恢复 2/2；原矩阵中会议窄屏和 Knowledge 正文位置失败已按同输入返修复验。当时独立审查报告通过全部 11 类必需样板及关键旅程，包含最后发现并修复的 Knowledge 原生 200% 长名称低高度阅读问题；原输入连续滚动、继续读取与 390/1440 回归均独立复验通过。原始失败、返修与证据边界保留在上述检查入口。上述事实不代表真实业务接入，也不能覆盖其后用户的设计拒绝；原视觉接受结论已撤回，返修结果以当前检查和用户实看反馈分别记录。
