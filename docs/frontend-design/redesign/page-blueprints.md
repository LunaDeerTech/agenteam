# 前端设计 v2：页面蓝图与覆盖矩阵

> 这些蓝图定义后续重构目标，不表示v2已经实现。当前范围按 `3fc44101` 校准为40个正式叶子（原 `ce2f8467` 的36个+M3新增4个）及Agent Memory等内嵌面板；项目设置共11叶。`P` 表示 `/:username/:project_name`。原审计截图仍只覆盖旧基线11路由，新增页面未做本轮视觉抽样，后续须实际查看。所有页面共用[目标设计系统](target-design.md)的真实状态、键盘与窄屏规则。

## 1. 固定信息层级与页面归属

```text
系统首页 Dashboard
└── 项目列表
    └── 项目空间（显示当前项目身份）
        └── 项目 header menu
            ├── 概览 Dashboard
            ├── 会议
            ├── 待办（当前项目 Inbox）
            ├── 任务（现有 Kanban；Explore 后续能力）
            ├── 知识库
            ├── 产物
            └── 项目设置
系统导航另有：个人设置；系统设置（仅管理员）
账号入口另用独立框架；404 保留合法返回入口
```

逻辑层级不意味着用户每次必须逐级点击；直接对象链接优先并恢复正确项目上下文。项目 header menu 的层次和功能归属保留，视觉密度与窄屏展开方式重新设计。

项目首页复用当前已授权 Project 元信息及真实路由入口。快捷区可用一组连续行或少量同表面入口，不能演变成无数据的统计卡片墙。归档/处理中状态和可用动作来自真实生命周期，设置入口不能绕过只读边界。

最近访问项目、跨项目待办、任务数量/趋势、执行统计和活动流均属于**数据依赖待确认**的增强，不是当前首页的前置门，也不能先用 fixture 值填入正式页面。

### 2.3 账号入口

参考 L1 的排版与降噪原则；本轮没有 Linear 登录产品页实看证据，不宣称认证页 1:1。

四种入口共享窄而舒适的认证正文区：品牌/返回→任务标题→必要说明→有标签的输入→唯一主动作→相关入口。错误就近、成功/等待不换成技术状态墙；长错误自然换行。旋转挑战只在真实要求时出现，窄屏键盘开启后输入与提交可达。Session 检查及邀请/reset 链接沿既有 `router/account-link.ts` 的捕获与清理规则：在创建浏览器 history 前取出并清除 fragment/history，只由当前页面 owner 内存持有必要令牌；不额外持久存储、回填 URL 或写入普通文案/日志。

| 路由 | 当前到目标的信息优先级 | 主动作 / 次动作；关键状态 |
| --- | --- | --- |
| `/` | 空 Dashboard → 你的项目、真实账号提示、进入工作 | 项目入口 / 查看全部；目录空/失败与 Session 分离 |
| `/projects` | 已有表式列表 → 名称、真实状态、入口，技术信息下沉 | 新建 / 筛选、刷新、分页；准备中、Unknown、只读 |
| `/login` | 认证字段与错误 → 单一登录任务，挑战按需 | 登录 / 找回密码；检查中、挑战失败、确认 Session |
| `/invite` | 邀请信息、注册字段 → 邀请合法性与填写步骤 | 接受邀请 / 登录；过期、已用、字段错误 |
| `/forgot-password` | 账号输入 → 请求重置及真实渠道反馈 | 发送重置请求 / 返回登录；等待、失败、限流 |
| `/reset-password` | 令牌检查、密码输入 → 设置新密码 | 重置 / 登录；令牌失效、密码校验、完成 |
| `P` | 空项目 Dashboard → 描述/状态、真实工作入口 | 进入任务等 / 基本信息；归档、处理中、权限失效 |

## 3. 任务工作台与详情

参考 L2 多视图、L5 看板、L6 详情/属性；本项目保留七状态、Milestone/Sprint/Task、指派/评审、Blocker、Execution 与时间线模型。

```text
系统层
项目层     ‹ 项目 / atlas     概览  会议  待办  [任务]  知识库  产物  设置
视图层     [当前 Sprint ▾]  [看板]    [筛选 ▾]    规划 ▾  [新建任务]
─────────────────────────────────────────────────────────────────
Backlog       Ready         Running         …七状态横向连续
列名  数量*   列名  数量*    列名  数量*
┌──────────┐ ┌──────────┐  ┌──────────┐
│任务标题  │ │任务标题  │  │任务标题  │
│简短属性  │ │简短属性  │  │阻塞原因  │
└──────────┘ └──────────┘  └──────────┘
                 仅看板容器横向滚动
```

`数量*` 只沿现有数据的可靠口径显示，页内已加载数量不能冒充全量。规划不再展开为一串永久表单：选择上下文后，Milestone/Sprint 创建与编辑、顺序调整分别进入明确任务容器。当前 Sprint 状态/必要生命周期操作在视图附近；不必操作时不占几屏高度。恢复提示放相关任务或顶部短条，详情展开保留完整原意图。

```text
列表/看板保留来源位置         任务详情（桌面宽面板；窄屏全宽）
                            任务标题                    ⋯  关闭
                            [状态]  类型/优先级/负责人（可编辑则就地）
                            描述与计划正文              属性区（可收起）
                            当前可执行的主要动作        关联/Sprint
                            [正文] [执行] [依赖] [历史]  技术信息按需
```

标签是目标组织方式，F5 可在内容规模和键盘逻辑检验后采用分区导航；不能为了分 Tab 丢失上下文。评审时成果与评审动作应同屏或有明确返回；取消、审批、Blocker 和 Unknown 保留各自门禁与结果；审批保留run-command及MCP远端工具的一次操作scope、approve/reject与原请求查询，不收窄为命令执行审批。任务标题先于动作群，长描述不被固定窄抽屉压缩。

| 路由 | 目标 | 必须保持 |
| --- | --- | --- |
| `P/tasks` | 当前合法默认范围的看板，首屏以任务为主体 | Current Sprint 默认规则、七状态与已有操作能力 |
| `P/tasks/sprints/:sprint_id` | 同一工作台，明确指定 Sprint，范围切换可辨认 | 直接链接优先，不用默认 Sprint 覆盖 |
| `P/tasks/:task_id` | 同一工作台+指定任务详情；失效目标就地反馈 | 稳定对象身份、返回来源、权限变化和迟到响应处理 |

390px 下系统/项目上下文压缩为紧凑两层，视图栏只保留当前范围、筛选和主动作；规划与次要操作收进有标签菜单。目标是首屏出现当前任务或其真实空/失败状态，而非先看数屏控制区。看板可以横滚，不能页面横溢。若保留拖拽，必须保留领域允许的状态/排序与非拖拽等价操作；不因新外观新增任意拖动权限。

## 4. Knowledge 与 Artifact 内容工作台

参考 L2 阅读主区、L3 资源与 L10 保持上下文的预览。沿现有目录/阅读边界演进，主内容从管理操作之后移到视觉中心。

```text
项目 header menu
视图层    知识库      [已有范围的标题查找]               新建 ▾
──────────────┬─────────────────────────────────────────────────
文档树        │ 父级 / 当前文档                    编辑   ⋯
  文件夹      │ 文档标题
    文档      │ 必要的真实索引/读取状态（有异常才突出）
              │
目录独立滚动  │ 正文：适当阅读宽度，长代码/表格局部滚动
              │
              │ 需要分段时：继续读取；边界与错误明确
──────────────┴─────────────────────────────────────────────────
```

文档树的展开和选择仍独立，搜索明确是已有标题范围；M3已有hybrid索引与Agent检索/版本页码引用，但不等于用户新增了全文/语义搜索输入，更不提供跨项目全局搜索。常规刷新进入区域工具或更多菜单；“从开头重读”等能力用用户能理解的名称，必要分段语义仍保留。改名/移动/删除等管理动作从阅读主动作中退后。编辑使用获得足够空间的模式，原草稿、完整读取条件、关闭确认和原请求追踪继续工作。

当前已支持TXT/Markdown/PDF/DOCX根目录及子文档上传、原文件替换、固定原版本下载和PDF预览。蓝图须把上传/替换与正文编辑分开，解析中/失败/不可用状态不遮住仍可用的原文件下载/PDF文件预览；保留原上传Unknown查询和契约允许的原请求重放、离页草稿与下载URL清理。原文件大小/格式限制来自当前实现，不借重设计增大预算。

Markdown 当前仍以原文呈现，阅读增强考虑安全渲染，原文编辑保持字节与格式含义；原 HTML 不直接执行，链接/资源策略先核工程能力。若需要依赖，F6 单列必要引入和验证，不偷偷扩大为富文本系统。未支持的格式展示清楚事实和已有安全获取入口。

```text
产物                                  [已有类型/范围筛选]  [创建文本产物]
名称                         类型        大小/时间           查看 →
─────────────────────────────────────────────────────────────────
打开产物： ‹ 返回列表   产物名称                  可用操作   ⋯
                  阅读/预览主区                  元信息（可展开）
```

Artifact 日期和大小面向用户格式化，原值可在详情复制；Token/字节等不同度量不能混同。在 `P/artifacts` 页，文本分段和非文本不支持在线预览仍是真实范围；M3已在Meeting composer接入Artifact附件上传/插入/引用预览，不能泛称全产品没有上传能力，也不能把会议上传按钮当作产物页已有入口。共享元信息/内容组件与F7协调，不能用静态预览替代实际数据。窄屏目录与正文轮流占主区，关闭目录返回所选文档；标题后尽快出现内容，次要动作不纵向铺满首屏。

| 路由 | 目标 | 主次操作与关键状态 |
| --- | --- | --- |
| `P/knowledge/:document_id?` | 树+阅读/编辑/文件预览，文档标题与正文为主 | 阅读/编辑/新建、四格式上传/替换/原版本下载/PDF预览；移动删除后置；树/正文/解析各自状态，草稿、冲突、Unknown、删除子树 |
| `P/artifacts` | 连续目录→阅读/预览，返回位置明确 | 查看/已支持创建；刷新/元信息次要；分段失败、真实无预览、权限与取消 |

## 5. 设置统一框架

参考 L8 的成组设置行；结合 L6 的就地属性操作。旧“当前读取值→修改配置→完整技术字段”改为“本栏目要完成的配置→必要说明→直接编辑→真实结果”。

```text
系统层（项目设置另保留项目 header menu）
──────────────────┬─────────────────────────────────────────────
设置菜单          │ 栏目标题
分组名            │ 一句必要说明
  当前栏目        │
  同组栏目        │ 目的分区
                  │ 标签 / 简短帮助           当前可编辑控件
另一分组          │ 标签 / 简短帮助           当前可编辑控件
                  │                         取消      保存
                  │
                  │ 危险区（确有业务时，单独说明影响）
──────────────────┴─────────────────────────────────────────────
```

集合型栏目不把所有详情放目录下面：桌面采用目录→对象详情或适当双区，选择后上下文稳定；窄屏全宽详情可返回。大型配置用正文编辑，短创建用 Dialog；只有真正独立的保存契约才各自有保存区。

页级状态不吞掉栏目内部状态：保存中限制重复，失败保留输入，冲突保留原版本与明确重读，Unknown 只查原意图。Credential/Secret 仅使用正式安全投影与写入语义，不为了简洁回显材料。菜单窄屏覆盖并可键盘打开、锁焦点和恢复；字段 DOM 顺序与视觉一致。

### 5.1 个人设置：3 个叶子

| 路由 | 目标信息/布局 | 主动作与保留边界 |
| --- | --- | --- |
| `/settings/profile` | 身份/头像在前，用户名/显示名直接编辑，邮箱只读；技术规则在帮助或错误处 | 保存资料；上传/移除头像按现契约；改名后的路径影响需在提交前清楚提示 |
| `/settings/appearance` | 浅/深/系统三项明确选中与小型预览，同一目的共用表面 | 保存 / 取消；预览与账号服务端持久化分清，不以本地 Debug 状态代证 |
| `/settings/password` | 当前密码→新密码→确认，简短规则，相关账号操作分区 | 修改密码；失败不清空无关页面，成功说明其他 Session 影响；不新增 MFA/设备管理 |

### 5.2 系统设置：11 个叶子

| 路由 | 目标信息/布局 | 主动作 / 次动作与保留边界 |
| --- | --- | --- |
| `/system/users` | 姓名/邮箱与身份为主的连续目录，用户名等辅助 | 查看；真实筛选/分页；不新增角色切换、禁用、删除或他人项目入口 |

| `/system/runners` | 名称、在线/离线、能力摘要为主；详情再展示平台、路径和 Enrollment | 按真实能力管理/Enrollment；凭据与撤销影响独立确认；离线不等于禁用 |
| `/system/providers` | Provider 目录→对象配置；Models 作为明确关联入口，Credential 单独任务 | 新建/保存 Provider；凭据替换、删除及原意图恢复；不纵向叠多个实体表单 |

| `/system/audit` | 简洁结构化过滤→连续事件→详情抽屉/主区，ID 在诊断中可取 | 查询；分页/详情；只读、安全证据，非全文搜索、不增加删除 |
| `/system/account-security` | 按 Session/重置/挑战分组，直接编辑现值，单位贴近控件 | 保存 / 取消；不再上下重复整份现值和草稿；版本冲突保持 |
| `/system/smtp` | 服务连接、发送身份、重试配置分组；测试区与保存区分开 | 保存配置；发送测试单独状态；不把测试成功等同业务投递成功，材料不回显 |
| `/system/outbound-policy` | 规则集合→规则编辑，CIDR/端口/HTTP含义清楚 | 新建/保存；删除单独确认；保固定禁止地址与对在途请求的真实影响 |
| `/system/runtime-information` | 只读运行概览：实际 ready 与组件状态优先，部署详情按需 | 刷新；未知/失败与 false 分清；不添加部署凭据编辑或虚假绿色健康 |

### 5.3 项目设置：11 个叶子

| 路由 | 目标信息/布局 | 主动作 / 次动作与保留边界 |
| --- | --- | --- |

## 6. 现有 M3 协作、连接与 Memory 页面

本节是当前F7必须重设计的范围，基于 `3fc44101` 的实际代码和正式M3接受摘要；不是未来能力占位。新增四个正式叶子为Meeting、项目Inbox、项目MCP和OAuth callback，Memory嵌入已有Agent页。以下结构需在F0实看并形成完整样板，本轮没有追加这些页面的视觉验收。

### 6.1 Meeting 与项目 Inbox

参考L2的内容主区、L6的上下文属性与L10的返回来源；Linear没有可直接复制的会议业务模型。

```text
项目 header：概览  [会议]  待办  任务  知识库  产物  设置
会议目录          │ 会议标题 / 当前状态             参会者/引用   ⋯
新建 / 列表       │ 必要Summary与本轮状态（可定位完整内容）
                  │ 消息正文、回复目标、文件引用
                  │ Decision / Approval / Proposal 就近处理
                  │
                  │ composer：输入、typed引用、附件          发送
                  │ 未确认上传/发送结果与原意图恢复留在任务内
```

会议列表/新建/直链、Metadata与参与Agent顺序/引用、串并行发送/队列/插话、回复、Retry/Regenerate/history、整轮/单Agent取消和skip、Summary失败重试、归档/恢复/删除均按现有契约保留。长线程以阅读和输入为主，管理操作进入明确上下文菜单；不能以减按钮为由删掉真实取消或恢复入口。

Composer保留typed `@`、`#`、file引用及上传并插入。附件五阶段、停止传输、Unknown查询/完成/取消和插入已上传结果分清；未确认上传先处理再发送。引用预览按稳定Artifact身份读取安全元信息/内容，文本分段与非文本不支持在线预览如实显示。删除处理中和迟到响应不得复活旧会议；草稿、焦点与返回来源保持。

有限Realtime仅按当前Meeting Timeline与展开Execution的实际绑定处理：ack、权威snapshot/resync、断线及权限/删除关闭；显示已提交状态、waiting、Tool摘要和公开文本，不承诺逐token或私有reasoning，也不把它泛化为Task本次新接WebSocket。

```text
项目 header：概览  会议  [待办]  任务  知识库  产物  设置
项目待办        [待处理 / 已处理]                     刷新
来源 / 条目标题                     当前状态        查看来源 →
分页/继续加载按正式混合cursor
```

Inbox只位于当前项目，混合Proposal与Decision来源、open/resolved两态及游标加载，跳到本项目会议处理。主动作是查看可判断的内容并进入真实来源，不新增dismiss、全局计数或跨项目聚合。离页cancel、scope失效撤下旧内容，返回后重读权威来源。390px下会议目录/详情和待办来源详情各自单一主区，输入/审批操作可达；键盘可到消息引用、当前动作和原返回位置。

| 路由 | 目标 | 主动作与关键状态 |
| --- | --- | --- |
| `P/meetings/:meeting_id?` | 目录+消息工作台，当前会议/执行状态与composer稳定 | 发送/真实Decision或审批；元信息、取消与历史按上下文；草稿、Unknown、删除、有限实时恢复 |
| `P/inbox` | 当前项目的Proposal/Decision连续列表→来源会议 | 状态筛选、条目来源标识、混合分页、查看来源；空/失败/撤权，非全局聚合 |

### 6.2 MCP 配置、连接与 OAuth 回调

参考L8分组设置与L6上下文属性；对象按“服务配置→连接→认证/发现”组织，不能把connected、enabled、认证与capability同步当同一个绿色状态。

```text
项目设置菜单   │ MCP服务目录：名称 / 系统或项目来源 / 当前状态
               │ 所选服务：概要                     编辑/连接/更多
               │ 连接与认证状态      当前可执行动作/原请求恢复
               │ Tools / Resources发现目录与状态
```

已有项目服务添加/编辑/删除、凭据配置、OAuth授权、连接/刷新发现/启停/断开入口都纳入重设计。系统配置来源只读；项目配置按Owner与归档只读规则编辑。连接、Credential与OAuth各自的Unknown/stopped恢复保留，不自动重兑授权码、不把刷新发现失败显示成连接配置丢失。主要任务表面与安全材料输入分开，错误留在对应过程。

| 路由 | 目标 | 主动作与关键状态 |
| --- | --- | --- |

### 6.3 Agent Memory 内嵌面板

Agent详情保留“查看记忆”入口，打开后以当前记录、修订历史/来源和必要过滤/分页为主；关闭回到原Agent和触发焦点。删除是已有命令，须保留明确确认、原删除Unknown查询及当前scope变化清理，不能降成静态只读说明，也不能新增任意编辑器。

Memory无独立路由；F7负责面板，F4负责Agent基础配置。桌面利用主内容空间呈现记录与修订，390px详情可返回目录，技术身份可展开但删除目标与结果必须清楚。MCP/Memory与其他设置使用同一v2框架，不能因增量接入形成第二套组件主题。

## 8. 全站共同边界与验收视角
