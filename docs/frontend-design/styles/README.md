# 样式设计规范

> 状态：2026-10-01 已确认并定稿为前端样式基线。规范固定视觉与组件细节，不表示生产前端已实现，也不确认业务页面布局。

## 1. 已确定的方向

采用 Linear 参考复刻的低噪声视觉方向，并使用本项目确认的配色：石墨灰阶、低饱和且偏蓝的青蓝强调色、细边界、小圆角、清晰文字层级和适度动效。浅色与深色使用相同语义，不把参考截图的色值当作 Linear 官方 token。

以下规则已确认：

- 任何情况下都禁止 eyebrow（眉题），不设例外。补充信息使用明确字段、属性、说明或导航，不在标题上方加装饰性小标题。
- 成功反馈显示在触发按钮上，不使用屏幕底部成功提示；错误留在对应字段或区域。
- 动作菜单、下拉选择器、说明、搜索、详情和模态按用途区分，不统一套用同一种浮层。
- 复选框、Radio 与开关使用统一自定义外观，保留原生交互语义。
- 文档树的箭头与连接线对齐，父子缩进一致，展开与选择独立。
- 消息不使用头像；用户靠右，Agent 靠左，保留名称与时间。
- 控件、内容分区和对话框操作区使用规范间距，不靠零散补丁排版。
- 动效可中断，并响应系统减少动效偏好。

## 3. 样式与布局的边界

Debug 内部的目录、展示卡片编排和断点只用于承载组件。系统骨架仅包含系统级顶部导航和内容区，项目级导航仅在未来项目工作区内部出现。它们不确定正式页面的区域划分、栏目位置、阅读宽度或业务流程；原会议、任务与设置试作页已移除。

正式页面布局以 [应用骨架及布局文档](../layouts/application-shell.md) 及领域文档为依据。组件内部的消息左右对齐、树缩进、控件尺寸、间距和反馈属于本样式规范；不能由此推导整页布局或新增 API、路由及产品功能。

## 4. 基线维护与验收

本轮已确认的值作为正式开发默认值，不再标记为候选或待选择。后续修改必须同步规范、CSS token 和组件示例，并复查受影响的状态、主题、键盘操作和减少动效路径。

验收包含浅深主题、1440 / 1024 / 834 / 390px 展示宽度、中英混排、长名称、局部滚动、控件状态、焦点限制及恢复。正文对比度至少 4.5:1，必要控件识别边界、状态图形和焦点至少 3:1。组件展示验证不替代生产业务页面或真实设备验收。
