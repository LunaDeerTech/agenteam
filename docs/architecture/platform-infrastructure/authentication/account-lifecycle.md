# 人类账号与认证生命周期

> 上层：[账号认证](README.md)。相关：[SMTP Delivery](smtp-delivery.md)、[安全与治理](../../security-governance/README.md)、[部署运行](../deployment-runtime.md)。

## 1. User 与身份边界

概念数据包含 User id、email、display_name、avatar 引用、role、password_hash、created_at、updated_at，以及初始密码建议是否仍需展示的状态。role 首版为系统管理员或普通用户。邮箱为登录标识，首版不允许修改；显示名和头像可修改。无显示名时 UI 显示邮箱。

User 与 Session、邀请、密码重置请求是平台对象，持久化在 PostgreSQL；密码不作为可读资料字段。密码仅保存不可逆哈希，具体算法与参数待定。头像走受控对象存储，不将任意上传内容作为可信媒体。

系统管理员可邀请普通用户并维护系统配置。首版不增加公开注册、角色切换、用户禁用 / 删除或项目成员机制。登录 identity 和每次资源访问的 Owner Authorization 分开校验。

## 2. 首次初始化

Central 完成必需基础设施与 migration 后，首次初始化创建 `admin@mail.com`，生成随机密码并输出 Central 后台日志。创建账号与初始化完成标记必须具有事务幂等性；普通重启、部署更新或已完成初始化时不重建账号、不覆盖密码、不重新打印密码。

首次登录展示修改初始密码的建议，可以继续使用系统，不强制进入改密关卡。修改成功后清除建议状态。

随机密码输出失败、初始化事务结果不确定时的恢复细节需在实现设计中补齐，不能以重新启动无条件覆盖已创建密码。

## 3. 管理员邀请

邀请概念数据：id、email、created_by_user_id、created_at、expires_at、token 验证材料及投递结果。有效期从创建开始固定 24 小时；链接 token 不作为普通可读字段，验证材料使用不可逆存储方式，具体生成及安全参数待实现设计。

创建由系统管理员执行。已注册邮箱拒绝重复邀请；已有有效邀请不重复创建，允许重试投递。邀请与重复请求需原子校验，避免多条有效邀请。过期邀请清理后可重新创建。

投递重试沿用有效链接，不延长 expires_at；用于重复投递的 token 材料仅由平台 Secret Management 加密保管，邀请可保存安全引用；读取接口不回显。邀请消费、撤销或过期后解除该材料引用，不能为重发在普通数据库列保存明文 token。

## 4. 邀请注册、撤销与清理

有效链接绑定唯一邮箱；注册输入 display_name、password、password confirmation，role 固定普通用户。服务端再次验证 token、到期时间和邮箱尚未注册，在同一事务中创建 User 并消费 / 删除邀请。成功后不能重复兑换。

管理员撤销相当于删除邀请记录，链接立即失效。24 小时到期自动撤销并删除记录；兑换必须独立检查 expires_at，不依赖清理任务准时运行。撤销、到期清理和兑换之间须事务保护，避免撤销后仍成功注册。

邀请管理只保留待注册有效记录及投递结果；已注册进入用户列表，不保留过期或已撤销邀请行。业务审计若记录邀请操作，只保留脱敏身份、动作与结果，不能保存明文链接。

## 5. 登录与 Web Session

邮箱和密码认证成功建立 Web Session；后续 API 与 WebSocket 复用同一 Auth identity。退出登录结束当前 Session。身份有效不等于可以访问任意项目，每个 Domain 仍校验 Project Owner 或 System Scope。

未登录访问受保护页面先登录，之后重新校验目标资源权限。Session cookie 属性、生命周期、刷新与撤销策略、认证错误规则和请求保护参数待定，不在此制定具体数字。

## 6. 密码修改与恢复

修改密码要求当前密码、新密码及确认密码；验证成功更新哈希，清除初始密码提示。修改后的 Session 处理待安全实现设计确认。

管理员与普通用户均可通过邮箱发起找回。已注册账号生成重置请求，经 SMTP / 后台日志渠道投递；公开响应不泄漏邮箱是否已注册，不公开 token。重置提交再次验证 token，成功更新密码并返回登录入口。

重置 token 的单次使用保障、有效期、重复申请对旧 token 的影响、原子消费及 Session 撤销规则需明确后实现；不直接继承邀请的 24 小时契约。未配置 SMTP 时日志访问者协助普通用户获取并转交链接，不因普通用户没有后台访问权而公开凭据。

## 7. 资料与界面偏好

邮箱只读；display_name、avatar 可修改，头像可移除。个人主题偏好为 system / light / dark，默认 system；其持久化属于账号偏好，不属于 Project 配置。头像媒体范围、大小、处理流程及生命周期待存储设计补齐。

## 8. 验证与待定

验证首次初始化与重启、并发邀请、重复注册、24 小时到期、兑换与撤销竞争、登录失败、退出、密码修改与恢复、普通用户 / 管理员权限。安全实现参数遵循专题待定项，文档不声称已有 Authentication 实现。
