# 人类账号与认证生命周期

> 上层：[账号认证](README.md)。相关：[SMTP Delivery](smtp-delivery.md)、[安全与治理](../../security-governance/README.md)、[部署运行](../deployment-runtime.md)。

## 1. User 与身份边界

概念数据包含 User id、email、username、display_name、avatar 引用、role、password_hash、created_at、updated_at，以及初始密码建议是否仍需展示的状态。管理员与普通用户使用同一 User 模型，仅角色与权限不同。邮箱为登录标识，首版不允许修改；username、显示名和头像可由本人修改。无显示名时 UI 显示邮箱。

User 与 Session、邀请、密码重置请求是平台对象，持久化在 PostgreSQL；密码不作为可读资料字段。密码使用 Argon2id、随机盐及保存的算法/参数版本，不以可解密 Secret 代替哈希。参数通过性能测试确定，并限制哈希验证并发；具体编码、升级和资源限制由 D07 落实。头像走受控对象存储，不将任意上传内容作为可信媒体。

系统管理员可邀请普通用户并维护系统配置。首版不增加公开注册、角色切换、用户禁用 / 删除或项目成员机制。登录 identity 和每次资源访问的 Owner Authorization 分开校验。

### 1.1 username 与可读路径

username 全站唯一，只使用英文字母、数字和连字符 `-`，与可含中文的 display_name 分开。唯一性不区分大小写，标准 URL 使用小写；长度、保留字和统一规范化由 D07 规格固定，不能由前端单独保证唯一。

项目主页为 `/{username}/{project_name}`，用户名路径先解析为稳定 User ID，再按[项目身份规则](../../project-work-management/README.md#21-project-身份与路径)定位和授权。用户名不成为新的登录方式，也不使项目公开。

本人修改 username 后旧路径立即失效，不维护历史别名或自动跳转；旧名可被重新使用。旧路径被其他对象重新占用时按当前对象重新授权，不能把旧书签的文字路径当作原对象身份。修改 username 不改变 User ID、项目数据或邮箱登录。

## 2. 首次初始化

Central 完成必需基础设施与 migration 后，首次初始化创建邮箱 `admin@mail.com`、username 为 `admin` 的管理员，生成随机密码并输出 Central 后台日志。创建账号与初始化完成标记必须具有事务幂等性；普通重启、部署更新或已完成初始化时不重建账号、不覆盖密码、不重新打印密码。

首次登录展示修改初始密码的建议，可以继续使用系统，不强制进入改密关卡。修改成功后清除建议状态。

初始密码日志丢失或管理员忘记密码时，使用与普通用户相同的忘记密码流程；不提供专用管理员密码重设 CLI 或初始密码取回接口。初始化事务结果不确定时须先核对持久化事实，不能以重新启动无条件覆盖已创建密码。未配置 SMTP 时重置链接走受限后台日志渠道。

## 3. 管理员邀请

邀请概念数据：id、email、created_by_user_id、created_at、expires_at、token 验证材料及投递结果。有效期从创建开始固定 24 小时；链接 token 不作为普通可读字段，验证材料使用不可逆存储方式，具体生成及安全参数待实现设计。

创建由系统管理员执行。已注册邮箱拒绝重复邀请；已有有效邀请不重复创建，允许重试投递。邀请与重复请求需原子校验，避免多条有效邀请。过期邀请清理后可重新创建。

投递重试沿用有效链接，不延长 expires_at；用于重复投递的 token 材料仅由平台 Secret Management 加密保管，邀请可保存安全引用；读取接口不回显。邀请消费、撤销或过期后解除该材料引用，不能为重发在普通数据库列保存明文 token。

## 4. 邀请注册、撤销与清理

有效链接绑定唯一邮箱；注册输入全站唯一 username、display_name、password、password confirmation，role 固定普通用户。服务端再次验证 token、到期时间、邮箱尚未注册及规范化后的 username 唯一性，在同一事务中创建 User 并消费 / 删除邀请。重复用户名提示更换，并发注册不能产生重名账号；成功后不能重复兑换。

管理员撤销相当于删除邀请记录，链接立即失效。24 小时到期自动撤销并删除记录；兑换必须独立检查 expires_at，不依赖清理任务准时运行。撤销、到期清理和兑换之间须事务保护，避免撤销后仍成功注册。

邀请管理只保留待注册有效记录及投递结果；已注册进入用户列表，不保留过期或已撤销邀请行。业务审计若记录邀请操作，只保留脱敏身份、动作与结果，不能保存明文链接。

## 5. 登录与 Web Session

邮箱和密码认证成功建立服务端管理的 Web Session；后续 API 与 WebSocket 复用同一 Auth identity。退出立即使当前 Session 失效。身份有效不等于可以访问任意项目，每个 Domain 仍校验 Project Owner 或 System Scope。网页登录过期、退出或会话撤销不自动取消已经运行的 Agent Execution。

未登录访问受保护页面先登录，之后重新校验目标资源权限。可信活动可延长空闲有效期，但不能突破从登录开始计算的绝对期限；不能仅因浏览器仍保持连接而无限续期。API 与 WebSocket 均须重新校验过期和撤销，具体活动定义、刷新节流及并发行为由 D07/D25 落实。

### 5.1 管理员可配置默认值

以下参数为管理员系统 UI / 管理 API 维护的 Runtime Platform Config，持久化 PostgreSQL；保存需校验、version 冲突处理和 Audit，普通用户不能修改。

| 参数 | 默认值 |
| --- | --- |
| Session 空闲期限 | 7 天 |
| Session 绝对期限 | 30 天 |
| 密码重置链接有效期 | 30 分钟 |
| 连续登录失败触发挑战的阈值 | 5 次 |

注册邀请仍固定 24 小时，不随此表自动变成可配置项。配置更新对已签发 Session / 重置请求的生效边界及撤销竞争由 D07 规格明确；重复申请和邮件重试均不得暗中延长已签发链接。

### 5.2 写请求保护与登录挑战

浏览器写请求严格校验本站 Origin 并验证 CSRF token，前端统一附带防伪标识；使用安全会话 Cookie，禁止 GET 修改业务状态，WebSocket 校验连接来源。Cookie 的 HttpOnly / Secure / SameSite、public origin、CSRF 签发和轮换及公开认证请求边界由 D07/D26 规格明确，不信任未经验证的 Host 拼接。

连续登录失败达到配置阈值后要求验证码/人机挑战，不采用递增等待或固定冷却。使用 GoCaptcha 与 go-captcha-vue 的 Go/Vue 包源码集成，支持滑块、旋转等交互，不另部署验证 service、容器或 Redis，也不使用 ALTCHA 方案。

挑战必须由服务端校验一次性、防重放和请求绑定，不能信任客户端成功标记。按账号/IP 的计数与重置、挑战期限和存储、具体类型、固定版本、素材许可、无障碍及真实浏览器验证由 D07/D26 落实；交互式验证码本身不构成可靠识别人类的保证。

## 6. 密码修改与恢复

所有设密入口统一接受 15–128 个字符，允许中文和空格，不强制大小写/数字/符号组合，拒绝常见弱密码。不截断或 trim 首尾空格，不要求无故定期改密；首次管理员仍只提示改密。字符计数、编码、弱密码列表来源和请求大小限制由 D07 固定，不新增外部密码泄漏查询服务。

普通改密要求当前密码、新密码及确认密码；验证成功更新哈希并清除初始密码提示，为当前设备换发新 Session，撤销其他旧 Session。相关旧 WebSocket 身份同步失效，不自动取消 Agent Execution。

管理员与普通用户均通过邮箱发起找回。已注册账号生成重置请求，经 SMTP / 后台日志渠道投递；公开响应不泄漏邮箱是否已注册，不公开 token。重置提交再次验证 token 并原子消费；成功更新密码、撤销全部 Session 和相关 WebSocket 身份，再返回登录入口。

尚未使用且仍有效的重置请求重复申请时，重发同一个链接且不延长到期时间；过期后才生成新链接。有效期默认 30 分钟并按 §5.1 配置，不能套用邀请的 24 小时。用于重发的 token 材料经 Secret Management 加密保管，普通数据库列不保存明文；发送频率受限。

单一有效请求、并发申请、原子消费、密码更新与 Session 撤销事务、响应丢失及材料清理由 D07 规格落实。未配置 SMTP 时日志访问者协助普通用户转交链接，不因普通用户没有后台访问权而公开凭据。已配置但投递失败保留失败/重试，不切换为后台日志；详细规则见 [SMTP Delivery](smtp-delivery.md)。

## 7. 资料与界面偏好

邮箱只读；username、display_name、avatar 可修改，头像可移除。个人主题偏好为 system / light / dark，默认 system；其持久化属于账号偏好，不属于 Project 配置。

头像只支持静态 JPG、PNG、WebP，不支持 SVG 或动态头像。服务端校验实际媒体内容，限制文件大小和图片尺寸，统一缩放、重新编码并去除附加元数据，不把扩展名或客户端 MIME 当成验证结果。

只保留当前头像，不提供历史查看或恢复。新头像持久化且资料引用成功切换后，后台清理旧图片；移除后显示默认头像并清理旧图片。清理失败可重试，不回滚成功的资料变更，也不能误删当前仍引用的对象。D05/D07 通过正式存储端口落实编码库/格式/资源限制、失败上传回收及并发替换、移除与可恢复清理。

## 8. 验证与待定

D07/D26 须验证首次初始化与重启、用户名规范化/并发唯一性/改名路径、并发邀请、24 小时到期、兑换与撤销竞争、Session 期限/撤销/WS 失效、CSRF/Origin、挑战防重放、密码修改/重置并发及头像生命周期。哈希参数、挑战和媒体库版本、事务与 wire 字段等工程细节仍须规格和真实验收；本文件不声称已有 Authentication 实现。
