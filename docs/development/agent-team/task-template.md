# 工作项简报与子任务卡模板

主线程先建立共享工作项简报/规格，再按完整结果下发精简子任务卡。产品规则、接口与验收场景在正式来源维护，卡片引用具体路径和段落，不复制全套架构。简单任务保留必要字段即可，不为每个函数或步骤单独拆卡。公共调度与治理规则见[团队流程](README.md)。

## 共享工作项简报 / 规格引用

- 工作项编号、名称及关联计划编号：
- 修订与状态：待开始 / 设计中 / 实现中 / 验收中 / 阻塞 / 已完成。
- 已确认的产品目标、可见行为与验收结果：
- 本次范围、明确排除项及仍待主线程处理的决定：
- 基线：`main` 提交、已有改动及必须保留的内容。
- 正式产品规则、模块规格、接口/状态/错误/事务/幂等和验收场景的引用；不适用项说明原因：
- 前置依赖及完成证据、未来端口绑定与集成验收的责任工作项：

主线程维护下表；按真实依赖、稳定正式契约及文件、迁移和共享资源所有权安排模块或完整结果任务并行，所需前置能力须有验收证据。不设单活动模块或常态两个、最多三个子任务限制；最多使用当前工具含主线程在内的 7 个总席位，实际可用席位不足时安排顺序，简单任务一个执行者。同一文件只有一个写入者；公共接口、锁文件、全局迁移编号及应用顺序、生成目录、端口、测试库和 Docker fixture 指定唯一所有者或使用顺序，不将尚未实现的接口视为已满足依赖。

| 任务与交付结果 | 依赖及完成证据 | 角色 | 独占写入范围 | 共享资源 / 所有者或顺序 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 子任务编号、完整结果 | 前置任务或正式契约 | 按需角色 | 具体文件 / 明确新增文件 | 不适用时写明 | 待下发 |

- 验收风险与安排：低影响自查加主线程审查 / 业务变更由未参与实现的实例审查 / 高风险关键场景独立验证。
- 共享检查：场景、命令、目录、环境、预期结果、执行责任与证据位置。
- 证据复用：已通过检查、基线加相关文件指纹或冻结修订、所依赖输入；明确哪些变化需要重跑。
- 模块完成门槛与未验证项：沿用开发计划和模块规格，不因单卡完成而宣告模块完成。

主线程负责规格最终确认、修订与所有权调度，规格正文可授权设计角色编写；任务卡、台账和调度记录由主线程维护。规格与卡片在同一文件时，仍须先移交写入权，再由新负责人修改。需求、契约或所有权变化时，先停止受影响写入、保留改动，提升修订再重新下发。

## 精简子任务卡

### 身份与输入

- 工作项 / 子任务编号、当前修订、状态：
- 执行角色与模型：按需角色，`gpt-6-astra / max`；创建时显式指定，`fork_turns=none`。
- 基线、已登记的并行任务及必须保留的改动：
- 共享规格和本任务所用规则/接口/验收段落：
- 必读源码与技能路径：首次读取必要输入，后续只补读变化。

### 交付结果与授权

- 应完成的行为或交付结果：
- 独占写入文件 / 明确允许的新文件；只读任务写明：
- 前置依赖及证据、共享资源的所有者 / 使用顺序：
- 不涉及的相邻范围：
- 必须遵循的步骤或技术约束，仅在结果与接口不足以表达时填写：

执行者自主决定未约束的局部细节，完成自测与授权范围内的文档同步。缺少产品决定/公共接口、需要未授权依赖或范围扩展、发生所有权冲突，或反复失败且没有新证据时，暂停受影响部分并向主线程报告；常规工具修正与范围内排查自行处理。不得覆盖已登记的其他任务改动。

### 验收与交付

- 风险等级、自测范围和独立验证安排，引用共享方案即可：
- 本任务正常、异常及相关回归场景；浏览器任务补充 URL、主题、视口和关键操作：
- 实际检查命令、目录、环境与预期；可复用证据及对应稳定输入/依赖：
- 未验证内容、原因与后续责任：
- 交付：完成结果和实际修改文件、检查/结果/证据、未完成项或阻塞、是否停止写入及后台命令。

先完成写入再形成检查结论。相关输入与依赖未变可复用通过证据；变化后重跑受影响检查。主线程确认被审查范围已停止写入后再安排独立审查，最终集成前停止全部相关写入。

子 agent 只向主线程报告，不直接询问用户，不再委派，不自动换模型；不得切换分支、创建或切换 worktree，以及执行 Git 暂存、提交、推送、reset、clean。主线程负责最终验收、台账与本地 Git 交付。
