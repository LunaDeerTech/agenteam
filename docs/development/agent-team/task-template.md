# 工作项简报与子任务卡模板

主线程将产品目标、共同契约和跨任务边界交给一级负责人；一级负责人自主拆分、调度、集成和验证，二级及更深执行者按收益继续拆分。产品规则、接口与验收场景在正式来源维护，卡片引用具体路径和段落。简单任务保留必要字段，不按每个函数拆卡。公共规则见[团队流程](README.md)。

## 共享工作项简报 / 规格引用

- 工作项编号、名称及关联计划编号：
- 负责人、直接上级与当前下级分工：
- 最小团队及按需技能：依据[任务组合](README.md#按任务选择最小团队)选择，说明独立验证者；不逐个串过全部专家。
- 修订与状态：待开始 / 设计中 / 实现中 / 验收中 / 阻塞 / 已完成。
- 已确认的产品目标、可见行为与验收结果：
- 本次范围、明确排除项及仍需上级协调的决定：
- Git 基线、限定差异范围、已有改动及必须保留的内容：
- 工作分支 `ai/<task>`、`.agent-state/current.md` 唯一写者与必要材料保存路径：
- 正式产品规则、模块规格、接口/状态/错误/事务/幂等和验收场景的引用；不适用项说明原因：
- 必要前置依赖及完成证据、未来端口绑定与集成验收的责任工作项：
- 动态容量安排：当前可用席位、可并行的 ready 任务、执行与独立验证需求、容量借用/归还，以及 CPU/RAM 和长检查/调研时间边界；不设角色单例或每负责人固定配额。

主线程和各级负责人尽可能并行推进 ready 任务：所需依赖已满足且有适用证据、契约稳定、写入与共享资源无冲突。一个任务完成或阻塞后立即调度下一 ready 任务，不等最慢任务；相同 role 可按不同 `task_name`、目标、文件和资源同时创建多个实例。主线程维护跨子目标所有权，各级负责人只维护其局部任务，不复制全树台账或新增永久锁表。

仓库按用户要求配置全树 100 个子 agent 并发值，不含主线程，不设角色单例或永久子树配额。各层按运行时实际容量动态协商、借用和归还席位，保留执行与必要独立验证能力，避免全员占位等待下级。新 CLI 请求 100 也不保证服务提供相同实际容量。任务完成不等于席位释放，须按运行时确认；无空位时复用合适实例或顺序推进受限任务。

CPU/RAM、PG、Docker、browser 的实际负载纳入容量安排；同一文件只有一个写入者，移交后原负责人只读。公共接口、cache、lockfile、迁移编号及应用顺序、assets/生成目录、ports、测试库和 fixture 明确唯一所有者或使用顺序，只串行冲突部分，无冲突工作继续。

| 任务与交付结果 | 直接负责人 / 执行者 | 依赖及完成证据 | 独占写入范围 | 共享资源 / 所有者或顺序 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 子任务编号、完整结果 | 按需角色与层级 | 前置任务或正式契约 | 具体文件 / 明确新增文件 | 不适用时写明 | 待下发 |

- 验收风险与安排：低影响自查加直接负责人审查 / 业务变更由未参与实现的实例审查 / 高风险关键场景独立验证。
- 共享检查：场景、命令、目录、环境、预期结果、执行责任。
- 完成判定：用户可见行为或权威事实、触发方式及观察方法；编译、测试发现或 HTTP 响应不能替代所需最终事实。
- 稳定输入与证据复用：Git 基线 + 限定 diff + 停止写入状态，或冻结修订；已通过检查、必要依赖及需要重跑的变化。
- 记录位置：分支的目标、状态（进行中/阻塞/完成）、任务分支、必要路径、完成/未完、实际检查、失败限制、下一步与依赖恢复写入 `.agent-state/current.md`；全局产品状态更新台账。
- 恢复材料：必要未完源码、harness、probe和不可再生失败输入放正式路径或 `.agent-state/<task>/`；可再生日志/缓存留在 `output/ai/`，不能只用scratch保存必要材料。
- 保存与交付：中间结果自动WIP commit/push工作分支；正式验收后整理代码、测试及必要文档为完整原子交付，不将保存声明为PASS。
- 模块完成门槛与未验证项：沿用开发计划和模块规格，不因单卡完成而宣告模块完成。

相应负责人维护范围内规格和任务修订，可授权单一文件所有者编写；跨子目标契约与冲突交主线程协调。负责人实际完成设计细化、集成和范围内返修，消化局部问题，不增加逐层审批。规格和卡片在同一文件时，也先移交写入权再修改。需求、契约或所有权变化时，停止受影响写入、保留改动并更新任务。

## 精简子任务卡

### 身份与输入

- 工作项 / 子任务编号、唯一 `task_name`、当前修订、状态：
- 直接负责人、所属层级与可继续拆分的范围：
- 执行角色与模型：按需角色，`gpt-6-astra / ultra`；创建时显式指定，`fork_turns=none`。Fast Mode 配置目标为 `service_tier=priority`；接口不支持该参数时说明实际生效限制，不虚报启用。
- Git 基线、限定 diff、已登记的并行任务及必须保留的改动：
- 分支与恢复路径：`ai/<task>`、本任务必要材料、状态文件唯一写者；由直接负责人汇总给主线程保存。
- 共享规格和本任务所用规则/接口/验收段落：
- 必读源码与技能路径：首次读取必要输入，后续只补读变化。
- 专业方法与执行预算：需要 database / security / test-engineering / runtime-debugging 等哪项技能、可用工具/资源和时间边界；仅填写本次相关项。

### 交付结果与授权

- 应完成的行为或完整子目标：
- 独占写入文件 / 明确允许的新文件，包含必要测试与文档；只读任务写明：
- 前置依赖及证据、共享资源所有者 / 使用顺序：
- 若继续拆分：下级完整结果、ready 条件、唯一写者、动态容量需求/借用归还、本级并行工作、滚动补位与集成责任；无收益时直接执行：
- 不涉及的相邻范围：
- 必须遵循的步骤或技术约束，仅在结果与接口不足以表达时填写：

执行者自主决定未约束的局部细节，完成实现、自测与必要文档同步。缺少产品决定/公共接口、需要未授权依赖或范围扩展、发生所有权冲突，或反复失败且没有新证据时，暂停受影响部分并向直接负责人报告；常规工具修正与范围内排查自行处理。负责人解决范围内问题，跨子目标问题再逐级上报，不覆盖其他任务改动。

### 验收与交付

- 风险等级、自测范围和独立验证安排，引用共享方案即可；独立性按是否参与实现判断，测试作者不能独立验收自己的 harness：
- 本任务正常、异常及相关回归场景和可观察事实；浏览器任务补充仓库测试入口、实际依赖/浏览器条件、URL、主题、视口和关键操作：
- 实际检查命令、目录、必要环境与结果；可复用证据及对应稳定输入：
- 未验证内容、原因与后续责任：
- 交付：完成结果、必要材料的精确文件路径、实际检查、失败限制、下一步，以及停止相关写入、后台命令和自有资源状态；不能只交临时路径或通过声明。

先完成交付范围写入再形成检查结论。相关输入与依赖未变可复用通过证据；变化后只重跑受影响检查。直接负责人确认审查范围停止写入后安排独立审查，最终集成前停止全部相关写入。默认不生成文件指纹、全树依赖闭包、manifest 或永久 verification/archive 包；只有发布完整性、外部文件身份或具体故障定位确需时限定范围哈希一次并复用，例外规则见团队流程。

每个有意义结果、下级交付、长检查前、暂停或回用户前，以及有改动时至多5分钟后的下一个安全写入边界，负责人主动交可恢复片段并停相关写者，由主线程批次调用checkpoint工具，自动commit并push `origin` 同名工作分支，不等验收或用户提醒。push失败保留本地提交，说明未远端保存并在后续安全边界重试；这不是后台daemon或断电前最后字节同步保证。工具和新设备接续步骤见[团队流程](README.md#自动保存与跨设备恢复)。

各层子 agent 向直接负责人汇报，不直接询问用户，不自动换模型；不得切换分支、创建或切换 worktree，以及执行 Git 暂存、提交、推送、reset、clean。主线程负责自动checkpoint和最终Git交付，必要时由主线程创建隔离 worktree；`main` 仅接正式验收结果，必要时squash WIP，完整原子交付包含代码、测试和必要文档，不为补哈希或回填提交编号另开 docs 提交。用户持续授权checkpoint与常规源码commit/push，不含部署、force push或覆盖他人改动。
