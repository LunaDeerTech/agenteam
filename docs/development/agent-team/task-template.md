# 工作项简报与子任务卡模板

本模板用于完整结果任务；简单任务只保留相关字段，可直接写在派工消息中，不为每个代理创建永久卡片。产品规则和接口在正式来源维护，简报引用路径与段落。公共规则见[团队流程](README.md)，逐分支保存与接续见[恢复说明](../../../.agent-state/README.md)。

root 只负责规划统筹、跨任务契约协调、调度与全部 Git；规格、实现、诊断、测试和文档均由明确子代理承担。各级负责人在自己范围继续拆分、集成和组织验证，有就绪工作和实际容量即并行推进。

## 共享工作项简报

- **目标与归属**：工作项/关联计划、用户可见行为或权威事实、本次范围、负责人、直接上级、活跃会话及状态；尚需产品决定的问题单列。
- **工作树与版本**：唯一 `ai/<task>` 分支、起始基线、已采纳上游提交/契约版本、本地 worktree 路径提示、须保留的已有改动、`current.md` 唯一作者；root 负责创建或接续工作树和 Git。目录可在新环境重建，分支及提交是恢复依据。
- **模块关系与真实契约**：谁调用谁，所用数据结构、接口、状态、错误、事务与幂等规则的正式来源；上游已实现能力及证据、下游调用方式、尚未实现/绑定的能力和集成责任。接口声明不视作实现，不能把单项能力通过写成整个上游模块完成。
- **首条功能联调路径**：从哪个真实入口触发，跨哪些模块，观察什么结果；最小可联调切片、所需上游实际版本、隔离的 `ai/integration-<task>` 候选及组合基线、调用方与集成负责人。基础自测后尽早运行该路径，记录未接通边界。
- **写入与资源边界**：各完整子目标、唯一执行者、明确文件/新增文件、依赖就绪条件；共享 API、迁移编号与顺序、根配置、锁文件、生成产物和 cache/端口/测试库/fixture 的 owner 或使用顺序。独立模块优先不同 worktree，只串行真实冲突部分。
- **团队与动态容量**：按[最小团队](README.md#按任务选择最小团队)选择相关角色/技能，当前可执行任务、实际席位与机器负载、独立验证需求及释放/借用安排；同角色可多实例，不设固定子树配额或逐专家审批阶段。
- **检查问题与停止条件**：轻量基础检查验证什么、最小命令/环境与预期观察；首条真实联调验证什么；哪些权限、数据、事务、协议、竞争及恢复关键风险须专项独立验证。界定本轮检查范围、资源/时间边界和失败时收敛条件，不以无关检查拖延功能反馈。
- **进展与升级**：负责人在可恢复成果、子任务交付、阻塞、契约/依赖变化、联调失败和完成时汇报结果、证据、下一步；root 据此滚动核对跨任务依赖和容量。范围内问题由负责人解决，跨任务冲突或未决产品决定才升级。
- **恢复材料与保存**：必要源码/harness/probe 的精确路径与版本、依赖恢复和失败复现命令、实际通过/失败/未验证项、运行命令与资源状态。详细进度只进本分支 `current.md`；全局协调分支 `current.md` 仅更新分支/任务/会话归属/上游版本/集成状态/下一步，正式产品状态变化才更新台账。
- **完成判定**：用户行为或最终事实的触发与观察方式、适用独立验收、模块仍未完成范围。保存 WIP、编译或测试发现不代表正式完成；单卡完成不代表模块完成。

共享文件始终单写。上游同步前由子代理评估共享 API、迁移、根配置、锁依赖及调用方影响，由 root 执行 Git，冲突交文件 owner 修复。需求或所有权变化时只暂停受影响写入，保留已有改动并更新相关简报，无依赖工作继续。

## 精简子任务卡

### 输入与授权

- 工作项、唯一 `task_name`、直接负责人、层级、当前状态：
- 应完成的完整结果，以及不涉及的相邻范围：
- 角色与必读规格/技能段落；首次读取必要输入，后续只补读变化：
- 实例使用 `gpt-6-astra / ultra`，创建时显式指定且 `fork_turns=none`；Fast 配置目标为 `service_tier=priority`，按实际运行时支持说明限制，不虚报生效：
- 任务分支、基线/上游版本、本地 worktree、限定 diff 与必须保留的改动：
- 独占写入文件/明确新增文件、状态文件作者；只读任务写明：
- 上下游真实调用关系、已就绪依赖与证据、未绑定边界及责任：
- 共享资源 owner/顺序和本任务所需实际容量：
- 继续拆分时的下级完整结果、就绪条件、所有权、集成责任与滚动补位安排；无收益时由本执行者完成：

执行者完成实现、排查、自测及必要文档，范围内细节自主处理。出现缺失产品决定/公共契约、未授权依赖、范围扩展、所有权冲突，或反复失败且无新证据时，只暂停受影响部分并向直接负责人报告。原 Codex 会话仍活跃时另建不冲突目标与唯一分支；同一任务分支只能明确交接后单写，不能抢占状态或 Git。

### 功能反馈与交付

- 轻量基础自测：具体问题、最小命令、目录/必要环境、观察事实、运行边界与停止条件：
- 首条隔离真实联调：实际入口、上游/下游版本、候选组合基线、预期事实、责任人及未接通边界：
- 风险专项：关键正常/异常/竞争/恢复场景、独立验证者与范围；独立性按实际参与实现判断，harness 作者不能独立验收自己的 harness：
- 实际检查及结果、失败与未验证项、稳定输入和可复用证据；相关输入变化后只重跑受影响检查：
- 交付：结果、必要文件与版本、恢复/复现命令、下一步、停止相关写入情况，以及后台命令和自有资源的实际状态：

浏览器任务按需补 URL、真实依赖、主题、视口和关键操作；其他专业任务只填相关方法，不设统一巨表或固定审批阶段。审查以基线、限定差异和停止相关写入的范围为输入；不默认增加全仓哈希、manifest 或永久验收归档。

每个有意义成果、交付、长检查或等待前、暂停或回复用户前，以及持续有改动时约每 5 分钟的下一个安全边界，负责人交出可恢复片段并暂停相关写入。root 进入各自 worktree，分别调用 checkpoint 工具提交并推送；未编译 WIP 如实保存，不等待最终验收。必要源码、harness、probe 与版本/命令进入 Git，不能只交文字。逐分支确认远端保存结果，push 失败保留并重试，禁止 force。

子 agent 不执行 Git 写操作、切换分支或创建/切换 worktree。`ai/integration-*` 承担隔离联调；正式验收后才由 root 将完整原子结果交付 `main`，包含实现、测试及必要文档。具体保存/恢复命令与会话归属规则引用[恢复说明](../../../.agent-state/README.md)，不在每张任务卡复制操作流水。
