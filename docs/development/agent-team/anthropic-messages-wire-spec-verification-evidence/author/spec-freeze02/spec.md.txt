## 3. 最小公共载体与同一传输

保留 `NewOpenAIChat`、所有旧 revision、`Request` / `CallOptions` / `End` / `Observation` 与 Exchange 方法签名。待 tools 最终接受后，仅增加以下公开形状；`mc` 为既有 model contract：

```go
const AnthropicMessagesTextToolsRevision = "anthropic-messages-text-tools-v1"
type AnthropicMessages struct { /* private Transport and *Budget */ }
func NewAnthropicMessages(Transport, *Budget) (*AnthropicMessages, error)
func (*AnthropicMessages) Start(context.Context, Request, CallOptions) (*Exchange, error)
// 两个现有载体只追加以下字段：
// Result.Message *mc.Message
// Event.PartIndex *int
```

Anthropic JSON 成功结果只填 `Message` 与原 `End`；Message.Role=assistant、Parts 按 native content 原序，只含 TextPart/ToolCallPart，必须通过 C0 Validate。原 `Text` 为空、tools 候选的 `ToolCalls` 为 nil，避免两份可分歧正文。OpenAI 三修订的 `Message` / `PartIndex` 恒 nil，既有 Text/ToolCalls/Event 含义保持；错误一律零 Result，SSE 不通过 Result 或 StreamEnd 夹带整条 Message/Arguments。

Anthropic SSE 的 TextDelta/ToolDelta/ToolComplete 都携 native `PartIndex`（0..255）；ToolDelta.Index/ToolComplete.Index 继续是遇到工具的稠密序号0..127，不能以 native part index 直接替代。文本块之间即使相邻也不拼成同一 part，text/tool/text 的顺序必须可重建。为了保留 `content:[{"type":"text","text":""}]` 的已有 C0 合法结构，空 text block 的 start 发一次 `TextDelta{Text:"", PartIndex:&i}` 结构标记；只有此新 revision 有该规则，不算 PartialOutput，不产生伪造正文。非空初始 text 直接发带该 index 的片段，随后 delta 续在同一 part。未来消费者须按冻结 revision 解释，不能套 OpenAI 无位置文本拼接器；本卡不实现未来 Runtime 投影。

不新增泛型 parser/transport 公共接口、不复制 Exchange/Client/Budget。使用私有 protocol 分派选择 native 请求/响应/SSE、header request ID 与错误解析；复用一个具体 Budget 的64全局/8 Project、原 Exchange worker 与 D04 client。新结构和 adapter 沿原安全 Format/LogValue/MarshalJSON；克隆 Message 的全部可变 parts/RawMessage，Event.PartIndex/工具 payload 指针也独立复制。Result 生命周期结束及时清掉私有结果；不把整 native buffer 经短 substring 留给小事件。

## 4. 准入、endpoint 与请求编码

Start 在 accept/Client/worker/Do 之前完成 C0、闭集、历史关系、大小和不可变编码检查。只接受 `AnthropicMessagesV1` / `AnthropicMessages` / Chat / 本 revision；输入输出 modalities 仅 text，ResponseFormat=text，StructuredOutputModes 空或仅 text；Parameters/RequestOverwrite 必须空 object，HeaderOverwrite 为空。Reasoning=false、无 efforts；流需 Streaming=true，工具历史/本次 tools 需 ToolCalls=true，ParallelToolCalls 沿 C0 显式值。MaxOutput 必须已配置正数；nil 为当前 profile unsupported，零/负数按 C0 InvalidArgument。没有型号猜测、静默参数丢弃或未验 beta。

**平台 Endpoint 是 API base_url**：保留既有 escaped path，只沿旧 wire 的单个尾斜杠规则追加固定 `/messages`，不猜测补/删版本、不调用 path.Clean。原生配置示例 `https://api.anthropic.com/v1` → `/v1/messages`；`https://host/proxy/v1` → `/proxy/v1/messages`；origin-only → `/messages`，不会自动变成 `/v1/messages`。SDK 默认 origin 后调用 `/v1/messages` 只是原生终点证据，平台 base 约定由本卡按 D09 §2 固定。无 userinfo/query/fragment；编码斜杠、代理前缀及精确 RequestURI 均需真实验证。

固定 POST；D04 `HeaderCredential("X-Api-Key", "", material)` 只绑定本次 target origin；请求显式 `anthropic-version: 2023-06-01`、Content-Type application/json，Accept 按 JSON/SSE。不发 Bearer、anthropic-beta、SDK 特有 headers、用户 metadata 或任意 overwrite；不把 key 转成长期 string 或日志。认证材料仍由调用方在实际 Joined 后销毁。POST 3xx 不跟随，HTTP 只在 CallOptions 与 D04 都显式允许时使用，实际首写门禁/透明零字节重试沿 D04，不加 SDK/adapter 重试。

| 输入 | native 编码与关系 |
| --- | --- |
| 开头 system 消息 | 只接受开头连续 system/text parts，按原序构成顶层 system text block 数组，不 trim/合并字符串/补分隔符；后置 system 拒绝，至少有一个非 system 的 user turn |
| user / assistant | user 仅 text；assistant 按原 parts 编码 text 与 `tool_use{id,name,input}`。保留空 text 与混排顺序；合法最后 assistant text prefill 不被改写。历史工具名不要求仍在本次工具集合 |
| role=tool | 仅 ToolResultPart，编码下一 user turn 的 `tool_result{tool_use_id,content:[text…],is_error}`，显式保留 true/false；空结果 parts 编码空字符串。OutputSchema 不发 native 请求，不编造错误文本 |
| 历史分组 | 每 assistant 工具组 ID 非空唯一；紧随结果恰一一匹配，可乱序，拒孤立/重复/遗漏/普通消息跨越未完成组。连续 tool 消息同组收敛到同一 user content，结果在后续普通 user text 之前；同 native role 连续消息仅按原 block 顺序组合，不插字/换序。完成组之后 ID 可复用，不成为全局执行身份 |

## 5. JSON 响应、内容与终止

仅200和正确 JSON MIME 进入成功解码；完整严格 UTF-8/Unicode escape、duplicate-key、单 JSON 值与类型校验。核心 message 必有 type=message、role=assistant、非空且无NUL的id/model（各≤256 UTF-8 bytes）、content array、非空已知 stop_reason。响应 model 可为请求 alias 的解析结果，不擅自要求与 snapshot 字符串相等，也不据它改写 snapshot。native message id 不冒充 ProviderRequestID；后者只取 `request-id` header 的既有安全 ASCII/256字节投影，缺失/非法则空。

先独立验证完整 envelope/usage 候选并保存可靠 usage，再处理内容的语义失败/refusal/unsupported。合法 refusal 允许空 content，仍先保存 usage 后报 content_filter；不能改成缺少成功正文的错误。其他成功要求1..256 content blocks，所有 Text/ToolCallPart 合并成有序 C0 Message。text 保原文及空块，citations 仅省略/null/空数组；非空 citations 明确 unsupported。tool_use 的 input 是**JSON object，不是 OpenAI arguments 字符串**，按原 RawMessage 保留数字词法，不 float64 往返；每项≤1MiB、C0 ToolCallPart.Validate 成功、最多128、ID唯一、name命中本次集合及 choice/parallel。

tool caller 允许省略/null或精确 `{type:direct}`；server caller、toolset_name 非空、server_tool_use、thinking/redacted、其他已知不支持内容失败，不悄悄丢 part。container/diagnostics 只允许省略/null。stop_details 仅在 refusal 时允许type=refusal、可空category（固定SDK五值）及可空explanation（≤64KiB），读后丢弃，解释正文不进入错误；非 refusal 的非空扩展为 unsupported。其他未知字段/类型为 protocol_invalid。不能把合法 usage 当整个 content 已验。

| stop_reason | 本修订结果 |
| --- | --- |
| end_turn | stop；不得带工具，required/named不得零工具成功 |
| stop_sequence | 仅无工具且ToolChoice非required/named的文本可成功为stop；任何工具内容或required/named零工具均为protocol_invalid。stop_sequence必须为非空字符串且≤4KiB，其余正常stop_sequence字段只能null/省略；本卡不发送自定义stop_sequences，不将原停止串投影成正文 |
| tool_use | tool_calls；至少一个完整合法工具，none不得工具，named只能该名，parallel=false最多一个；全部校验后才发布 |
| max_tokens | 无工具且非强制工具时为 length 的文本结果；任何工具内容/强制工具不满足均安全 protocol_invalid，不能发可执行的半工具 |
| refusal | content_filter，零 Result/零成功 StreamEnd，保可靠 usage |
| model_context_window_exceeded | context_too_large，零成功，不猜成正常stop或自动压缩/续发 |
| pause_turn | unsupported_feature；不自动继续 server-side turn |
| 未知/空原因 | protocol_invalid；HTTP EOF不补出原因 |

普通 JSON 全响应总量≤16MiB，解码正文 text + tool arguments 的总量也≤16MiB。Args 的 object 根 depth=1、子 value（含 scalar）≤32、重复键/尾随/非法 Unicode/NUL ID/`1e400` 沿 C0 拒绝；>2^53 的有限数字保原词法。Anthropic input 本身嵌入 envelope，不能直接套“整个 native JSON 深度32”把合法 C0深度32缩成28：新 parser 按固定 envelope 开销最多36层防护，再对子 input 独立跑 C0深度32。旧 OpenAI jsonShape 闭集/默认深度不放宽。长扫描每有界步检查原ctx，无脱离 Exchange 的验证 goroutine；取消后不发布 Message。

## 6. SSE 状态机与位置

复用有界 SSE framing；私有 reader 可暴露 event name/data，原 OpenAI `next` wrapper 仍只接受其旧 event 名。Anthropic 要求 event 名与 JSON type 精确相同，支持下面六个 message/content 事件与 ping/error；未知 event/未知type/不匹配不忽略。保留 comment、多 data 行、CRLF、跨网络 UTF-8/JSON 转义拆片；每 event（含注释/字段行）≤1MiB，EOF 中断不当正常结束。

1. 恰一次 message_start：message的核心身份与§5一致，content=[]、stop_reason/stop_sequence为null/省略。初始 usage 按§7原值观察并发 UsageUpdate，不补 output=0。ping 可在非终局任意位置出现，仅校验固定type，不改变状态/PartialOutput。
2. content_block_start 按0起连续 native index 创建，最多256part/128工具；拒负数、非整数、稀疏巨大index/重复start。可有多个已start未stop块，delta/stop只许作用于对应活块，不能在index切换时猜另一块结束。工具index另按工具遇见顺序分配。text初值按§3发位置片段/空标记；tool id/name完整校验后分两项 ToolDelta 发出，不能因先见一个完整名字便执行。
3. text_delta 只属于text；input_json_delta只属于tool。partial_json 解码后的原字符串按顺序累积，空片段不发空工具事件；分为≤64KiB且不拆UTF-8的 ToolDelta。tool start 的 input object 先有界保存；首个非空 partial_json 到来时按官方累积语义替换 start input，不把`{}`拼到 JSON 前面。若直到stop无非空delta，采用显式start input并在stop前按同样片段规则交付。因此参数完全来自供应商，不把“无输入字段”补成空object。
4. content_block_stop 恰一次，校验本块最终 text/tool 形状、完整 object/C0 与全部独立上限，之后拒该块late delta。工具完整输入验证后即可释放参数 buffer，只留有界ID/name/字节数/part索引；尚不发 ToolComplete，避免后续同响应另一工具坏时先给“全部工具已合法”的暗示。已经给出的片段只为 partial。
5. message_delta 只在全部已开始块stop之后；允许 stop_reason null 的中间累计usage更新。恰一次非null终止原因，按§5全响应的工具集合/选择/parallel及usage语义校验；全部成功后按工具dense index发 ToolComplete（含对应PartIndex、原metadata-only ArgumentsBytes），不含完整Arguments/隐藏句柄/取回口。终止原因后只接受message_stop或ping/error，拒第二终止/内容增量。
6. message_stop 必须在已知终止原因、所有块完成与全响应校验之后；它是必要协议终止，不使用 `[DONE]`。缺message_delta、缺message_stop、半JSON、流内error、取消或后续协议错误都零成功StreamEnd，已观察usage仍留存。message_stop后原parser返回/Body.Close/Client.StopAdmission+Drain实际完成且ctx有效，Next才恰一次返回StreamEnd，随后EOF；已交付ToolComplete不等于上述成功或业务提交。

text累计只计字节，不在SSE保留第二份全文/Message。工具initial input候选、当前参数buffer、所有已接受文本/参数字节共同受16MiB总上限；start input被首delta替换时原候选释放且不当已交付参数，不能一边保留128份大初值一边把其排除预算。每工具最多1MiB，最多128工具；metadata有界。每工具只在完整校验时临时有一次≤1MiB副本，之后释放；小片段按append/chunk增长，不能每delta复制完整前缀。

队列仍≤32项且所有payload合计≤256KiB；计入Text、全部ToolDelta/ToolComplete字符串、Usage/End和PartIndex等标量/指针指向值，新的独立clone字符串不能漏计。空text结构标记也占一项及位置成本。SSE没有整体Message/Arguments队列项，不用私有缓存句柄绕过上界。满队列仅原worker可取消等待，不为每part起goroutine。PartialOutput只依据Next已交付的非空TextDelta/ToolDelta或ToolComplete，再结合真实Sent；空text/仅usage/ping/只入队都不算。

## 7. usage：原值、覆盖与失败保留

| Anthropic 字段 | C0 |
| --- | --- |
| input_tokens | InputTokens，保该原值，不加cache |
| output_tokens | OutputTokens，已包含thinking，不再加reasoning |
| cache_read_input_tokens | CachedInputTokens |
| cache_creation_input_tokens | CacheWriteTokens |
| output_tokens_details.thinking_tokens | ReasoningTokens；有明确值才填，不从可见thinking文本估计 |
| 没有total字段 | TotalTokens始终NULL，不从input/output/cache估算 |

初始/普通结果缺失或null为未知，明确0为0；本库沿D09允许整个usage或计数字段缺失/null，不把SDK的必填注解变成伪造计数。现有已知字段保持ProviderUsage，无任何已知值则UnknownUsage。只接受原生非负十进制整数≤MaxInt64，不接受字符串、小数、指数、负数、溢出；>2^53精确保存。

每次 message_delta 先完整解析候选，再一次更新：非null的新值**覆盖**旧值，不加和、不取max、不要求单调；optional omitted/null保先前值，output缺失/null也不把最后可靠值归零。output_tokens_details缺失/null保旧Reasoning，合法新thinking才覆盖；不以本地推算修正、夹断或归零其他供应商计数。非法字段不能先提交其中几个合法值，Observe/UsageUpdate必须同一完整候选，满足既有C0 Usage.Validate。

cache_creation 的两个TTL细分、server_tool_use的两个请求计数只按固定来源检查非负整数，不计为token；service_tier只允许固定standard/priority/batch，inference_geo为≤128 UTF-8 bytes的字符串，这些旁字段均可省略/null且不进入Usage。server工具计数非零属本修订不支持的实际能力，先保存已合法token再失败，不宣称本地工具执行。未知usage字段或错类型失败，保此前合法观察。

初始usage、普通envelope usage或后续累计更新一旦合法，不因坏工具JSON、refusal、网络断流/error、超时/取消撤销。例如start output=1而final output=0要得到0；start有cache、final只给output须保cache；start之后缺message_delta/message_stop为失败但保start值。此为最后可靠观测，不声称已取得供应商最终完整账单。成功terminal确无任何usage时仍可成功且全NULL；不从正文、max_tokens、工具个数或HTTP状态估算。Observe只有wire事实，不是ledger已提交确认。

## 8. 安全错误、取消与唯一 owner

HTTP非200最多读64KiB错误body；已知error envelope只验证type/error.type与有界message等固定字段，原message/诊断正文一律丢弃。可信分类来自HTTP状态和固定error.type，不解析英文message猜model不存在/上下文长度；404/not_found_error都不自动变model_not_found。HTTP401→authentication，403→permission，429→rate_limited，408→timeout，500/502/503/504/529→provider_unavailable；其中rate_limited/timeout/provider_unavailable设Retryable=true，仍不在adapter重发。400/413/422→invalid_request，其余→provider_error且不重试；非法body仍按安全HTTP状态fallback，不泄露body/cause。HTTP Code固定为wire_http_error，body不能把401改成可重试错误。

200 SSE的error采用固定error.type：authentication_error/permission_error/invalid_request_error分别映射同名语义；rate_limit_error→rate_limited、timeout_error→timeout、overloaded_error→provider_unavailable并可重试；api_error/not_found_error/billing_error→provider_error且不重试。未知type安全unknown且不重试。有效error envelope的Code固定为wire_anthropic_error，坏形状为原wire_protocol_invalid，不复制供应商自由文本；header request-id安全过滤，body request_id不覆盖header。流内error不当HTTP200成功，也不丢已有usage。

本地C0/消息关系错误为InvalidArgument/NotStarted；合法但不支持的能力为unsupported_feature/wire_unsupported_feature，均零slot/Exchange/Do。收到的坏协议为provider_error/wire_protocol_invalid，上界为wire_limit_exceeded；Refusal/上下文耗尽按§5。Dispatched仅来自D04 Decision.Sent，PartialOutput按§6，不凭Start或HTTP headers猜发送。所有Request/Result/Event/日志/错误都不得出现key、输入/答案、tool schema/args或供应商诊断canary。

constructor无I/O/worker；overall≤120s、read-idle≤60s并不超剩余overall、caller更早取消、Close/Force原预算和真实Join规则全部沿已验Exchange。新parser/校验在原worker内，取消唤醒读/背压/长扫描；Body.Close/worker/Client.Drain前保slot与借用材料边界。ctx.Done或合法message_stop不代替Join，无WithoutCancel/新超时/后台无限等待/第二client池。结果发布前复核原ctx，失败/取消零Message、一次错误后EOF。其外层DB writer、ProcessGuard、Project生命周期和工具side effects仍未绑定。
