## 覆盖和原失败

- 作者新组对真实初始管理员/正式邀请创建用户逐项比对 DB 注册时间、资料变更不改时间、同时间稳定分页；补合法 HEAD 查询、非法/篡改/跨资源 cursor、普通用户/匿名/真实撤销 Session 拒绝。owned 用户行 year10000 的 GET/HEAD 均安全503，随后恢复 fixture。
- 独立组重新创建真实身份，检查新九字段/旧八字段隔离、DB 精确 canonical 时间、HEAD 编码长度、合法 cursor 变 limit、非法 query 同状态、精确 `Allow: GET, HEAD` 和其他列表 HEAD405，以及当前权限与已撤销 cookie。
- 单元受控 rows 的 first/middle/limit+1、ID/version/role/theme/时间/行错误均零候选；不把受控 rows 说成真实数据库。新真实 year10000 场景另有实际 HTTP/PG 证据。
- author01 的 admin HEAD405 首红保留。rev1 静审把 serializer 的 HEAD 空 body 能力误当成实际路由支持；该静审结论被首红纠正。rev2 修复仅增加 users 显式 route/query/OpenAPI，原 HEAD200 断言保留，修后真实通过。见 `finding-head01.json`。
- 复用 input01 未变扫描/契约/Runner 检查，input02 重跑受影响 HTTP/CSRF/Directory pure+race、account vet、集成仅编译及 Central build。`-run ^$` 及脚本中其他 `[no tests to run]` 不是动态用例通过。
