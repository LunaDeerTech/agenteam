已验前置明确区分：`81fe742` 是真实 Project Owner/Session/gate + Secret checker/Audit/CRUD 的库组合，保留其未归因旧 Outbox 红；不是 HTTP/root。`ecd7337` 明确覆盖 Secret.Metadata Project Owner/Read，同 Tx User/Credential/Project SH；新 HTTP 2s 可约束原库 3s 上限，不需推定新库语义。`ac5b4c65` 的被动查证仅 System，原 Unknown 为合法 Store 装饰，不是网络 ACK 丢失证据。

1. **Project lookup 是本卡新增契约与真实锁增量。** 当前 contract/write_lookup.go:24–29 仅 System/owners=[User]；write_lookup.go:37 强制 System 端口，49 只持 Command/User SH。新 Project 分支须独立 Validate scope、精确 owners=[ProjectID,UserID]、secret namespace、kind/ref/version/Purpose=Model；同一 Tx 一次 AcquireAll Command/User/Project SH，再真实当前 Session/Owner Read/gate 后 scope/scope_key/command_digest receipt SQL。不能只放宽 Validate，不能依赖 Tx 外预授权补锁。保 System 分支兼容、nil/typed-nil 分支与当前 Session 优先级、提交 Unknown/取消零 observation。有效不同 namespace 是独立 key，通常 absent；同 identity 错 kind 是非法，已存行内容与请求不符另属 KeyReused，验收须分清。
2. **Read 观察不能成为 mutation 成功捷径。** 固定 System http_credentials.go:153–189 的 observed 只跳 Metadata；Metadata 失败后的晚 lookup 命中也只继续，所有成功必经唯一 ExecuteWrite 原 request。可复用 Purpose 防误改与迟到 receipt 形状，不能返回 observation.Result 替代 ExecuteWrite。Secret write.go:273–276 的 Apply 当前 Mutate 先于 findReceipt；archived/archiving Read lookup 可观察历史，但原材料写重放仍被 Mutate gate 拒绝，deleting 连 Read 也拒绝。Tx 外 Mutate precheck不替代真实事务。Create PrepareWrite 已有 Tx 外 receipt→stableRef 发现，不能写成“所有 receipt SQL 必先 Mutate”；原最终返回仍由 Apply 当前权限+原材料摘要绑定约束。
3. **真实 root 同 Store/Authority 接缝。** 固定 createProjectUsage 尚未填 AuditFacts，createSecret 尚未绑定 Projects。应同 db 构造 Secret ProjectAuditAuthority，填唯一 Project Authority 的 SecretProducer map，再构造 Project SecretAuthority→真实 Audit/Secret，保持原 model/Project Outbox 与 catalog 顺序。Secret checker 的 witness 精确 Store/Tx/Entry/AppendKey/原 receipt/payload ownership；不能用 alwaysallow/fake checker，也不能声称 opaque provider 构造时能识别任意 wrapper 的 Store。同实例装配与运行时跨 Store/Tx 拒绝分别举证；只登记 Secret，Object/cleanup/lifecycle 不顺带启用。
4. **材料所有权与公开零泄漏。** 固定 SecretMaterial 上限 65536 byte；New 会复制，Use 借同步私有 copy并defer clear，Destroy 清理持有 bytes，但 Go JSON string/运行时临时复制无法承诺全部擦除。新卡必须冻结文本/编码语义、完整 JSON最坏转义预算、strictpresence/null/未知字段、最大合法实编码和 +1 拒绝、所有 return/panic/cancel 分支的 owned buffer/material Destroy。仅安全 Credential ID/Purpose/version/deleted DTO；响应/Problem/log/trace/样本不含材料、密文或摘要。native syscall记录限端口与生命周期，避免read/write/send/recv缓冲载荷落入raw。
5. **真实 Unknown、权限和引用保护。** 正式账户链建立三写→metadata/HEAD→原 key无材料 lookup；同User新Session、跨Project/User/kind/ref/version、撤Session/Owner、archived/deleting、活 lease/retain删除拒绝。原 ExecuteWrite 仍核原完整材料，lookup present不证明材料同义、absent不证明回滚、不授权自动重试。物理 ACK 丢失需精确原目标Tx/backend及实际COMMIT/idle；held原writer未终局和释放后的终态分记。未知/取消不发布候选，单次实际调用、回滚零额外receipt/Audit/Touch，材料泄漏检查不把测试sentinel输出为证据。
6. **I/O 与共享根交接。** 新规格要冻结写预算/2s读查证、自然到期/更早parent、业务前无I/O能力解析、bounded Unwrap/解析前尾部所有权、partial deadline/FlushError优先级、实际Write/Flush/Close/callback join/keepalive清除；复用已验工具也不得复用旧env PID baseline或把native合成writer当socket。精确新旧 selectors、实际闭包、每top含Cleanup预算、owned七资源双清与daemon未wait限制由完整卡给定。Model read 产品完整接受且root移交account等共享根后才能实施/运行；规格阶段不消费其活动实现。生产Resolution/Invocations/Meeting/D24、创建initializer/生命周期、ready503和三停止保持。
