## 真实与纯测试门槛

原 fixture `validWire` 将每场景 Chunks 限为 512 项、总 payload 512 KiB；HoldAfter/DisconnectAfter/Release 及请求、handler、connection 观察可复用，毋须改旧 fixture。静态尺寸算例中恰 320 KiB 的 JSON object 参数，包含工具 delta、finish 和 DONE 后总 SSE payload 为 328108 B，最大 native event 为 327943 B，均在原限制内。此计算只证明该验收场景可构造，没有运行 parser 或网络。

真实 320 KiB 场景必须验证参数逐字重建及 ≤64 KiB 输出片段，并跨越 256 KiB 队列总 payload；不能只用小参数或只检查事件个数。1 MiB 与 +1、16 MiB 与 +1、128/129、256 event entries、C0 深度/数字/NUL 和长扫描取消在纯 parser/transport 测试证明。单事件 1 MiB 限制仍适用；精确 1 MiB 参数通过多个 native events 组成，不能把外层 SSE/JSON 额外字节误计成参数能力下降。真实与纯门槛必须分别报告。

独立动态验收仍需合法 envelope 内 arguments/choice 失败和工具输出已交付后的取消/缺 DONE；使用主线程独占窗口、原 race/count1/6m、固定输入/argv/env/exit/raw 与双次 exact-ID 清理。当前未运行这些检查，不占资源窗口。最终只推荐规格采纳，不替代后续作者自测和未参与实施者的独立验收。
