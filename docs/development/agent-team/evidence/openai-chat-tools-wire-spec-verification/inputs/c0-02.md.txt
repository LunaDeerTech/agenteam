## 3. 修订与正式 wire 增量

保持 `NewOpenAIChat`、`Start`、`Request`、`CallOptions`、`Exchange.Observe/Result/Next/Close/Joined` 方法签名；保持原 `End`、`Observation`。只新增下列导出载体/常量和两个现有结构的字段；`mc` 为既有 model contract。

```go
const OpenAIChatToolsRevision = "openai-chat-tools-v1"
const (
    ToolDelta    EventKind = "tool_delta"
    ToolComplete EventKind = "tool_complete"
)
type ToolDeltaEvent struct {
    Index             int
    IDFragment        string
    NameFragment      string
    ArgumentsFragment string
}
type ToolCompleteEvent struct {
    Index          int
    ID             string
    Name           string
    ArgumentsBytes int
}
// Result 原 Text/End 字段保持；新字段只有 JSONResponse 成功才返回。
type Result struct {
    Text      string
    End       End
    ToolCalls []mc.ToolCallPart
}
// Event 原 Kind/Text/Usage/End 字段保持；新分支恰一个 payload。
type Event struct {
    Kind         EventKind
    Text         string
    Usage        *mc.Usage
    End          *End
    ToolDelta    *ToolDeltaEvent
    ToolComplete *ToolCompleteEvent
}
```

`ToolDeltaEvent` 每项恰有一个非空 fragment，Index 为 0..127；fragment 是已解码 UTF-8 字节，不是 raw JSON 转义。`ToolCompleteEvent` 是已验证完整参数的元数据标记，**不含**完整 Arguments、私有缓存引用、取回参数方法或任何执行能力。SSE 消费者按 index 拼接已收到的片段，核完整 ID/name/ArgumentsBytes 后可在自己的有界内存中重建 C0 ToolCallPart；这只是未来 Runtime 的投影责任，本卡不实现它，也不为 wire 事件分配 CallID/InvocationID/ModelFrame sequence。

新载体提供安全 Format/LogValue/MarshalJSON，只输出固定 marker，不暴露 name/ID/片段/参数；Result/Event 继续原安全格式化。接受请求和返回结果均复制可变切片/指针/RawMessage，调用方修改不能改变本次编码、请求工具集合或后续事件。旧修订所有 Result 的 ToolCalls 为 nil，旧 Event 新字段均 nil；未知 revision/未支持组合在准入前拒绝。

新 revision 只接受 OpenAIChatV1/OpenAIChat/Chat、text 输入输出、ToolCalls=true、ParallelToolCalls 为既有显式布尔；Streaming 沿原能力检查。Parameters/RequestOverwrite 必须空对象，HeaderOverwrite 为空，无 reasoning，StructuredOutputModes 为空或仅 text，ResponseFormat=text。tools+json_schema 组合不属于本修订；旧 structured 修订仍拒绝 tools，不修改旧 snapshot 的含义。

## 4. 请求、历史消息与能力限制

Start 在 Budget.accept、Client/worker/Do 之前完成本节全部校验与不可变请求编码。C0 的合法结构是起点，native function name 另限 `[A-Za-z0-9_-]{1,64}`；工具定义名唯一、最多128个，description/InputSchema/OutputSchema 保留 C0 上限，输入 messages 1..256、累计 MessagePart 至多256。请求编码总量仍 ≤16 MiB，分配前检查累计预算，不先展开大数组再判大小。

每个 Tool 映射 `{"type":"function","function":{"name":Name,"description":Description,"parameters":InputSchema,"strict":false}}`。InputSchema 是有界完整 JSON object，保留原字段和精确数字；本修订不编译它、不展开 `$ref`、不改 required/additionalProperties，不冒充 strict-schema 保证。OutputSchema 是平台工具结果契约，不发送为 native 参数。本库只检查返回 arguments 的完整 JSON object 与声明工具名，实际 schema/权限/业务验证仍归未来 Tool/Runtime，不能据 ToolComplete 自动调用工具。

| 工具选择 | 编码与结果约束 |
| --- | --- |
| tools 非空，none/auto/required | 原生同名字符串；none 只允许零工具结果，auto 允许零或多个，required 必须至少一个 |
| named | Name 必须精确命中本次工具集合；编码 function named choice，结果只能调用该 name |
| tools 为空 | 只接受 none/auto；两者均不发送 tools/tool_choice/parallel_tool_calls，使用官方无 tools 的 none 默认；required/named 为 InvalidArgument |
| parallel | tools 非空时总是显式发送 capability 的 true/false；false 时本次输出最多一个工具调用，true 时仍最多128，不表示上层必须并行执行 |

system/user 保留单一 TextPart。assistant 接受至多一个 TextPart 加 function ToolCallPart；普通文本仍使用 string content，只有 tool calls 时 content=null；tool_calls 按原 Parts 中的工具顺序编码，arguments 是保存原 JSON 文本的 native 字符串。历史工具 name 不要求仍在本次可选工具集合，以免配置工具集合变化改写历史；仍执行 native 名称、JSON 与字节限制。

role=tool 只接受 ToolResultPart；同一 Message 的多个结果按原 Parts 顺序展开为 native tool 消息，每项精确 tool_call_id。Text ResultPart 按原顺序编码原生 text content 数组，空 Parts 编码空字符串；image/file/其他类型在准入前明确 unsupported，不读取 Object。原 IsError 属平台执行结果状态，OpenAI 没有对应字段：发送调用者已构造的原文本，不新增 is_error 键、不添加或伪造错误正文/前缀；其 true/false 均不能改变调用权限或工具执行，验收明确核这一映射。错误状态的持久化和对模型可见的 canonical 文本由未来 consumer 提供，本库不生成工具结果。

历史每个 assistant 工具组的 ID 非空且唯一；随后的 tool results 必须各命中该组尚未匹配的 ID，允许组内结果乱序，不允许缺失、重复、孤立结果或未完成组被下一条普通消息跨越。一个完整组结束后才可进入下一组；不同完整组可复用相同文本 ID，不将它当全局 Operation 身份。展开后仍受256消息与16 MiB上界。输入不合法为 InvalidArgument/NotStarted；C0 合法但能力/修订/媒体等不支持为原 unsupported_feature，均零 slot/Exchange/Do。

原 endpoint 路径/Bearer origin binding/POST 禁重定向、include_usage、max_completion_tokens、实际 D04 网络策略及错误保持。无 SDK/adapter 重试，无新 URL/header/任意 native JSON 入口。

## 5. 普通响应与完整工具结果

沿原 status=200、JSON MIME、单 choice index=0、严格 envelope/字段类型/Unicode/duplicate-key/usage 检查。仅新增 function tool_calls 与 finish=tool_calls 的闭集；custom、deprecated function_call、未知键/类型仍明确失败。无非空 refusal 的成功响应仅在有工具结果时允许 content 为 null/省略，不能把空结构当成功正文。合法 refusal envelope 不受这项成功形状限制：非空 refusal 配 null/省略 content 仍先保存可靠 usage，再返回原 content_filter，不改成 content 缺失错误。

每个工具必须具有完整非空且不含 NUL 的 ID（最多256 UTF-8字节）、type=function、本次允许的精确 name、完整 arguments 字符串。arguments 解码后 ≤1 MiB，恰一个 JSON object，无重复键/尾随值/非法 Unicode。普通 Result.ToolCalls 及每个 SSE ToolComplete 都须以既有 `mc.ToolCallPart{ID, Name, Arguments}.Validate()` 成功为完成门槛，再满足本修订的 native 名称与工具集合约束；C0 只读不变，不能仅用 adapter.jsonShape 的较宽检查代替。

C0 `objectJSON/jsonBody` 的根 depth=1，每个子 value（包括标量）递增且不得超过32；其 json.Number 经 `strconv.ParseFloat(...,64)` 检查错误、Inf/NaN，仅用于验证范围，不能把该浮点值写回参数。有限且大于2^53的数字仍逐字保留原 RawMessage/片段词法，`1e400` 等 C0 拒绝的值安全失败，不交普通工具结果或 SSE 完成标记。最多128个工具，ID 唯一；JSON 数组位置即工具 Index，Result.ToolCalls 保留该顺序。混合响应的 Result.Text 是原文本，工具列表独立；本库不推断原生 content 与 tool_calls 两字段之间不存在的时间顺序。

finish=tool_calls 必须有合法非空工具结果且符合 ToolChoice/parallel 约束；finish=stop 不得带工具，required/named 不得零工具成功。已有工具片段却以 length/content_filter 结束不交完整 ToolCalls；length 安全失败为 provider_error/wire_protocol_invalid，content_filter 或非空 refusal 为 content_filter。没有工具且 choice 不强制工具时，stop/length/content_filter 保持原文本修订的已知 finish 含义；非空 refusal 仍错误。成功 Result 必须全部工具通过，不返回部分工具数组。

先保存通过原 envelope/usage 类型校验的可靠 usage，再验证工具参数或拒绝结果；普通响应参数坏、截断或 refusal 不丢已收到的合法 usage。无法合法解析 envelope/usage 时不虚构用量。未知字段为 NULL、明确0为0、六字段映射和 int64 溢出拒绝沿旧规则。只有原 Client/body/parser actual join 且本次 ctx 仍有效，Result 才返回完整文本和工具；失败/取消返回零 Result。

合法但未支持的 custom/deprecated 协议变体沿 unsupported_feature/wire_unsupported_feature；未知字段、坏类型/工具名绑定/ID或选择关系、参数JSON错误沿 provider_error/wire_protocol_invalid；字节/数量/深度预算超限沿 provider_error/wire_limit_exceeded。拒绝结果不回显参数或原诊断文本，Dispatched 仍只来自实际 Decision，取消/超时/HTTP/D04 fault 沿原安全映射；不能为使新测试通过而重写旧 text/structured 错误分类。

## 6. SSE 组装、队列与终止

按原协议读取每个 ≤1 MiB event，支持 UTF-8/JSON 转义拆片、obfuscation、最终空 choices usage 和必需 `[DONE]`。每个原生 tool delta 要求 Index 为整数0..127；同一 chunk 的重复 Index 按出现顺序合并，不同工具可交错，不能在 index 切换时提前认定前一工具结束。id/name/arguments 的非 null 字符串按序追加；缺失/null 不覆盖已得内容。type 缺失可等待，出现则必须为 function，重复 function 合法，其他值失败。最终每个工具必须实际见过 function 类型。

每个 native entry 的输出次序固定为非空 IDFragment、NameFragment、ArgumentsFragment；一个 native chunk 同时带文本和工具时先 TextDelta，再按工具数组顺序发片段。不声称该工程顺序是供应商跨字段时序。ID/name 的累计上限分别256/64字节；argument片段拆成 ≤64 KiB、保持 UTF-8 边界的 ToolDelta。空字段/index-only delta 只更新受限状态，不发空事件。单个 event 的工具数组至多256项，distinct Index 最多128；最终 Index 集必须恰为0..N-1，不能把稀疏巨大 index 用作分配长度。

parser 保存每个工具的有界 argument 累积和名称/ID，接受片段前核累计长度。整个响应 TextDelta 原文字节与各工具 arguments 解码后字节合计 ≤16 MiB；单工具上限仍1 MiB。SSE 不另存完整文本或第二份完整工具列表。组装使用有界 append/chunk buffer，避免每个小片段复制完整前缀；临时完整参数校验副本一次最多1 MiB，逐工具用完释放。ID/name/index元数据最多128组；不能预分配128个1 MiB buffer或从 index/长度声明直接分配无界内存。新的长扫描/逐节点检查服从原 ctx，不另起验证 goroutine。

在唯一合法 finish=tool_calls 处，先完整验证**全部**工具、密集 index、唯一ID、工具集合/ToolChoice/parallel、§5 的 C0 ToolCallPart.Validate 及参数 JSON 和累计预算，随后按 index 升序发 ToolComplete。验证一项失败则本轮零 ToolComplete；已经交付的片段保持 partial 事实。工具 buffers 在不再用于校验后释放，ToolComplete 仅保存 Index/完整ID/name/ArgumentsBytes；不把参数挪到隐藏队列或共享取回仓库。finish 后只有至多一次最终空 choices usage 和 `[DONE]` 可继续，拒绝工具/文本迟到增量、第二finish或第二完成标记。零工具的文本路径不发 ToolComplete。

队列仍最多32项、按所有 payload 字符串及标量保守计量合计 ≤256 KiB；ToolDelta 的 ID/name/Arguments 片段和 ToolComplete 的 ID/name 都进入 `eventBytes`。新 payload 字符串须复制为独立有界值，不能以短 substring 保留整块 event/argument buffer。不存在带1 MiB Arguments的队列项、绕过预算的缓存指针或完整工具结果随 StreamEnd 附送。parser 的累计校验缓冲与队列是两个分别受限的预算，不能把一个未计量的完整结果伪装成元数据项。满队列只在原 parser worker 内等待且可取消，不能每片段另起 goroutine。

ToolComplete 仅表示参数已经组装校验；它可在 usage/[DONE]/actual join 前交付，仍不得执行工具。缺 `[DONE]`、后续协议错误、取消、超时或 join 不成立，最终必须是一次安全错误再 EOF，零 StreamEnd；已交付的完成标记不能变成业务成功。StreamEnd 沿原 Next 路径，在原 Client/body/parser 真实 join 后恰一次交付，只含原 End。未来 Runtime 还须持久确认本次业务终态后才能发布 C0 message_end 或分派 Tool，本卡没有该能力。

PartialOutput 只依已经从 Next 返回的非空 TextDelta/ToolDelta 或 ToolComplete；只收到 UsageUpdate、只入队未交付、纯 index-only delta 都不算。仍结合实际 Decision.Sent；不能按累计 buffer 是否非空代替已交付事实。合法 usage 后的协议错误继续保留 Observe().Usage。
