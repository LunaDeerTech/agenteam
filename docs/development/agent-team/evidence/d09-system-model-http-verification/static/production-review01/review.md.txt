## F1：读事务已提交后的取消仍返回成功 observation

位置：固定 `internal/central/secret/write_lookup.go:97–100`。`commitError(committed)` 成功后直接返回 `observed, nil`，未检查 caller `ctx.Err()`。规范 §2.2 第 4 条（固定卡第 68 行）要求取消错误返回零 observation + 错误，同时保留真实 commit state。

精确可达情形：正式 Store 完成真实只读事务并取得 `Committed` 后，在 `WithinTx` 返回给新 lookup 前取消调用方 context。当前代码会返回已有的 `Observed=true, Result!=nil, nil`；若该读事务未观察到行，则返回 `Observed=false, nil`。两者都把已经发生的取消隐藏为成功读取。无需推翻或推测原写 receipt 状态，也不依赖网络故障。

最小修订：仅在新 lookup 的成功提交返回边界检查 `ctx.Err()`，取消则返回零 `WriteCommandObservation` 与安全 typed Fault，**保留 `foundation.Committed`**。不要用现有通用 `unavailable()` 把实际读事务改记为 NotStarted，也不要改成 Unknown；无需修改旧公共 `commitError` 或不相关 legacy 路径。已验依赖 `secret/model_usage.go:121–137` 的取消返回策略可作为既有实现参照。

后续必要验证：正式 Store 装饰层保留并记录底层真实 Committed，在交回结果前取消 context；分别覆盖已有 receipt 与 absent。断言零 observation、非 nil 错误、可追溯 context cancellation 和 Committed 状态。本轮仅静态确认此分支，未运行该反例。
