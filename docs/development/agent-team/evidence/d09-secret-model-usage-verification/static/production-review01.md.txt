## 确定问题

### S1 — 旧 Acquire 的更早授权/依赖错误被新 PreparationRequired 遮盖（P2）

位置：`candidate/internal/central/secret/lease.go:132`。

新增 metadata 预读在 `leaseGrant` 前；只要实际目的为 Model 且 owner 为 execution/model_call，就直接返回 PreparationRequired/ResourceBusy。可达输入为有效 Store/Tx、有效已存在 Model ref/owner、正确 SecretService actor，但 `auth.Usage=nil`。基线先经过 leaseGrant 的 nil dependency 分支，返回 AuthorizationUnbound/DependencyUnbound；候选从新分支提前返回 PreparationRequired。错误 actor/service/cause 也同样越过原 leaseGrant 的授权拒绝。此结论来自确定控制流，不依赖 SQL 竞态或恶意 provider。

这违反卡 §5“结构、初始化、Store/依赖失败等原有更早错误……不强行改成 PreparationRequired”。需在授权 lease.go 内恢复原更早错误优先级，仍在任何写入/upsert 前关闭合法原授权的实际 Model 组合。可恢复原 leaseGrant→metadata/purpose 核对顺序，再在 writable/INSERT 前作实际组合拒绝；不改变 Account/MCP/System 的合法行为。修后用缺 Usage、错 actor/cause 与合法 Model 对照反例分别核精确码及零写入，不能把任意 error 算通过。

### S2 — 已确认提交到交付之间的 caller 取消仍返回材料（P2）

位置：`candidate/internal/central/secret/model_usage.go:115`–`125`。

新入口收到 Committed 后无条件 NewSecretMaterial 并返回，没有检查原 caller ctx 的取消状态。确定触发路径：真实读取/AEAD/Audit Tx 成功提交；测试 Store 装饰器在实际 WithinTx 返回后、返回该原 CommittedResult 给 Service 前取消 caller ctx。候选继续复制 plaintext，返回非零可 Use 材料。固定 D03 `postgres/transaction.go:128`–`130` 在 raw.Commit 成功时返回 Committed，本身不承诺在后续交付点替调用层检查 caller 的取消。

卡 §5 明确取消一律零材料。需仅在新入口的确认 Committed 后交付点检查原 caller ctx，取消时零材料并走既定安全错误处理；保留已确认的数据库事实，不把此场景冒称回滚/Unknown。Unknown 必须仍优先保留其原 attempt/cause，不能被取消检查替换；不顺带改变旧 legacy 入口。真实测试装饰器可确定性验证 Audit 已提交、ctx 已取消、材料 Use 回调未运行；这不是网络故障或 backend 未终局测试。
