# 串行子 agent 开发团队

主线程负责与用户讨论、规划、下发、复杂诊断、审查、必要集成和汇报；业务实现由子 agent 执行。直接在 `main` 上每次推进一个工作项，完成验收和本地提交后再开始下一项。

## 角色与配置

| 角色 | 执行内容 | 项目技能 |
| --- | --- | --- |
| [backend_worker](../../../.codex/agents/backend-worker.toml) | 已确定的 Go、Central、Runner、数据库小任务 | `agenteam-go-development` |
| [frontend_worker](../../../.codex/agents/frontend-worker.toml) | 已确定的 Vue 页面、组件和样式小任务 | `agenteam-vue-development` |
| [verification_worker](../../../.codex/agents/verification-worker.toml) | 测试、浏览器验收、必要测试补充及文档同步 | `agenteam-verification` |

角色定义位于 [`.codex/agents/`](../../../.codex/agents/)，均固定 `model = "gpt-6-astra"`、`model_reasoning_effort = "max"`。[项目配置](../../../.codex/config.toml)将子 agent 默认模型和思考强度同样设置为 `gpt-6-astra / max`，最多一个子 agent；角色规则长期保留，实例按任务启动。主线程保持当前模型及思考强度。

角色身份以 TOML 的 `name` 字段为准；本项目文件名使用连字符，角色名使用下划线。检查时枚举实际文件，不根据角色名猜测文件路径。

当前子 agent 未结束前不启动下一位，也不把测试或文档放到另一个并行执行线程。子 agent 不再创建下级 agent。需要换角色时，先确认当前任务状态为已完成；中断任务则确认命令与文件写入已停止，再下发下一张任务卡。客户端提供关闭线程接口时可关闭；没有该接口时不把关闭作为交接前提，也不调用不存在的工具。若运行时仍因线程上限拒绝下一位，报告主线程，由主线程结束当前会话并在新会话恢复台账，不放宽并发配置。

新会话先读取 [AGENTS.md](../../../AGENTS.md)、[任务台账](tasks.md)、当前分支与实际差异，再恢复第一个未完成任务。不能仅凭上一轮的完成声明认定已交付。

正式产品开发的模块顺序、契约门槛与验收范围见[开发计划](../development-plan.md)。任务卡用于拆分当前模块的顺序步骤，小卡完成不等于模块已完成；模块全部验收后才推进下一模块。

## 任务卡与交接

主线程使用[任务卡模板](task-template.md)，先确定目标、文件范围、接口、步骤、必用技能、验收命令、预期结果及停止条件，再交给子 agent。每张卡只解决一个明确行为，通常涉及一个组件、函数或处理器；跨模块工作拆成顺序小任务。

流程：讨论确定 → 开发 → 验证 → 必要返修 → 主线程验收 → 本地提交 → 下一工作项。

- 用户确认工作项后，主线程在该范围内自动顺序下发，无需逐卡确认。
- 架构、接口和重大排查由主线程先解决。子 agent 不重新设计已确定的方案，也不替缺失的业务决策作决定。
- 缺少信息、需要任务卡未授权的新依赖或扩大范围时，停止受影响步骤并向主线程说明；相同失败尝试两次仍未解决，也返回主线程。
- 子 agent 交付修改文件、实际检查命令及结果、证据、未完成项和阻塞。主线程独立检查实际差异和重要验收证据。
- 用户调整时，暂停受影响执行、保留已有改动，讨论确定后提高任务卡修订号并重新下发。
- 主线程在开始、阻塞、进入验收和完成提交时报告；持续工作期间约每 60 秒提供简短更新。提问等待用户回答，不设置自动超时。

## 技能使用

三个项目技能位于 [`.agents/skills/`](../../../.agents/skills/)，按角色使用。Vue 测试任务补充 [vue-testing-best-practices](../../../.agents/skills/vue-testing-best-practices/SKILL.md)，读取与当前问题有关的参考；真实浏览器任务使用当前环境已有的 `playwright` 技能。

主线程在任务卡中明确必用技能，提供文件路径或可发现的技能名称。子 agent 先读取对应 `SKILL.md`，仅在当前任务需要时读取技术参考。技能的通用建议服从用户决定、项目规范及任务范围；参考示例不授权新增依赖、改变架构或扩大修改范围。

外部技能固定版本及许可证记录见[技能来源](skill-sources.md)。版本更新作为独立工作项，由主线程先检查差异。技能可发现不等于浏览器、测试库或其他工具可用；实际不可用时明确报告。不能把 `flushPromises` 当作推进 fake timers 的替代。

项目配置由支持自定义角色的 Codex 会话加载。当前会话的工具列表若尚未出现自定义角色，先重新加载角色；在需要继续执行时，可使用普通 `worker`，显式指定 `gpt-6-astra`、`max` 和本角色指令。创建时采用自包含任务卡；支持 `fork_turns` 的接口设置为 `none`，避免全量继承覆盖指定模型与强度。模型不可用时报告主线程，不自动替换模型。

## 验收与 Git 交付

仅修改团队配置、技能和文档时，检查配置加载、技能格式与发现、文档链接和 `git diff --check`。前端任务按影响执行工程检查及浏览器验收；后端任务先检查实际 Go 工程，由主线程把合适的命令写入任务卡。

子 agent 不暂存、提交、推送、切分支、建立 worktree，也不执行 `git reset` 或 `git clean`。主线程等待执行停止、验收通过后，只暂存当前工作项文件，自动创建 Conventional Commit；没有实际改动则不创建空提交。推送、发布及部署须有用户明确指令。

交付报告包含完成行为、实际验证和限制、本地提交记录以及推送状态。台账中与自身提交同批写入的记录，用文件历史定位提交，避免为补写自身提交哈希再生成一个提交。

## 初始化行为演练

逐个角色进行只读演练，确认以下行为；确认前一位已完成并停止执行后，再开始下一位。

1. 前端在组件接口未明确、授权文件不包含相关类型或样式时，返回主线程确认，保留公共组件与 Debug 边界。
2. 后端发现没有 Go module，且任务卡未授权工程初始化时，报告缺少工程基线，不自行初始化或选框架。
3. 验收任务区分实际通过、失败与未执行；不把历史验证、配置可发现或子 agent 自述当作本次运行通过。

技能格式检查只验证文件结构；行为演练与后续真实任务用来观察越界、漏验和返修原因，再按实际问题精修技能。

本次运行证据、演练问题及验证边界见[初始化验证记录](verification.md)。
