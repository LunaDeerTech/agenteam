# 主线程统筹的开发团队

用户与主线程讨论产品目标、可见行为和取舍；主线程将意图转成工程规格、任务与验收条件，并负责技术决定、调度、返修、整合和交付。业务实现和成组文档修改委派子 agent，主线程可完成必要的小范围集成与修正。

直接在 `main` 上每次推进一个活动工作项，正式开发保持一个活动模块。模块顺序、契约和完整验收门槛见[开发计划](../development-plan.md)；当前模块的任务完成并不代表模块已完成，完整验收后才进入下一模块。

## 从产品想法到交付

1. **明确当前产品目标。** 主线程先核对已确认规则，只将影响当前范围的未决产品行为、实质性范围变更或必须授权的行动交回用户。相关问题合并，附建议及用户能理解的影响，不重复打开已定决定；字段名、拆包、测试命令和子任务管理由主线程处理。
2. **形成共享规格与任务。** 主线程决定工程方案；需要时由设计或调研角色提供建议，主线程采纳后由该文件负责人写入正式规格。使用[任务模板](task-template.md)引用产品规则、接口和验收场景，按完整结果拆分任务并确定依赖、文件及共享资源所有权。用户授权范围内连续推进，不增加逐角色、逐阶段的用户批准。
3. **按需执行与自测。** 主线程按依赖和风险选择角色、实例和并行度。执行者完成实现、有意义的自测及局部文档同步，在授权范围内自行修正工具使用和排查问题。
4. **验证并整合结果。** 执行者冻结交付范围并报告证据，主线程按风险安排独立验证、处理返修，核对实际差异、关键边界和集成结果。稳定输入已有的通过证据可以复用。
5. **完成本地交付。** 相关写入全部停止且验收通过后，主线程更新台账、仅提交当前工作项，并报告结果、验证、限制和下一步。推送需要用户明确指令。

主线程在开始、阻塞、进入验收和完成提交时汇报；持续工作期间约每 60 秒给出简短进展。子 agent 只向主线程报告，主线程消化内部调度和工程阻塞。必须由用户决定的问题保持待定，沉默不视为选择。

## 角色与技能

六个角色是按需使用的能力，不是六个必经阶段；角色数量不等于活动实例数量。

| 角色 | 适用职责 | 项目技能 |
| --- | --- | --- |
| [architecture_worker](../../../.codex/agents/architecture-worker.toml) | 影响分析、工程规格与契约、验收方案；不补造产品规则 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [research_worker](../../../.codex/agents/research-worker.toml) | 默认只读，围绕明确技术未知项有界查证，给出证据、限制与建议 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [backend_worker](../../../.codex/agents/backend-worker.toml) | Go、Central、Runner、数据库的完整结果实现、自测与局部文档 | [agenteam-go-development](../../../.agents/skills/agenteam-go-development/SKILL.md) |
| [frontend_worker](../../../.codex/agents/frontend-worker.toml) | Vue 页面、组件与样式的完整结果实现、自测与局部文档 | [agenteam-vue-development](../../../.agents/skills/agenteam-vue-development/SKILL.md) |
| [documentation_worker](../../../.codex/agents/documentation-worker.toml) | 成组或跨文档归位已确认决定，检查引用与一致性 | [agenteam-documentation](../../../.agents/skills/agenteam-documentation/SKILL.md) |
| [verification_worker](../../../.codex/agents/verification-worker.toml) | 独立审查与验证；任务卡授权时补充指定测试 | [agenteam-verification](../../../.agents/skills/agenteam-verification/SKILL.md) |

调研结论须经主线程采纳才能成为正式契约；文档角色不成为每次改动的交接环节。简单任务由一个执行者完成，实施中的范围内返修可复用有效实例；职责、独立性或上下文需要变化时再换实例，不为每张小卡强制冷启动。

主线程在卡片中列出必读技能和规格的相关段落。执行者首次读取仓库规则、当前卡与对应 `SKILL.md`，再按需读取源码和技术参考；同一任务后续只补读变化，不全量继承聊天或反复遍历产品架构。技能建议服从用户决定、仓库规范及任务范围，不授权新增依赖或扩大修改范围。

Vue 测试任务补充 [vue-testing-best-practices](../../../.agents/skills/vue-testing-best-practices/SKILL.md) 的相关参考；真实浏览器任务使用环境可用的 `playwright` 技能。外部技能版本及许可证见[技能来源](skill-sources.md)，升级另立工作项并先审查差异。技能可发现不代表浏览器、测试库或工具可用，实际限制须报告。

## 依赖、所有权与并行

常态最多两个活动子任务，简单任务一个；只有共同契约稳定、前置依赖完成、文件及共享运行资源均可隔离时，主线程才可增加到三个。三个是硬上限，由主线程计数和调度保证，配置仅作辅助；不为占满名额拆卡，也不同时实现后续模块。

主线程在当前规格中维护一张任务表：任务、依赖及完成证据、角色、写入范围、共享资源和状态。并行下发前逐项确认：

- 同一文件同一时间只有一个写入者；卡片、台账和调度记录由主线程维护。已登记的其他任务改动属于共同工作区正常输入，不覆盖或回退。
- 公共接口、依赖锁、全局迁移编号、生成目录、端口和测试库指定所有者或顺序。目录不同不代表独立，共享资源冲突时串行处理。
- 只读审查针对已经停止写入的范围；无关任务可继续，最终集成和提交前停止全部相关写入与后台命令。
- 用户调整、规格或所有权变化时，先暂停受影响写入并保留改动，主线程提高规格/任务卡修订后重新下发；无依赖任务可以继续。

执行者可以自主选择卡片未约束的实现细节并排查局部问题。缺少产品决定或公共接口、需要未授权依赖或扩大范围、发生所有权冲突，或反复失败且没有新证据时，只暂停受影响部分并向主线程报告事实、已尝试方法和建议。主线程负责工程阻塞，不默认把它转为用户问题。

## 按风险验收与证据复用

| 任务风险 | 执行与验收方式 |
| --- | --- |
| 简单、低影响的文档、配置或局部调整 | 一个执行者自查，加主线程审查；不为走流程新增演练或无关产品测试 |
| 普通业务变更 | 实现者自测，由未参与该实现的实例独立审查；主线程核对边界、集成与证据 |
| 权限、数据、事务、协议、恢复等高风险变更 | 先明确关键正常、异常、竞争和恢复场景，必须独立验证相关场景，再由主线程整合验收 |

作者对自己的结果与自测负责，独立验证不替代自测。主线程对完整模块门槛负责；风险分层只决定如何组织检查，不缩减已规定的实现、异常处理、真实依赖和集成验收范围。

每项检查记录实际命令、执行目录与环境、输入版本、结果和限制。输入使用基线提交加相关文件指纹，或明确冻结的修订标识，并列出影响结论的依赖；仅写“通过”或引用旧聊天不构成证据。审查范围停止写入后才能形成有效结论，相关文件或依赖改变后重跑受影响检查；未变的输入及依赖可复用已通过结果，主线程不机械重复全套检查。

纯文档检查内容一致性、Markdown 结构、相对链接/fragment 和 `git diff --check`；配置或技能变更增加对应解析、格式及可用的加载/发现检查。前端按影响检查工程与浏览器行为；后端先核对实际工程，再确定测试命令。没有运行的检查明确标为未执行，不声称产品行为已通过。

交付保持简短，包含完成结果和实际文件范围、检查及可复用输入证据、未验证内容或阻塞，以及是否已停止写入。发现问题由主线程交回拥有该范围的执行者修复，验证者不越权修改产品实现。

## 运行时配置与实例

[项目配置](../../../.codex/config.toml)及[六个角色文件](../../../.codex/agents/)统一使用 `gpt-6-astra / max`，配置并发上限为 3。角色身份按 TOML 的 `name` 字段识别，检查时枚举实际文件，不从角色名猜测文件名。所有实例继承主线程权限和 sandbox，子 agent 不再委派，不自动换模型，不修改全局 trust。

创建实例时使用自包含任务卡，显式指定 `gpt-6-astra`、`max`；支持 `fork_turns` 的接口设为 `none`。当前工具未提供自定义角色时，主线程可使用普通执行实例并附上角色指令和必读技能；模型不可用则报告阻塞，不降低模型或思考强度。

TOML 可解析、技能可发现、显式实例创建成功与 CLI 自动加载生效是不同证据。运行时版本、trust 或工具能力可能限制项目配置加载，未实测就保留限制，不能仅凭文件内容宣布生效。运行时线程名额可能与活动任务数不同；只使用实际提供的停止或关闭接口，无法创建新实例时报告主线程处理，不放宽上限。

历史初始化证据见[初始化验证记录](verification.md)，不作为当前配置或本次行为的通过证明；无需每次修改都逐角色重复演练。

## 交接与 Git 交付

新会话读取 [AGENTS.md](../../../AGENTS.md)、[开发计划](../development-plan.md)、[任务台账](tasks.md)及当前规格/任务卡，核对分支、提交、实际差异和前置验收证据，从首个未完成项恢复。里程碑和中途交接同步持久台账，记录工作项与计划编号、阶段、规格路径/修订、完成及未完成内容、实际检查及输入证据、限制、阻塞、未绑定端口、提交定位、未提交文件和下一步。中途切换先确认子 agent 与命令停止写入，保留已有改动和历史记录原事实。

子 agent 不执行 `git add`、`git commit`、`git push`、`git reset`、`git clean`，不切换分支或创建、切换 worktree。主线程在相关写入停止且验收通过后，仅暂存当前工作项文件，自动创建本地 Conventional Commit；没有实际改动不创建空提交。推送、发布和部署须有用户明确指令。

最终报告包含完成结果、实际验证与限制、本地提交记录和推送状态。同批台账通过文件历史定位自身提交，避免仅为补写哈希再生成一次提交。
