# 主线程统筹的开发团队

用户与主线程讨论产品目标、可见行为和取舍；主线程专注沟通协调，将意图转成工程规格、任务与验收条件，并负责技术决定、调度、返修、最终整合和交付。业务实现、业务返修和成组文档修改委派对应子 agent；测试计划、证据分析、故障归因和独立验收交给专门验收负责人。主线程核对验收结论与关键证据、协调跨任务整合并执行 Git 交付。

直接在 `main` 上按真实依赖推进工作项；没有未满足依赖的模块和完整结果任务可以并行，不再要求只有一个活动模块。依赖、契约和完整验收门槛见[开发计划](../development-plan.md)；单项任务完成不代表模块完成，所有适用门槛仍须完整通过。

## 从产品想法到交付

1. **明确当前产品目标。** 主线程先核对已确认规则，只将影响当前范围的未决产品行为、实质性范围变更或必须授权的行动交回用户。相关问题合并，附建议及用户能理解的影响，不重复打开已定决定；字段名、拆包、测试命令和子任务管理由主线程处理。
2. **形成共享规格与任务。** 主线程决定工程方案；需要时由设计或调研角色提供建议，主线程采纳后由该文件负责人写入正式规格。使用[任务模板](task-template.md)引用产品规则、接口和验收场景，按完整结果拆分任务并确定依赖、文件及共享资源所有权。用户授权范围内连续推进，不增加逐角色、逐阶段的用户批准。
3. **按需执行与自测。** 主线程按真实依赖、风险、所有权和实际可用席位选择角色、实例和并行度。执行者完成实现、有意义的自测及局部文档同步，在授权范围内自行修正工具使用和排查问题。
4. **验证并整合结果。** 执行者冻结交付范围并报告证据，专门验收负责人按风险开展独立审查，分析测试证据和故障，明确通过、失败、未验证范围及返修建议；主线程处理调度与返修，核对实际差异、关键边界和结论，完成最终整合。稳定输入已有的通过证据可以复用。
5. **完成交付。** 相关写入全部停止且验收通过后，主线程更新台账、仅提交本次已验收完整结果的文件，并报告结果、验证、限制和下一步。推送沿用用户已有明确授权；本轮 D01–D28/E01 已授权独立可验证小块及时提交、同步 `main` 并推送，无需逐卡重问。

主线程在开始、阻塞、进入验收和完成提交时汇报；持续工作期间约每 60 秒给出简短进展。子 agent 只向主线程报告，主线程消化内部调度和工程阻塞。必须由用户决定的问题保持待定，沉默不视为选择。

## 角色与技能

六个角色是按需使用的能力，不是六个必经阶段；角色数量不等于活动实例数量。

| 角色 | 适用职责 | 项目技能 |
| --- | --- | --- |
| [architecture_worker](../../../.codex/agents/architecture-worker.toml) | 影响分析、工程规格与契约、验收方案；不补造产品规则 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [research_worker](../../../.codex/agents/research-worker.toml) | 默认只读，围绕明确技术未知项有界查证，给出证据、限制与建议 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [backend_worker](../../../.codex/agents/backend-worker.toml) | Go、Central、Runner、数据库的完整结果实现、自测与局部文档 | [agenteam-go-development](../../../.agents/skills/agenteam-go-development/SKILL.md) |
| [frontend_worker](../../../.codex/agents/frontend-worker.toml) | Vue 页面、组件与样式的完整结果实现、自测与局部文档 | [agenteam-vue-development](../../../.agents/skills/agenteam-vue-development/SKILL.md) |
| [documentation_worker](../../../.codex/agents/documentation-worker.toml) | 成组或跨文档归位已确认决定，检查引用与一致性 | [agenteam-documentation](../../../.agents/skills/agenteam-documentation/SKILL.md) |
| [verification_worker](../../../.codex/agents/verification-worker.toml) | 专门验收负责人：测试计划、证据分析、故障归因与独立验证；任务卡授权时补充指定测试 | [agenteam-verification](../../../.agents/skills/agenteam-verification/SKILL.md) |

调研结论须经主线程采纳才能成为正式契约；文档角色不成为每次改动的交接环节。简单任务由一个执行者完成，实施中的范围内返修可复用有效实例；职责、独立性或上下文需要变化时再换实例，不为每张小卡强制冷启动。

主线程在卡片中列出必读技能和规格的相关段落。执行者首次读取仓库规则、当前卡与对应 `SKILL.md`，再按需读取源码和技术参考；同一任务后续只补读变化，不全量继承聊天或反复遍历产品架构。技能建议服从用户决定、仓库规范及任务范围，不授权新增依赖或扩大修改范围。

Vue 测试任务补充 [vue-testing-best-practices](../../../.agents/skills/vue-testing-best-practices/SKILL.md) 的相关参考；真实浏览器任务使用环境可用的 `playwright` 技能。外部技能版本及许可证见[技能来源](skill-sources.md)，升级另立工作项并先审查差异。技能可发现不代表浏览器、测试库或工具可用，实际限制须报告。

## 依赖、所有权与并行

按真实依赖和所有权决定并行度，不设置单活动模块、常态两个或最多三个子任务的限制。当前工具共提供 7 个总席位，包含主线程及所有占用运行时名额的子 agent；项目配置同步该上限，实际可用席位更少时以工具为准。简单任务一个执行者，不为占满名额拆卡。

主线程在各规格与台账中维护任务表：任务、直接及传递依赖和验收证据、正式契约修订、角色、写入范围、共享资源和状态。并行下发前逐项确认：

- 所需前置能力已经实现并有适用验收证据，共同正式契约稳定。只消费上游已验收子能力的完整结果任务可先行，但必须写明精确依赖、未完成能力和后续绑定责任；不能把上游未完成模块或接口声明当成已实现依赖。
- 同一文件同一时间只有一个写入者；卡片、台账和调度记录由主线程统筹，可明确委派单一文件负责人。已登记的其他任务改动属于共同工作区正常输入，不覆盖或回退。
- 公共接口、依赖锁、全局迁移编号及应用顺序、生成目录、端口、测试库、Docker fixture 指定唯一所有者或使用顺序。目录不同不代表独立，共享资源冲突时只串行受影响部分；测试环境确已隔离且容量足够才允许并发运行。
- 只读审查针对已经停止写入的范围或带精确输入清单的冻结副本；无关任务可继续，最终集成和提交前停止全部相关写入与后台命令。固定副本上的结论必须与待整合文件及依赖重新匹配。
- 用户调整、规格或所有权变化时，先暂停受影响写入并保留改动，主线程提高规格/任务卡修订后重新下发；无依赖任务可以继续。

执行者可以自主选择卡片未约束的实现细节并排查局部问题。缺少产品决定或公共接口、需要未授权依赖或扩大范围、发生所有权冲突，或反复失败且没有新证据时，只暂停受影响部分并向主线程报告事实、已尝试方法和建议。主线程负责工程阻塞，不默认把它转为用户问题。

## 按风险验收与证据复用

| 任务风险 | 执行与验收方式 |
| --- | --- |
| 简单、低影响的文档、配置或局部调整 | 一个执行者自查，加主线程审查；不为走流程新增演练或无关产品测试 |
| 普通业务变更 | 实现者自测，由未参与该实现的实例独立审查；主线程核对边界、集成与证据 |
| 权限、数据、事务、协议、恢复等高风险变更 | 先明确关键正常、异常、竞争和恢复场景，必须独立验证相关场景，再由主线程整合验收 |

作者对自己的结果与自测负责，独立验证不替代自测。专门验收负责人必须是未参与相应实现的 `gpt-6-astra / max` 实例，负责测试方案、证据分析、故障定位及验收建议；如需多名验证者，由主线程分派，验收负责人不再委派。主线程专注协调与最终整合，并对完整模块门槛负责；风险分层和并行调度都不缩减已规定的实现、异常处理、真实依赖和集成验收范围。

验证交付默认包含固定输入标识、实际命令及原始日志、结论与限制、精确提交路径；命令保留必要执行目录与环境。输入使用基线提交加相关文件指纹，或明确冻结的修订标识，按风险核对影响结论的必要依赖；仅写“通过”或引用旧聊天不构成证据。审查范围停止写入后才能形成有效结论；语义及依赖未变时复用既有证据，缺陷修复后只重跑受影响检查，主线程不机械重复全套检查。

不得机械复制全树或重复生成大型索引；固定输入及执行条件已具备时，不因报告排版延迟验证。保留原始失败日志及对应输入，相关命令和自有资源必须核实实际停止/清零，不能以 all-stop 声明代替。轻量证据不降低上表的独立验收、安全与完整模块门槛。

纯文档检查内容一致性、Markdown 结构、相对链接/fragment 和 `git diff --check`；配置或技能变更增加对应解析、格式及可用的加载/发现检查。前端按影响检查工程与浏览器行为；后端先核对实际工程，再确定测试命令。没有运行的检查明确标为未执行，不声称产品行为已通过。

交付保持简短，包含完成结果和实际文件范围、检查及可复用输入证据、未验证内容或阻塞，以及是否已停止写入。发现问题由主线程交回拥有该范围的执行者修复，验证者不越权修改产品实现。

## 运行时配置与实例

[项目配置](../../../.codex/config.toml)及[六个角色文件](../../../.codex/agents/)统一使用 `gpt-6-astra / max`，配置并发上限为 7；调度按当前工具的 7 个总席位计算，包含主线程，不视为 7 个子 agent 名额。角色身份按 TOML 的 `name` 字段识别，检查时枚举实际文件，不从角色名猜测文件名。所有实例继承主线程权限和 sandbox，子 agent 不再委派，不自动换模型，不修改全局 trust。

创建实例时使用自包含任务卡，显式指定 `gpt-6-astra`、`max`；支持 `fork_turns` 的接口设为 `none`。当前工具未提供自定义角色时，主线程可使用普通执行实例并附上角色指令和必读技能；模型不可用则报告阻塞，不降低模型或思考强度。

TOML 可解析、技能可发现、显式实例创建成功与 CLI 自动加载生效是不同证据。运行时版本、trust 或工具能力可能限制项目配置加载，未实测就保留限制，不能仅凭文件内容宣布生效。运行时线程名额可能与活动任务数不同；主线程核对工具实际占用，只使用实际提供的停止或关闭接口，无法创建新实例时复用合适实例或安排顺序，不将任务结束声明等同于名额已释放。

续派已 all-stop 或完成的实例须调用 `followup_task`，并等到确认接收与实际启动后再将任务记为进行中；`send_message` 只传递消息，不能代替启动。闲置实例在确认无活动写入、命令和自有资源后可通过当前可用的停止/关闭接口处理，是否释放席位以工具实际占用为准。

历史初始化证据见[初始化验证记录](verification.md)，不作为当前配置或本次行为的通过证明；无需每次修改都逐角色重复演练。

## 交接与 Git 交付

新会话读取 [AGENTS.md](../../../AGENTS.md)、[开发计划](../development-plan.md)、[任务台账](tasks.md)及当前规格/任务卡，核对分支、提交、实际差异和前置验收证据，从首个未完成项恢复。里程碑和中途交接同步持久台账，记录工作项与计划编号、阶段、规格路径/修订、完成及未完成内容、实际检查及输入证据、限制、阻塞、未绑定端口、提交定位、未提交文件和下一步。中途切换先确认子 agent 与命令停止写入，保留已有改动和历史记录原事实。

子 agent 不执行 `git add`、`git commit`、`git push`、`git reset`、`git clean`，不切换分支或创建、切换 worktree。主线程在相关写入停止且验收通过后，仅暂存本次已验收完整结果的文件，自动创建本地 Conventional Commit；没有实际改动不创建空提交。推送、发布和部署须有用户明确授权；本轮持续开发和 `main` 推送沿用[开发计划](../development-plan.md#当前基线与计划范围)记录的已有授权，不重复确认，也不因此扩展发布或部署范围。

最终报告包含完成结果、实际验证与限制、本地提交记录和推送状态。同批台账通过文件历史定位自身提交，避免仅为补写哈希再生成一次提交。
