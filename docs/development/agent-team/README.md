# 主线程统筹的开发团队

本页维护现行团队流程。当前产品状态、停止边界和下一步只在[任务台账](tasks.md)与[开发计划](../development-plan.md)维护；历史验收报告保留当时事实，不以其中的旧派工、哈希或归档步骤驱动新任务。

用户与主线程讨论产品目标、可见行为和取舍。主线程负责目标、跨任务边界、一级负责人调度、最终整合与 Git 交付；一级负责人自主将完整子目标拆给二级执行者，组织局部返修、集成和验证。二级及更深执行者按收益继续拆分，逐级向直接负责人汇报，主线程不逐文件重做负责人已完成的审查。

在当前任务确认的分支上按真实依赖推进工作项，不自行切换分支；没有未满足依赖的模块和完整结果任务可以并行。依赖、契约和完整验收门槛见开发计划；单项任务完成不代表模块完成，所有适用门槛仍须完整通过。

## 从产品想法到交付

1. **明确当前产品目标。** 主线程核对已确认规则，只将影响当前范围的未决产品行为、实质性范围变更或必须授权的行动交回用户。相关问题合并并附建议，不重复打开已定决定；工程细节由相应负责人处理。
2. **交付完整子目标。** 主线程确定共同契约和跨任务所有权，将工程目标、范围与验收条件交给一级负责人。负责人使用[任务模板](task-template.md)引用正式规则，自主拆分子任务、确定文件与共享资源所有权，并选择实现与验证角色。授权范围内连续推进，不增加逐角色、逐阶段的用户批准。
3. **执行、自测与文档同步。** 执行者完成实现、有意义的自测和必要文档，范围内自行选择局部细节、修正工具使用和排查问题。代码、测试及必要文档作为同一原子变更准备，避免把 README 或任务结论留作实现交付后的单独末件。
4. **逐级验证与整合。** 执行者停止交付范围写入并报告结果，负责人按风险组织独立审查、处理返修并集成子目标。稳定输入已有的通过证据可以复用；负责人向上交付通过、失败、未验证范围和关键证据，主线程核对整体边界与集成结论。
5. **一次交付原子变更。** 相关写入停止且验收通过后，主线程将代码、测试、必要文档和确有必要的归档一起提交。推送沿用当前任务已有明确授权，不逐卡重问，也不将历史其他任务的授权扩展到新任务。

主线程在开始、阻塞、进入验收和完成提交时汇报；持续工作期间约每 60 秒给出简短进展。子 agent 逐级报告，直接负责人消化范围内工程阻塞；只有跨子目标冲突、超出授权或需要产品决定的问题上报主线程。必须由用户决定的问题保持待定，沉默不视为选择。

## 角色与技能

六个角色是按需使用的能力，不是六个必经阶段；同一角色可承担一级负责人或下级执行者，角色数量不等于活动实例数量。

| 角色 | 适用职责 | 项目技能 |
| --- | --- | --- |
| [architecture_worker](../../../.codex/agents/architecture-worker.toml) | 影响分析、工程规格与契约、验收方案；不补造产品规则 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [research_worker](../../../.codex/agents/research-worker.toml) | 默认只读，围绕明确技术未知项有界查证，给出证据、限制与建议 | [agenteam-design](../../../.agents/skills/agenteam-design/SKILL.md) |
| [backend_worker](../../../.codex/agents/backend-worker.toml) | Go、Central、Runner、数据库的完整结果实现、自测与必要文档 | [agenteam-go-development](../../../.agents/skills/agenteam-go-development/SKILL.md) |
| [frontend_worker](../../../.codex/agents/frontend-worker.toml) | Vue 页面、组件与样式的完整结果实现、自测与必要文档 | [agenteam-vue-development](../../../.agents/skills/agenteam-vue-development/SKILL.md) |
| [documentation_worker](../../../.codex/agents/documentation-worker.toml) | 成组或跨文档归位已确认决定，检查引用与一致性 | [agenteam-documentation](../../../.agents/skills/agenteam-documentation/SKILL.md) |
| [verification_worker](../../../.codex/agents/verification-worker.toml) | 测试计划、证据分析、故障归因与独立验证；任务卡授权时补充指定测试 | [agenteam-verification](../../../.agents/skills/agenteam-verification/SKILL.md) |

调研结论由相应负责人采纳后写入正式契约，跨子目标契约由主线程协调。文档角色不成为每次改动的交接环节。简单任务由一个执行者完成，范围内返修可复用有效实例；职责、独立性或上下文需要变化时再换实例，不为每张小卡强制冷启动。

直接负责人在卡片中列出必读技能和规格的相关段落。执行者首次读取仓库规则、当前卡与对应 `SKILL.md`，再按需读取源码和技术参考；同一任务后续只补读变化，不全量继承聊天或反复遍历产品架构。技能建议服从用户决定、仓库规范及任务范围，不授权新增依赖或扩大修改范围。

Vue 测试任务补充 [vue-testing-best-practices](../../../.agents/skills/vue-testing-best-practices/SKILL.md) 的相关参考；真实浏览器任务使用环境可用的 `playwright` 技能。外部技能版本及许可证见[技能来源](skill-sources.md)，升级另立工作项并先审查差异。技能可发现不代表浏览器、测试库或工具可用，实际限制须报告。

## 依赖、所有权与并行

按真实依赖、风险和拆分收益决定层级及并行度，不设置单活动模块或固定子任务数量。当前工具共提供 7 个总席位，包含主线程和所有层级占用运行时名额的子 agent；配置上限不增加工具实际席位。各负责人共享名额，派工前核对可用席位并为执行与必要独立验证预留位置，避免所有名额都被等待下级的负责人占满。无空位时复用合适实例或顺序执行；简单任务不为占满名额拆卡。

主线程维护跨子目标依赖与所有权，一级负责人维护其内部任务和下级分工，不重复建立全树任务索引。并行下发前确认：

- 所需前置能力已经实现并有适用验收证据，共同正式契约稳定。只消费上游已验收子能力的任务可先行，但须明确必要依赖、未完成能力与后续绑定责任，不能把接口声明视为已实现依赖。
- 同一文件同一时间只有一个写入者。负责人可移交文件所有权，父级和其他执行者随后保持只读；台账、卡片和规格也遵循此规则。已登记的其他任务改动属于共同工作区正常输入，不覆盖或回退。
- 公共接口、依赖锁、全局迁移编号及应用顺序、生成目录、端口、测试库和 Docker fixture 指定唯一所有者或使用顺序。目录不同不代表独立；仅在环境隔离且容量足够时并发运行，冲突时串行受影响部分。
- 只读审查针对停止写入的范围或可定位的冻结修订。默认记录 Git 基线与限定路径的实际 diff，新增文件列入范围；冻结副本结论在整合时核对相关差异。最终集成和提交前停止全部相关写入与后台命令，无关任务可继续。
- 需求、契约或所有权变化时，由相应负责人暂停受影响写入、保留改动并修订任务；跨子目标变更交主线程协调，无依赖任务可继续。

执行者遇到缺少产品决定或公共接口、需要未授权依赖或扩大范围、所有权冲突，或反复失败且没有新证据时，只暂停受影响部分，向直接负责人报告事实、已尝试方法和建议。负责人先处理范围内问题，确需跨子目标协调时再逐级上报。

## 按风险验收与证据复用

| 任务风险 | 执行与验收方式 |
| --- | --- |
| 简单、低影响的文档、配置或局部调整 | 一个执行者自查，加直接负责人审查；不新增无关产品测试或固定审批链 |
| 普通业务变更 | 实现者自测，由未参与该实现的实例独立审查；负责人核对边界、集成与证据 |
| 权限、数据、事务、协议、恢复等高风险变更 | 明确关键正常、异常、竞争和恢复场景，必须由未参与实现的实例独立验证相关场景，再由负责人集成 |

作者对结果和自测负责，独立验证不替代自测。验收负责人使用 `gpt-6-astra / ultra`，可按需要继续分派验证任务；独立验收的实际执行者及形成验收结论的负责人均不得参与所验实现。一级负责人组织子目标验证，主线程核对完整模块门槛、跨任务风险与关键结论，不逐文件重复哈希或全文审查。层级调度不缩减既定实现、异常处理、真实依赖和集成验收范围。

验证默认以 **Git 基线提交、限定路径的 diff 和停止写入状态** 标识输入；已有冻结修订也可直接引用。记录实际命令、必要目录/环境、结果与限制，按变更风险核对影响结论的必要依赖。语义与相关依赖未变时复用已有证据，修复后只重跑受影响检查。仅写“通过”或引用旧聊天不构成证据。

不默认计算文件指纹、`sha256`、全树依赖闭包或 manifest，也不重复生成索引。仅发布产物完整性、外部文件身份或具体故障定位确实需要时，对明确范围计算一次哈希，说明用途并复用；后续只有对应输入变化才更新，不能把每轮重复哈希作为验收门槛。产品已有完整性检查与依赖锁文件仍按真实用途维护。

原始命令日志、截图和故障原件默认临时保存在忽略的 `output/ai/`，不自动入库。任务记录只保留可复现的命令、结论、必要失败事实、限制和下一步；不默认新增永久 verification/archive 包、重复报告或逐轮流水。确需长期保留的必要证据应精简、脱敏并随同一原子变更交付。既有历史报告保留，不要求新任务复刻其取证流程。相关命令和自有资源仍须核实实际停止/清零，不能以 STOP 声明代替。

纯文档检查内容一致性、Markdown 结构、相对链接/fragment 和 `git diff --check`；配置或技能变更增加对应解析、格式及可用的加载/发现检查。前端按影响检查工程与浏览器行为；后端先核对实际工程，再确定测试命令。没有运行的检查明确标为未执行，不声称产品行为已通过。

交付保持简短：完成结果与实际文件范围、检查及可复用输入、未验证内容或阻塞，以及是否停止写入和后台命令。缺陷交直接负责人安排原文件所有者修复，验证者不越权修改产品实现。

## 运行时配置与实例

[项目配置](../../../.codex/config.toml)与[六个角色文件](../../../.codex/agents/)统一要求各层实例使用 `gpt-6-astra`、`model_reasoning_effort = "ultra"`，Fast Mode 对应 `service_tier = "priority"`。角色身份按 TOML 的 `name` 字段识别，检查时枚举实际文件。所有层级继承权限和 sandbox，均可在授权范围内按需要继续委派，不自动换模型，不修改全局 trust。

项目配置的并发上限为 20，实际派工仍受工具全树共享席位限制。`agents.max_depth = 6` 是可调整的递归深度上限，不要求任务拆满六层；该字段只对当前 V1 多代理运行时有效，V2 会忽略它，切换运行时须重新核实支持情况。

创建实例时使用自包含任务卡，显式指定 `gpt-6-astra`、`ultra`；支持 `fork_turns` 的接口设为 `none`。工具未提供自定义角色时，可用普通实例附上角色指令和必读技能；模型不可用则报告阻塞，不降低模型或思考强度。

Fast Mode 的配置目标、CLI 支持与实例实际服务档位须分别核实。`spawn_agent` 接口没有 Fast/service tier 参数时，只能显式指定其支持的模型与思考强度；不能据此声称当前所有实例已启用 Fast。项目配置是否加载还受运行时版本、trust 及会话覆盖影响；配置变更不自动切换当前会话，未实测的加载或继承行为须保留限制。

本机 CLI 0.159.0-alpha.3 的模型目录将 `priority` 标为 Fast、列出 `gpt-6-astra` 支持 `ultra`，`fast_mode` 功能为开启；字段解析已验证角色 `service_tier` 和 V1 `agents.max_depth`。当前项目因未受信任而未自动加载，本次不修改全局 trust。以上检查证明 CLI 支持和配置格式，不证明当前实例的实际服务档位。

需要从仓库根显式启动新 CLI 会话时，可用以下覆盖参数，无需修改全局 trust。同参数的严格配置解析已检查，以下交互启动未执行；自定义角色仍需显式指定 `agents.<name>.config_file` 或由受信任项目加载。

```sh
codex --strict-config -C . \
  -c 'model="gpt-6-astra"' \
  -c 'model_reasoning_effort="ultra"' \
  -c 'service_tier="priority"' \
  -c 'agents.enabled=true' \
  -c 'agents.max_concurrent_threads_per_session=20' \
  -c 'agents.max_depth=6' \
  -c 'agents.default_subagent_model="gpt-6-astra"' \
  -c 'agents.default_subagent_reasoning_effort="ultra"'
```

TOML 可解析、技能可发现、显式实例创建成功与 CLI 自动加载生效是不同证据，不要求每次修改逐角色重复演练。运行时线程名额可能与活动任务数不同；只使用实际提供的停止或关闭接口，并核实名额是否释放，不能将任务完成声明当作名额释放。

续派已 STOP 或完成的实例须调用 `followup_task`，并确认接收与实际启动后再记为进行中；`send_message` 只传递消息，不能代替启动。历史初始化证据见[初始化验证记录](verification.md)，不作为当前配置或本次行为的通过证明。

## 交接与 Git 交付

新会话先读 [AGENTS.md](../../../AGENTS.md)，核对分支、提交与实际差异，再按需读取[开发计划](../development-plan.md)、[任务台账](tasks.md)的当前摘要和目标工作项规格，核对必要前置证据后从首个未完成项恢复；不默认遍历整份计划、台账或历史报告。里程碑或中途交接时，文件负责人在现有任务记录中简写阶段、当前规格、已完成/未完成内容、检查结论与限制、阻塞、未绑定端口、未提交范围和下一步，不另建轮次报告。中途切换先确认相关子 agent 与命令停止写入，保留已有改动和历史事实。

各层子 agent 均不执行 `git add`、`git commit`、`git push`、`git reset`、`git clean`，不切换分支或创建、切换 worktree。主线程在相关写入停止且验收通过后，只暂存本次完整原子变更，以一次 Conventional Commit 包含代码、测试及必要 docs/docs archive；不得为了补哈希、归档、重复报告或回填本提交编号再开 docs 提交。真实新增且独立可验证的结果可另行提交，没有改动不创建空提交。

推送、发布和部署分别沿用当前任务已有明确授权，不重复确认，也不扩展到其他行动；历史授权保留在开发计划中，不自动适用于新任务。最终报告给出完成结果、实际验证与限制、本地提交和推送状态；同批文档通过 Git 文件历史定位自身提交。
