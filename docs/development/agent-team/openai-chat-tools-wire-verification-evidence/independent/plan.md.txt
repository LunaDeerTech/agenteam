## 最小独立真实增量（冻结实现后确定 selector）

A. 合法 ordinary envelope 内的参数/选择闭合。构造有效工具定义、snapshot、身份与单次真实 POST；响应提供可靠 usage，再分别送 C0 拒绝的 `1e400` 参数或本次 ToolChoice 不允许的工具。断言预期安全错误、零 Result.ToolCalls/Text、Observe 的0/大整数/NULL语义、单次发送、无 canary 泄露、actual join 后材料销毁。用既有正式 Account/Audit/PolicyService/D04 fixture，不签发工具执行 grant。

B. 工具完成不等于流成功。先让完整工具片段与 ToolComplete 从 Next 实际返回，再交可靠 usage，并在 DONE 前设置服务器 hold/断流分支：取消或缺 DONE 必须错误一次后 EOF、零 StreamEnd、真实 Dispatched/PartialOutput、usage保留。另按作者覆盖情况补两工具中第二工具无效：第一工具合法且其片段已交付，finish 时仍必须零 ToolComplete，证明全工具完成门槛。不能只等待 buffer/队列状态代替实际交付。

共享 Budget 未 join 保槽及真实 writer 尾部已有强旧证据；本轮先核生产关闭链有无改动及作者三修订覆盖，再决定是否需要独立重补该窗口。不要为机械重复扩大 selector 或资源成本。若新 clone/扫描实现仍存在关键证据缺口，再补最小纯测试；不以接口形状镜像测试替代内存/取消行为证据。

## 结果口径

真实320 KiB只证明原512 KiB场景可覆盖超过队列的参数；1 MiB/16 MiB极限只计纯 parser/transport实测，精确1 MiB参数应分多个native event以保外层1 MiB event预算。ToolComplete与成功wire终局均没有 Tool执行或持久DB终态授权；Resolver仍拒绝tools，Runtime/consumer/Secret grant/ledger/Provider/root保持各自任务。

最终结论分列通过、失败、未验证与复用证据；绑定最终14源/新manifest/独立overlay和编译闭包、原失败及修复差量、真实资源双清。不把SDK/规格静审、空编译或旧阶段局部绿写成当前产品通过。当前计划冻结后等待作者固定核心，不改源码、不启动工具链或资源。
