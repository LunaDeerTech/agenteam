## 2. 唯一 HTTP 契约

| 方法及路径 | 输入与 200 输出 |
| --- | --- |
| `GET /api/v1/system/model-selection/meeting-summary` | 无 query/body；当前 System Read，调用原 `GetMeetingSummarySelection`；输出恰 `{id,version,model}` |
| `HEAD` 同路径 | 与 GET 相同的当前授权、完整读取及错误状态/headers，无响应 body；不提供页面 HEAD 操作 |
| `PUT` 同路径 | body 恰 `{id,expected_version,model}`；当前 System Mutate，唯一合法 `Idempotency-Key` 和当前 CSRF；构造原 `UpdateMeetingSummarySelectionRequest{CommandMeta,SelectionID:id,ExpectedVersion,Model}`；输出原安全 receipt |
| `POST /api/v1/system/model-commands/lookup`（原口） | body 仍恰 `{command:"model.selection.update"}`，带捕获的原 key、当前有效同身份 CSRF；intent=Read 但 unsafe POST 仍检查 CSRF；输出原 `{found,receipt}` |

新 GET 的三个字段全部 required、`additionalProperties:false`：`id` 是 canonical UUIDv7，`version` 是 `[1,9223372036854775807]` 的 canonical 十进制字符串，`model` 必须显式为 null 或 canonical Model UUIDv7。null 仅表示已初始化但从未配置；未初始化返回 `DEPENDENCY_UNBOUND`，坏事实/缺表等沿 S1 `DEPENDENCY_UNAVAILABLE`，不能投影为 null。停用或后来不可用于新生成仍返回已保存 ModelID。HTTP DTO 不加 Provider、Project、reasoning、内部 plan 或材料。

PUT 三字段全部 required，`model` 不能 null/空/遗漏；expected_version 是有合法后继的正 int64 字符串。输入 id 是 Summary singleton，不能用四用途 ID 或由浏览器生成；scope/actor/user/command/key 不进入 body。只把受信 Account actor、SystemScope 和原 key 放入 CommandMeta。新 GET/HEAD/PUT 均拒绝 query/ForceQuery；GET/HEAD 拒绝 body，包括不合法 framing 和实际非空体。PUT 使用原严格 `DecodeJSON`，本新口上限 **16 KiB**，拒绝未知/重复/大小写别名/尾随 JSON、非 UTF-8、错误 media/encoding、数值版本及非法 null；不改变旧口 1 MiB 服务端上限。

receipt 恰 `{kind,resource_id,version,affected_references}`：kind=`model.selection.update`，resource_id=原 Summary ID，version=原 expected_version+1，affected_references 为字符串 `"0"`。lookup 的 false 必须 receipt:null；true 仍严格核上述捕获的目标/版本。历史 receipt 可以早于独立 GET 的当前版本，不得用当前版本覆盖历史结果。原四项及 Summary 同属 `model.system/[UserID]/model.selection.update/key`；同 key 异义仍为 `IDEMPOTENCY_KEY_REUSED`，不另造命令身份或把 lookup 观察当写权限/同义证明。

`api/openapi/model-system.json` 仅增加此 path 的 GET/HEAD/PUT、闭合 `MeetingSummarySelection`/`MeetingSummarySelectionInput` schema、对应 cookie/CSRF/key/错误和历史 receipt 描述；复用公共 UUID/string-version/Problem 与原 Receipt/CommandLookup。旧 Selection/SelectionInput 字段、七种 command、旧 deletion-impact 闭集均保持。schema 与严格前端应对同一真实安全 body 验证，不能只断言 schema 文件含某字段。

### 2.1 安全、预算与实际完成

沿原 `CheckRequest` 的安全 headers、精确 Host/Origin/Fetch-Metadata、规范 path/RawPath 检查和单层外部 middleware。新口随后在 `RequireSystem` 之前开始 min(parent,now+3s) 的 GET/HEAD 总预算、min(parent,now+30s) 的 PUT 总预算，覆盖前置 Session/admin、解码、S1 服务、序列化和实际 I/O 收尾。服务同 Tx 重核当前 System 权限；HTTP 通过不能替代它。S1 Get 内部 3s 只能取更早期限，不能重开窗口。原 lookup 沿原预算和行为，不据本卡宣称其新增 3s/30s 保证。

`model/http.go` 只对精确新 route 分派专门的有界处理；其它 route 的 dispatch 不改。新处理器使用本包私有 native deadline/收尾接缝，参考已接受 Usage/outbound 实际模式，**不修改它们的 helper 或导出通用框架**：设置读/写 deadline，取消 callback 只推进 deadline；所有 body read/Close、服务、response write、callback 都实际结束后返回。正常成功须先停止或 join callback、清除 deadline，再由外层 cancel，避免成功 keepalive 后续响应被延迟 callback 截断。失败/超时须限制 drain 并实际收尾；不支持 deadline 的 writer 在业务派发前安全失败，不能静默省略或启动脱离 owner 的 body goroutine。受控 writer/native HTTP 分别证明能力，不能仅用 context/select 超时冒充 join。

GET 只有完整 Committed 且 context 仍有效才发布完整 DTO；Unknown/取消/损坏事实零候选。PUT 只调用原服务一次，不在 HTTP 中自动重试或重新 GET 后覆盖 receipt。服务内原 Unknown 确认若成功，200 返回原 receipt；最终仍 Unknown 才沿 503/`retry_hint=lookup`。超时后不新造“未开始/未提交”；传输已失效可按原安全惯例 abort，客户端保留未确认。任何 partial/short write 不追加第二份 Problem。

沿真实 foundation 映射：400 参数，401 未认证/Session 撤销，403 当前管理员/CSRF/Origin 拒绝，404 错 selector/目标或未知路由，405 非 GET/HEAD/PUT（`Allow: GET, HEAD, PUT`），409 版本/异义 key/非法状态，413 体积，415 media，422 已定能力/schema，429 限流，503 依赖/最终 Unknown，500 原 InternalError。保留原 commit_state/cause 分类，不能把 PG 锁错误统一重标 503。Problem 不回显 body/key/CSRF/raw SQL。规范路径外无 redirect、CORS、匿名或 SPA fallback；旧四项 GET/PUT、通用 lookup、管理读、Account/Usage/diagnostics 路由均保留。

## 3. 同页独立表单与安全恢复

### 3.1 可见状态和选择

沿原“平台模型用途”叶子、URL、菜单计数与精确 return 闭集；同页追加“会议 Summary”独立 section/内联 form，原四项保留原整组 Dialog/PUT，不改成五项一次保存。独立显示 Summary 版本、未配置/已保存 ID、完整安全 Model/Provider 名称和停用状态，提供显式编辑、保存、取消、重读。说明用于初始/更新及首轮标题，配置保存不代表生成运行可用；不展示设置 reasoning/tools、连接测试或生成按钮。

候选沿已接受 Provider 分页→该 Provider Model 分页，每页25、按原 cursor/history 规则，仅当前主动候选页；复用完整 Provider/Model 严格解析。合法候选只需 enabled System Provider + enabled System chat 及原合法配置，不要求 Memory 的 json_schema，不能因 S3 尚未支持某 wire 将此配置选择缩窄。无 Model 引导既有管理叶子，空当前页不推断全域不存在；不用任意 UUID 输入、不嵌入创建/编辑 Model，不预取全部候选。

初始 null 允许直接配置 Summary，即使原四项 configured=null 或其分区读取失败；反方向同理。已保存引用停用或详情失败仍保留 ID，明确“当前详情不可用/不可选”；当前 Model→Provider 两 GET 组合沿原 `getSavedModel` 完整校验、同一 signal/owner/30s 预算、零半成品公开，不由 Summary 页面直接 fetch。新保存要求已确认当前 singleton/版本及完整合法目标详情；无变化零 PUT、浏览不选中、不自动保存。仅取消未派发草稿不会写 null；已选后的“不配置/清空”动作不存在。

两区读取、草稿、版本、反馈、历史 receipt、requiresReload 和候选分页互不覆盖。页面进入的两项当前读取有界顺序协调：每区至多一次初始派发，前一实际 owner 结束后再派下一项；一个普通读取失败不跳过另一项，401/当前403则按身份规则共同失效。沿既有有限已保存引用补读，最多四项加 Summary 一项，不扫描候选目录、不重试失败请求、不新建通用队列。owner 忙时可保留一个尚未派发的初始/显式读取意向，页面/身份/代次失效即退休；取消或失败后只能显式重读。取消的局部 loading 退休为可重读状态，不能永久 loading，也不能清掉另一分区已完成观察。

### 3.2 固定 API 与两个私有 intent

扩原 `SystemModelSelectionAPI` 第六依赖，增加具体 `getMeetingSummary(signal)`、`updateMeetingSummary(command,write)`、`lookupMeetingSummaryCommand(command,write)`；前三者仅用 §2 固定路径，lookup 复用原固定 transport。新增独立类型 `MeetingSummaryState{id,version,model:string|null}` 与 `MeetingSummaryCommand{kind:"model.selection.update",id,expected_version,model:string}`，纯捕获/strict parser 可放新文件后由原 API 组合。旧 `SelectionPurpose`/`SelectionCommand`/`SelectionState` 不扩字段或 union 含义。现接口工厂增加方法，不改变 12 项依赖顺序、不创建另一个 API domain。transport 仅将两新 endpoint 加入原 SelectionEndpoint 的受限 GET/PUT 分类；无任意 URL/options。

请求在生成 key/intent 前严格捕获，序列化 body≤16KiB；响应和 Problem 沿 600000B、已有 listProviders 成功200的2097152B例外，取消/超限 read/cancel 尾部实际 join。版本用字符串/BigInt 精确检查，不能 Number 损失 >2^53；拒错字段、null/遗漏、错 ID/receipt kind/版本、溢出。两种 receipt 都须绑定捕获的本区原命令，不能仅因 kind 相同接受另一 singleton 的结果。

在既有 selection 域内部显式分 `platform` 与 `meeting-summary` 两槽：各自的 read/action revisions、固定 identity `{userID,sessionID,epoch}`、singleton ID、expected_version、不可变 body、CSRF、唯一 key、uncertain/checked/keyConflict、receipt/lookup observation 独立。原 `auth.system.selection` 四项方法保持原调用语义，增加固定 `.meetingSummary` facade，不让旧方法默认为“当前选中的槽”。开始/继续某槽操作不得覆盖/abandon/改变另一槽的 key/body/版本。两个未确认 intent 可以共存；没有实际在途 owner 时，另一槽可独立读写，不能以其它槽尚未配置/失败/未确认作为保存门槛。

具体 facade 为 `auth.system.selection.meetingSummary`，具有 `get/getSavedModel/listProviders/getProvider/listModels/abandonRead/abandon/start/checkOriginal/retryOriginal/progress`，参数及返回沿上述独立类型和原分页/WriteOptions。其 action 闭集为 `meeting-summary-state`、`meeting-summary-reference`、`meeting-summary-providers`、`meeting-summary-provider`、`meeting-summary-models`、`meeting-summary-write`、`meeting-summary-lookup`；纳入原 SelectionAction 分类，旧五 read/action 字符串不改。旧 `selection.abandon()` 只清 platform，新增 facade 的 abandon 只清 Summary；身份失效的内部全 selection 清理显式清两槽。不能将一份 `selectionIntent` 按最近页面动作切换，或让原全域 clear 被局部按钮误调用。

唯一 Cookie owner 仍覆盖两槽及所有原域，任一实际 I/O 未 join 时不得启动第二请求，30s 可见超时/abandon 不提前归还。selection action 必须显式携带或编码槽，runAuthorized 的 revision、cancel、CSRF_FAILED、current403、restore 同身份保留、全局清理分支完整纳入，不能落入 Provider/个人默认分支。局部 abandon/read-cancel 仅退休自己槽当前 action；全局失权/注销/新Session/dispose才清两槽。旧与新槽对个人、Provider 两步、Model、邀请等既有域仍双向隔离，旧迟到结果/403不能污染新身份或另一代次。

### 3.3 原命令、当前观察与导航

| 事件 | 必须保留的行为 |
| --- | --- |
| 本地未派发或可确认业务拒绝 | 不冒称 Unknown；本区保留草稿、显示参数/版本/目标状态错误，另一分区不受影响 |
| 断连、超时、非法/截断响应、取消、最终 COMMIT_UNKNOWN | 本区原 intent 不可变、结果未确认；不自动生成新 key/重写 body/改 expected_version/补偿/重试 |
| “检查原请求” | 先正式 Session 重验，同完整 identity/admin/CSRF 才保留原 intent；POST 原 lookup 的 found/missing/failed 只是该命令身份的历史观察，不能确认本次 body，也不能把 missing 当原 writer 已回滚 |
| “重试原请求” | 与原 selection 同规则：成功重验上下文、无 keyConflict 且实际 owner 空闲后，用户显式执行本区原 PUT；原 key/id/version/model 完全相同。即使 lookup 失败，只要上下文已确认仍可显式原重放；不以当前 GET 相同、旧Model已删/停用或版本已推进阻止合法历史重放 |
| 原 Execute 返回严格匹配 receipt | 只确认该次历史保存；随后本区 GET 失败不撤销确认、不重发写，仅提供重读。当前配置可能已被别的管理员/删除替换改变 |
| VERSION_CONFLICT/目标变化 | 保留本区草稿，显式“读取最新并核对”后才能建立新 intent；不能自动合并/升级版本。已有未确认性不被后续拒绝或 lookup missing 抹去 |
| IDEMPOTENCY_KEY_REUSED | 标明原身份异义冲突，禁原重试；用户明确放弃本区跟踪并重新读/核对后才允许新命令，不挪用另一槽 receipt |

当前401/CSRF失效沿唯一 Cookie纪律；当前403清两个系统私有槽并设身份绑定拒绝，正式 Session 重验后恢复。另一 admin 相同裸 key 不能查原 User receipt；服务允许同 User 新合法 Session 查历史，不意味着 UI 可把旧完整identity私有intent跨Session迁移。原请求、key、CSRF 不进 URL/storage/log/公开 reactive state。

App 仍只创建/provide 现有 selection 页面 owner，现有 navigation hook、logout、dispose 入口不新增第二链。`useSystemModelSelection` 在其内部组合独立 Summary controller，旧四项局部编辑/取消/重读只作用四项；Summary 局部操作只作用 Summary。保持旧四项 Dialog，新 Summary 使用同页内联 form，两个未保存草稿可以共存；modal 焦点阻塞和实际 Cookie I/O 串行不等于数据互为前置。

页面级 dirty 是两区 dirty/进行中/未确认写的并集。离页、退出、beforeunload 与主动全页离开使用 **一次聚合确认**，精确说明会放弃哪些本地草稿/请求跟踪：在用户确认前两槽均不 discard；继续编辑/关闭确认保留两槽；确认后核同身份、页面代次及捕获的两槽状态，再一次同步退休本次覆盖的状态。不得先清第一槽、再询问第二槽，亦不得清理确认打开后产生的新意图；若捕获状态失效，中止原导航而不自动同意。丢弃只放弃本地跟踪，不撤销可能已经提交的服务器配置。

仍只有 View 末尾一个确认 Dialog 宿主，放在旧业务 Dialog 与新 section 之后；局部重读/取消与页面级确认区分作用范围，同一时刻只保留一个确认 Promise。checking 卸载 View 时 App 期两区草稿、确认及原 Promise 留存，同完整identity恢复后原序重挂、无新 PUT/自动回答；真实离页/新身份/失权/dispose以 false 结算旧确认且清理 overlay/inert/滚动锁。焦点恢复仅在 View 仍挂载、当前目标可用、无更高 modal 时执行，沿已接受 fallback；不能全局查询/手动抢焦点修复层序。

## 4. 默认 root 的显式初始化

继续由 `app/account.go` 创建的同一个 Model Service 提供 HTTP 与两个 selector。在原 `deps.secret(ctx,...)` 的 Secret 成功和 ctx 检查后，将原 helper 扩为明确的 `initializeModelsAndUsage(ctx, models, summary, usageSchema)`：逐项调用 `models.Initialize(ctx)` → `models.InitializeMeetingSummarySelection(ctx)` → `projectUsage.reader.Initialize(ctx)`，每一步开始前检查同一个 ctx；任何错误/取消立即返回，后继不执行。总顺序为 **Secret→Model→Summary→Usage**，不 WithTimeout/Background 派生新启动预算，不从旧 `Service.Initialize` 隐式调用 Summary。

构造仍无 I/O。Summary 方法只做 S1 的技术 singleton 初始化，version="1"/model=null、与旧 ID 不同；重启/并发沿 S1 幂等保留原 ID/version/值，不猜 Model、不写命令/Audit/Event、不初始化 Project或生产Facts、不启动worker/Resolver。生产库必须已按正式迁移应用00020；缺表/损坏/旧技术行缺失导致启动失败，不能自动DDL或降级成功。未配置合法且服务可启动，ready仍503；不能将“运行已启动”解释为Meeting生成已就绪。原 Outbound/Object/Outbox 后继顺序和停止/join契约不变。

## 6. 验收与停止条件

### 6.1 必要离线与协议检查

纯/race/vet、完整 integration compile/list、两 cmd 实际 build、前端严格client/state/component/type/format/production build按真实闭包固定；Go list/TestMain动态构建/embed、候选与工具/hash在前后匹配，过滤 -run 不免除进程入口闭包。schema用真实安全body核完整closed字段，原失败与输入保留。没有明确实际运行的步骤不标PASS。

- GET/PUT 与 schema/client 的 required/null、未知/重复键、数字/前导零/int64边界、>2^53版本、错误singleton/Model/receipt、16KiB/600000B和流式超限；旧四项字节/lookup闭集不变。
- Summary新口3s/30s或更早parent在授权前生效，受控认证/body/service/response尾部未完成不得返回；真实native慢body/慢读/取消/不支持deadline/清除失败/keepalive成功路径，callback实际join、零遗留，不以fake writer证明socket已完。
- root纯顺序及同ctx，Secret/Model/Summary任一步错或取消不运行后继；构造零SQL、不重复初始化、新 Summary失败不能让Usage或listener成功继续。
- 同槽/跨槽两个未决intent，各自key/body/id/version不变；A取消/abandon/错误/lookup不能改变B。一个可见超时仍占owner到实际完成；另槽及login/logout/个人/Model不得越过尾部。当前/迟到401/403/CSRF、同身份重验/新Session、App.dispose均有精确断言。
- 仅本区重读/取消、双草稿一次导航确认、确认前零discard、cancel全保留、确认后精确清理、checking卸载重挂、旧Promise不能在新身份续行；失效读取可显式恢复，旧四项未配置/错误不挡Summary及反向。
