# agenteam 前端重设计

本项目编写的薄编排技能，复用已有设计、实现和验证能力。它提供阶段方法和检查门槛；页面规则、尺寸与 token 只在正式设计来源维护。角色、所有权、独立性与 Git 交付沿用[团队流程](../../../docs/development/agent-team/README.md)，不增加阶段审批。

## 触发、输入与来源

适用于重设计规范、完整页面样板、共享控件迁移、业务页面迁移与独立视觉验收。先确认当前任务允许的是规划、样板还是产品实现；读取[设计规范 v2](../../../docs/frontend-design/redesign/target-design.md)、[页面蓝图](../../../docs/frontend-design/redesign/page-blueprints.md)中当前模板，以及[执行计划](../../../docs/frontend-design/redesign/implementation-plan.md)中当前阶段。已有上下文只补读变化，不逐遍加载全部文档。

- 用户已要求对照 Linear 重新制定规范。新规范与其完整页面样板是重设计依据；旧 `styles/`、`layouts/`、现有 CSS token 和 Debug 是待迁移现状，不能以符合旧尺寸、颜色或卡片结构否决新设计。来源优先级与迁移范围见[重设计入口](../../../docs/frontend-design/redesign/README.md)。
- 参考 [Linear 官方产品研究](../../../docs/frontend-design/redesign/linear-reference.md)中的应用界面、官方产品文档与交互；官网营销 hero、渐变或宣传构图不作为工作界面模板。不将公开截图推导成 Linear 官方精确 token。
- 保持 **Dashboard → Projects → Workspace → project header menu** 对应的系统首页、项目列表、项目空间及项目内菜单。Linear 的 Workspace/Team 组织方式不能覆盖本项目的系统、Owner 与 Project 边界。
- 读取本次路由、组件接口、API 与状态来源。权限、Session、请求身份、幂等、Unknown、草稿、取消和恢复继续按业务契约执行；新设计没有授权补造服务能力、搜索、统计或导航入口。

## 阶段与技能组合

[frontend_designer](../../../.codex/agents/frontend-designer.toml) 负责完整页面设计、状态与授权样板，`frontend_worker` 承接正式 Vue 实现；[frontend_visual_reviewer](../../../.codex/agents/frontend-visual-reviewer.toml) 须未参与被审设计或实现，独立检查真实浏览器视觉与交互。`test_worker` 按需提供 harness，`verification_worker` 承担功能与风险验证；职责可按任务组合，不增加审批层或每阶段固定开齐角色。F0 进行设计和独立样板校验，F1—F7 按需开发/测试/独审，F8 汇合视觉、交互与功能结论，具体范围以阶段计划为准。

| 当前阶段 | 使用技能 | 可审查产物 |
| --- | --- | --- |
| 新规范与完整页面样板 | [frontend-design](../frontend-design/SKILL.md) + [web-design-guidelines](../web-design-guidelines/SKILL.md) | 当前页信息层级、完整布局、状态方案及与 Linear 产品参考的对应关系 |
| 应用框架、共享组件与页面实现 | [agenteam-vue-development](../agenteam-vue-development/SKILL.md)；写 Vue 测试时加 [vue-testing-best-practices](../vue-testing-best-practices/SKILL.md) | 可操作页面、必要组件调整、保留的业务行为与有意义自测 |

| 独立视觉与交互验收 | [agenteam-verification](../agenteam-verification/SKILL.md) + web-design-guidelines + agenteam-test-engineering | 按模板判定的通过/失败/未验证结论及定位清楚的返修项 |

## 执行顺序

1. 写清当前用户任务、主要对象、唯一优先动作、辅助信息、返回路径与滚动归属。先选择页面模板，再安排控件；对正式蓝图中的缺口给出可检查方案，范围内设计细节由负责人处理。
2. 先做项目列表、任务工作台、复杂设置页的完整样板，放入真实结构的中英文、长名称和足量内容，并检查正常、空、加载及失败状态。完整效果成立后才提炼共享框架、token 与组件；不能用孤立按钮、Debug 拼贴或 token 表作为全站迁移依据。
3. 依当前阶段迁移共享层和完整业务页面。复用可用的状态逻辑、接口与测试；新增布局先在完整任务中验证，避免给所有页面套同一种居中表单或卡片。发现共用接口冲突交唯一 owner 协调，未受影响工作继续。
4. 作者完成必要工程检查和浏览器自查后，交未参与被审设计、实现及其决策的验证者检查真实页面。`npm run check`、DOM 断言和 Debug 展示分别证明其范围，不能替代完整页面视觉、键盘与连续操作验收。

## 按模板检查完整页面

以下是检查方法；具体宽度、行高、颜色、断点和路由覆盖以 v2 及当前蓝图为准。

| 模板 | 必须能在页面中检查的结果 |
| --- | --- |
| Dashboard / 项目集合 | 当前层级明确；名称、状态和主动作先被看到；列表能横向比较对象；现有数据有合理首屏密度，空态不借假指标填充 |
| 设置 / 管理 | 栏目导航与表单正文分工清楚；字段按目的成组；保存靠近影响范围；危险区可辨认；复杂实体先选对象再编辑，不常驻堆叠全部新建/编辑表单 |
| 任务 / 资源工作台 | 项目上下文稳定；目录、主内容和属性各有职责；正文占主要空间；选择/打开对象后仍能辨认来源；滚动与窄屏收起不遮挡主动作 |
| 阅读 / 编辑 / 详情 | 正文有适当行宽和空间；元信息退后且可达；保存、关闭、返回与草稿恢复明确；长内容不被全局截断 |
| 账号 / 短任务 / 浮层 | 当前任务与必要字段清楚；错误在对应区域；提交中状态可辨；键盘顺序、关闭规则和焦点恢复成立；主要操作在窄屏可达 |

所有模板同时检查字体层级、对齐、表面与留白、对象与动作的距离。仅换色、缩间距、减边框、统一圆角，或把内容重排成重复卡片，不构成完整重设计。必要的错误、权限原因与 Unknown 不得为了简洁藏入难以发现的折叠区。

## 独立浏览器验收与返修

- 用同一路由、数据、状态、viewport、缩放和 theme 对比迁移前后整页与关键局部；注明浏览器和输入来源。Linear 图用于对照空间/任务模式，不作为跨产品像素相等断言。等待字体、异步状态与必要动画稳定后截图。
- 按当前阶段覆盖浅深主题、桌面/窄屏、长内容、空/加载/失败及适用权限、冲突、Unknown/恢复状态；用真实操作检查键盘、焦点恢复、缩放、reduced motion 与 overflow。执行计划中的矩阵是范围依据，不机械扩大到无关业务全量回归。
- 每项视觉发现写出页面/状态、观察到的问题、对应规范或蓝图、用户影响和修正方向。版式门槛失败即返修相应页面；权限、状态或恢复倒退按业务影响处理。作者自查与独立结论分别标注。
- 原 owner 修复后，在相同输入上复验受影响模板与共享层影响范围。相关输入未变的通过结果复用；不得用调整 fixture、放宽断言或删掉失败状态换取通过。浏览器未运行或某状态无法构造时，明确未验证并交负责人处理该范围。

## 简短交付

报告完成的页面/模板与实际文件、依据的 v2/蓝图及稳定输入、工程与浏览器实际结果、截图位置、失败/未验证与下一 owner，并注明停止写入状态。材料沿用任务现有路径和团队保存规则，不另建永久验收档案；规划完成、样板通过与真实业务完成分别说明。
