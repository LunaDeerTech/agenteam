# agenteam 前端开发

## 适用任务

用于 `frontend_worker` 按既定接口交付完整前端结果，负责有意义的自测及授权范围内的局部文档同步。
任务拆分、逐级汇报、并行与所有权、证据留存及交付规则见 [团队流程](../../../docs/development/agent-team/README.md)；以任务卡和共享规格明确范围，不因实现任务自行重定组件边界。

## 按需读取来源

- 开始前读 [仓库规范](../../../AGENTS.md)、任务卡和指定共享规格，后续仅补读变化及相关输入。
- 读 [前端开发基础](../../../docs/development/frontend/README.md) 与 [公共组件接口](../../../docs/development/frontend/components.md) 的相关章节。
- 从 [前端设计入口](../../../docs/frontend-design/README.md) 选择任务对应的 `layouts/` 文档。
- 从 [样式规范](../../../docs/frontend-design/styles/README.md) 选择任务对应的主题、密度和交互规范。
- 写 Vue 测试时读取相邻 [Vue 测试最佳实践](../vue-testing-best-practices/SKILL.md)，仅加载当前测试需要的参考。
- 浏览器任务使用仓库内[测试工程技能](../agenteam-test-engineering/SKILL.md)及锁定 Playwright harness；机器已有的外部 `playwright` 技能可按需辅助，其缺失不构成硬前提。

## 按可见行为实现

1. 从路由、页面、composable、API client 到已有 Ui 控件追踪真实调用链，先确认本次状态由谁持有、接口返回什么以及哪些端口尚未绑定。
2. 按当前接口列出涉及的加载、空态、权限拒绝、冲突、提交未知和恢复状态，明确用户动作与最终反馈。正式状态规则来自 API 与任务规格，不能从 Debug 样例推导。
3. 对异步读取标明请求身份和页面/资源身份，构造迟到响应与导航切换检查，防止旧结果覆盖新上下文。命令草稿、幂等键、原 payload 与 lookup 的保留和恢复严格沿对应契约实现。
4. 组件测试通过 props、emits、用户操作和渲染结果检查行为，避免只测内部方法或复制实现计算期望。先注册要观察的响应再触发动作；Promise flush、计时器推进和 DOM 更新分别等待。
5. 组合真实浏览器测试前确认正式资产、owned 后端与锁定 executable，按[测试工程技能](../agenteam-test-engineering/SKILL.md)关联 UI、网络响应和最终业务事实。环境缺失用[运行时技能](../agenteam-runtime-debugging/SKILL.md)定位和恢复，权限竞争按需组合[安全技能](../agenteam-security/SKILL.md)。

## 尽早接通真实调用

先核对模块职责、接口与调用方式、依赖版本及集成 owner。低风险小模块完成可调用功能和必要正常/失败基础测试后，立即向直接上级报告并配合隔离环境的真实上下游小范围联调；不先反复运行全量检查。深入或独立测试按风险并行，权限、Secret、数据和迁移等关键门禁在暴露相应风险前完成，可联调仍不等于正式完成。

每轮验证明确问题、受影响范围和结束条件，输入及相关依赖未变时复用通过证据；无新证据的重复失败转有界诊断和 owner 修复。首个可调用功能、基础检查后、首次联调、依赖变化或受阻时及时报直接上级；共享接口漂移立即报告并暂停受影响写入。

## 执行检查

1. 核对 root 分配的 worktree/cwd 与 `ai/` 模块任务分支，每条命令显式指定 `workdir`/cwd；再核对卡片修订、Git 基线、实际源码、依赖版本与文件/资源所有权，保留已登记的其他任务及用户改动。
2. 按既定 props/emits 完成正常与异常交互，核对源码类型与组件文档，在正式验收的同一原子变更中同步代码、测试与必要局部文档；公共接口冲突时只暂停受影响部分并报告直接负责人。
3. 遵循已确认的布局、主题、密度和交互规范，优先复用现有 Ui 控件、composables 与共享 tokens。
4. 共享组件不得引入 Debug 演示代码、数据或业务 API。
5. Debug 仅供开发，确保生产路由和构建继续排除其展示代码。
6. Vue 3 使用周边一致的 `<script setup lang="ts">`、模板及样式写法。
7. 除任务卡明确授权，不新增 Tailwind、Pinia、Testing Library 等依赖；依赖锁与生成文件按团队所有权规则处理。
8. 只格式化授权文件，不运行会重写整个仓库的格式命令。
9. 按变更影响执行适用工程检查和有意义的自测，记录命令、环境、稳定输入和实际结果；作者自测不冒充独立验收。

范围内实现细节、工具修正和常规排查自主处理。
测试应验证用户可见行为和异常处理，不机械复制参考示例。
对 MSW 等示例先核对项目依赖与 API 版本，不能直接引入不匹配方案。
涉及定时器时按实际 Vitest API 推进 fake timers，并在测试结束恢复。
`flushPromises` 不保证推进定时器，异步等待与时间推进应分别处理。
视觉或交互任务按卡片检查主题、窄屏、键盘、焦点恢复、减少动效和溢出。

分支不隔离端口、数据库和可写缓存；运行前核对实际资源 owner 或使用顺序，不能因目录不同就共享可写资源。

## 可恢复检查点

按[自动保存规则](../../../docs/development/agent-team/README.md#自动保存与跨设备恢复)，在阶段产物、交付和长检查前主动暂停保存范围写入，向直接负责人交出必要页面源码、测试与浏览器 harness、脱敏输入及实际状态，由 root 按各 worktree 独立 WIP commit/push 并确认远端，记录见[状态与恢复说明](../../../.agent-state/README.md)。保存用仓库内普通文件；WIP 不表示验收通过，子代理不执行本仓库 Git 写操作。

## 证据与交付

证据绑定 Git 基线、限定 diff 和停止写入状态或冻结修订，同时记录影响结论的相关依赖和环境。输入及相关依赖未变时可复用已通过结果，相关修改后重跑受影响检查。原始材料、简短任务结论与例外哈希按团队流程处理，不机械重复全部检查。

产品决策不能从 Debug 默认状态或测试 fixture 推导。交付实际修改文件、完整行为、局部文档和验证证据，以及失败、未执行项、阻塞与停止写入状态。未执行的检查不得报告为通过；未决决定/接口、未授权依赖或范围、所有权冲突，或排查无新证据时，按团队流程向直接负责人报告受影响部分并保留当前改动。
