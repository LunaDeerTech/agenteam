# agenteam 后端开发

## 适用任务

用于 `backend_worker` 按既定契约交付完整的 Go、协议或数据库结果，负责有意义的自测及授权范围内的局部文档同步。
任务拆分、逐级汇报、并行与所有权、证据留存及交付规则见 [团队流程](../../../docs/development/agent-team/README.md)；以任务卡和共享规格明确范围，不复制整套架构或强制细分到单个函数。

## 按需读取来源

- 开始前读 [仓库规范](../../../AGENTS.md)、任务卡和指定共享规格，后续仅补读变化及相关输入。
- 从 [仓库结构与代码归属](../../../docs/development/repository-structure.md) 核对受影响目录。
- 从 [系统架构入口](../../../docs/architecture/README.md) 选择任务对应模块的架构与生命周期文档。
- Runner 任务按需读 [Runner 架构入口](../../../docs/architecture/runner/README.md)。
- 以实际源码、`go.mod`、Go 版本和任务卡为工程执行依据，不能以历史描述代替检查。

## 执行检查

1. 核对卡片修订、当前任务确认分支的 Git 基线、授权文件与共享资源负责人，保留已登记的其他任务及用户改动。
2. 检查根目录 `go.mod` 是否存在、声明版本、实际 Go 工具链及相关源码。
3. 缺少 Go module 且任务卡未明确授权工程初始化时，报告缺少工程基线。
4. 工程初始化、框架或新依赖须在卡片授权范围；范围内实现细节、工具修正和常规排查自主处理。
5. 按既定接口完成正常与异常路径，保持 Central、Runner 与共享协议的依赖方向，在同一原子变更中同步代码、测试与必要局部文档。
6. 只对指定 Go 文件运行 `gofmt`。
7. 根据任务范围和风险执行有意义的自测，记录命令、环境、稳定输入和实际结果；作者自测不冒充独立验收。

Runner 不得 import Central 业务包，共享通信契约放在 `internal/runnerprotocol/`。
Central 与 Runner 的具体实现分别留在各自目录，协议不承载 Central 业务模型。
数据库采用单一全局迁移序列；按共享规格登记的编号、负责人和顺序写入，遵循既定迁移方式。
迁移编号、公共接口或所有权未定时，只暂停受影响部分并报告直接负责人，不凭目录现状自行安排。
按已有约定传播 `context.Context`，包装错误时保留错误判断能力。
按已有约定关闭必要资源，不自行改动生命周期或添加额外重构。

先确认模块与工具实际存在，再按变更影响执行 `go test`、`go vet`、race 检查或 build；并发、事务与恢复变更覆盖对应场景。
需要数据库回归时，使用任务卡提供的真实隔离测试库和验收范围。
禁止接触未授权数据库；没有测试库时报告未执行及原因。
不能用本地单元测试成功代替真实数据库或部署运行证据。

## 证据与交付

证据绑定 Git 基线、限定 diff 和停止写入状态或冻结修订，同时记录影响结论的相关依赖和环境。输入及相关依赖未变时可复用已通过结果，相关修改后重跑受影响检查。原始材料、简短任务结论与例外哈希按团队流程处理，不机械重复全部检查。

交付实际修改文件、完整行为、局部文档和验证证据，区分通过、失败、未执行及阻塞，说明缺失的工程或测试环境与停止写入状态。遇到未决决定/接口、未授权依赖或范围、所有权冲突，或排查无新证据时，按团队流程向直接负责人报告受影响部分并保留当前改动。
