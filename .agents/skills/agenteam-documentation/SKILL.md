# agenteam 文档归位

## 适用任务

用于已确认决定的批量、跨文档归位及文档一致性修正。实现者负责自己的局部文档同步，`documentation_worker` 不成为每项实现的必经环节。

先读 [仓库规范](../../../AGENTS.md)、[团队流程](../../../docs/development/agent-team/README.md)、任务卡和本次决定来源。公共分工、所有权、升级和交付规则以团队流程为准；只读取受影响的正式来源与实际差异，后续补读变化。

## 来源与归属

- 业务规则归位到 [架构专题](../../../docs/architecture/README.md)；前端布局和样式归位到 [前端设计](../../../docs/frontend-design/README.md)。
- [开发计划](../../../docs/development/development-plan.md) 保存模块顺序和门槛，具体接口与实现决定放在对应工作项规格，避免复制另一套规则。
- 开发团队的公共治理只在团队流程维护，角色与技能保留职责、专业要求和必要引用。
- 当前状态以仓库、任务卡修订和实际证据为准；历史记录保留当时事实，通过页首说明或新记录指向现行规则，不重写旧验收结果。

决定来源不完整或相互冲突时，标明冲突和影响，向主线程报告受影响部分；不能把聊天推测、Debug 默认值或未确认建议写成正式产品规则。

## 编辑与检查

1. 核对授权文件、基线与已登记的其他任务改动，按文件所有权修改，保留他人工作。
2. 将每项决定落到明确的正式来源，更新授权范围内的入口和交叉引用；需要修改范围外文件时报告主线程，不自行扩大写入范围。
3. 保持既有术语、章节结构和文件命名，删改正文时同步受影响的本地路径与 fragment，避免相互矛盾或循环解释。
4. 检查受影响 Markdown 的相对链接/fragment、标题、列表、表格与代码块结构，以及 UTF-8、LF、末尾换行和尾空格；运行限定本次文件的 `git diff --check`，新增文件也须覆盖格式检查。
5. 按需要解析配置或检查技能 frontmatter；检查实际字段和引用，不仅检查文本是否出现。

纯文档改动不触发无关产品测试，也不为低影响可逆编辑新增无意义测试。配置可解析、技能可发现、实例实际运行和 CLI 自动加载分别记录，不能互相替代。低影响文档的作者自查与主线程审查按团队流程执行，不另设固定审批链。

## 交付

报告实际归位内容和文件、检查命令/环境、基线及相关文件指纹或冻结修订、结果和限制。输入及依赖未变时可引用已有检查；相关修改后重跑受影响检查，旧结果不能证明新文本。

列出未验证内容、跨范围引用待处理项和停止写入状态。没有实际执行的检查不标记为通过，文档一致性不等于对应产品能力已经实现或验收。
