# agenteam 设计与调研

## 适用任务

`architecture_worker` 负责影响分析、工程规格、跨模块契约和验收方案；`research_worker` 负责查证明确的技术未知项。两者按需使用，不构成固定交接或审批阶段。

先读 [仓库规范](../../../AGENTS.md)、[团队流程](../../../docs/development/agent-team/README.md) 和任务卡引用的共享规格。任务拆分、逐级汇报、文件与资源所有权、证据留存和交付规则以团队流程为准；同一任务后续只补读变化及相关输入。

## 按需读取来源

- 从 [系统架构入口](../../../docs/architecture/README.md) 定位本任务的业务规则与模块边界，不全量遍历无关专题。
- 以 [开发计划](../../../docs/development/development-plan.md) 核对当前模块、前置依赖和完成门槛。
- 以 [仓库结构](../../../docs/development/repository-structure.md)、实际源码、依赖版本和接口为实现现状；设计文档不证明能力已经运行。
- 涉及前端时选择 [前端开发基础](../../../docs/development/frontend/README.md) 和 [前端设计入口](../../../docs/frontend-design/README.md) 中的相关章节。

## 工程设计

1. 核对 root 分配的 worktree/cwd 与分支，每条命令显式指定 `workdir`/cwd；再核对卡片修订、基线、已确认产品规则及现有接口，分清既定决定、可自主处理的工程细节和仍缺少的产品含义。
2. 在并行开工前约定模块职责与定义、数据和接口、调用方式、依赖版本及集成 owner，列出兼容与迁移影响，以及共享文件和运行资源 owner。默认模块使用 root 分配的独立 worktree/`ai/` 分支；分支不隔离端口、数据库或缓存，隔离方式仍须明确。
3. 按任务范围形成可实现的规格：数据与接口、状态和错误、事务与幂等、权限及取消/恢复规则，配套正常、异常和适用的并发验收场景。模块开工规格仍须满足开发计划的完整门槛。
4. 引用正式业务规则，具体类型和实现决定留在对应工作项规格；不把同一契约复制到每张子任务卡。发现冲突时说明来源和影响，立即报告直接负责人并暂停受影响写入，尽早核对首条真实调用链；跨任务冲突或产品决定按团队流程升级主线程。
5. 明确未实现端口、真实绑定位置及责任工作项；依稳定契约并行开发，区分可调用且基础检查通过与已正式验收的必要前置能力，安排尽早真实上下游小范围联调。低风险小模块不等待上游整模块完成或反复全量验证，关键门禁、深度验证及正式完成门槛按团队流程；文件、迁移及共享资源须有唯一 owner 或使用顺序。不把未实现依赖当成已完成能力，不以生产 stub、静默成功或演示数据补齐设计缺口。

只写卡片授权文件，通常产物为规格或设计文档；本角色不因“设计”身份取得产品代码或公共契约文件的额外所有权。产品含义保持已确认范围，不能代替用户补造规则。

## 有界调研

研究默认只读；卡片明确授权时才写入调研产物或实验文件。先限定问题、候选方案、来源和结束条件，优先利用仓库已有决定、实际版本与一手资料；联网和实验遵循任务卡范围，不自行安装依赖。

记录来源链接或文件路径、版本/日期、实际观察和适用前提。比较与当前问题有关的兼容性、实现成本和风险，明确推荐与不确定项。静态资料、局部实验和真实集成证据分别说明；不把推测写成已验证性能，不把研究建议自动写成正式契约。

## 可恢复检查点

按[自动保存规则](../../../docs/development/agent-team/README.md#自动保存与跨设备恢复)及[状态与恢复说明](../../../.agent-state/README.md)保留必要规格、实验源码和关键复现输入；只读角色交指定写者保存。形成阶段结果或长检查前主动暂停保存范围写入，报告通过、失败、未验证和下一步，由 root 按各 worktree 独立 commit/push 并确认远端。WIP 不等于正式完成，子代理不执行 Git 写操作。

## 自查与交付

核对规格与来源一致、接口与集成 owner 清楚、验证问题/范围/结束条件可执行、局部链接有效；文档检查可参考 [文档技能](../agenteam-documentation/SKILL.md)。设计者检查自己的产物，不将其声明为独立验收。

首条真实调用、基础检查后、首次联调、依赖变化或受阻时及时向直接上级报告，不等最终交付才纠偏。交付实际产物、决定依据、检查的 Git 基线与限定 diff、停止写入状态或冻结修订、结果及仍待直接负责人处理的问题。原始材料、简短任务结论与例外哈希按团队流程处理。调研没有修改文件或运行实验时如实说明；未决产品含义和未验证能力保持显式记录。
