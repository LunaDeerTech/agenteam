# agenteam 审查与验证

## 适用任务

用于 `verification_worker` 按风险执行独立审查或验证；作者可复用适用检查，但不得把自查声明为独立验收。
任务拆分、逐级汇报、独立性与风险分级、所有权、证据留存和交付规则见 [团队流程](../../../docs/development/agent-team/README.md)。先确认卡片为只读审查，还是允许写入指定测试或验证记录；成组文档归位使用 [文档技能](../agenteam-documentation/SKILL.md)。

## 按需读取来源

- 读 [仓库规范](../../../AGENTS.md)、任务卡、共享规格和实际 diff；同一任务后续只补读变化及相关输入。
- 前端影响读 [前端开发基础](../../../docs/development/frontend/README.md) 与 [验证记录](../../../docs/development/frontend/verification.md)。
- 组件验证读 [公共组件接口](../../../docs/development/frontend/components.md) 及任务对应设计文档。
- 写 Vue 测试时读取 [Vue 测试最佳实践](../vue-testing-best-practices/SKILL.md) 的对应参考。
- 后端验证从 [仓库结构](../../../docs/development/repository-structure.md) 和 [系统架构](../../../docs/architecture/README.md) 选择相关来源。
- 浏览器任务使用本仓库[测试工程技能](../agenteam-test-engineering/SKILL.md)与锁定 harness；外部 `playwright` 技能可按需辅助，缺少它不阻止使用仓库已安装 CLI。

## 形成有判别力的审查

把目标契约、实际修改点和已有证据对应起来，先选能够区分正确与错误实现的场景，再决定补充什么检查。每个发现给出触发输入、预期条款、实际行为和影响；只看到代码模式可疑时标为待证假设，不写成已复现缺陷。

审查重点沿事实流选择：身份和资源何时确定、何时重验权限、写入落在哪个事务、错误或取消后哪些输出仍可见、哪个持久事实证明完成。检查实现与测试是否共享同一个错误假设；恢复、权限和并发改动至少覆盖任务相关的失败或竞争边界。

按需要组合[数据库技能](../agenteam-database/SKILL.md)或[安全技能](../agenteam-security/SKILL.md)；需要新增 fixture、故障注入或浏览器用例时用[测试工程技能](../agenteam-test-engineering/SKILL.md)，工具和环境问题用[运行时技能](../agenteam-runtime-debugging/SKILL.md)。无测试写权时给出最小复现，由负责人安排指定写者。

核命令是否真的执行并命中目标测试，区分编译、列举、跳过、实际断言与最终资源终态。作者证据可在相关输入未变时复用；独立验证选择能检查关键假设的补充场景，不机械重跑全部检查。

## 验证时机与结束条件

每轮先说明要回答的问题、受影响范围和结束条件，再选择最小适用检查。低风险小模块完成可调用功能和必要正常/失败基础测试后，配合隔离的真实上下游小范围联调；深入或独立验证可按风险并行，不让全量矩阵成为联调前的固定等待。权限、Secret、数据、迁移等关键门禁在暴露相应风险前通过，联调中发现的问题和未验证范围不计为正式完成。

已有通过证据的输入、相关依赖与环境未变时直接复用并注明来源。没有新证据的重复失败转为有界诊断，明确下一条可区分假设的检查、结束条件和修复 owner，不再扩大矩阵或反复重跑。测试方法和证据记录只服务当前问题，不新增每卡方法审批、全树指纹或额外开发主线。

## 执行检查

1. 核对 root 分配的 worktree/cwd 与任务分支，每条命令显式指定 `workdir`/cwd；再核对卡片修订、Git 基线、授权范围、资源 owner 及独立性，保留其他任务和用户改动；参与过该实现的实例不能承担其独立验收。
2. 确认审查范围已停止写入，以 Git 基线、限定 diff 和停止写入状态或明确冻结修订绑定输入；仍变化的范围不能形成有效结论，最终集成也须等待相关写入停止。
3. 审查实际 diff、既定契约和作者证据，按风险覆盖正常、异常及适用的权限、数据、事务、协议、并发和恢复场景，不用快照代替行为验证。
4. 核对已有结果的输入、依赖和环境；未变且适用时复用，相关改变后重跑受影响检查，不无条件重复全量验收。
5. 前端先运行受影响的工程与浏览器子集，完整范围确有需要时再选择 `npm run check --prefix web`；后端先确认实际工程和授权的隔离环境，再执行适用验证。
6. 仅改 docs/config 时，不运行不相关的前端或 Go 测试；文档检查相对链接/fragment、受影响引用和 Markdown 结构。
7. 只写卡片允许的测试或验证记录，不私改产品代码；执行限定本次文件的 `git diff --check`，新增文件也须覆盖格式检查。
8. 记录实际命令、环境、稳定输入、结果和限制；输入不完整或检查未运行时保持未验证状态。哈希仅在团队流程规定的例外需要时限定范围计算一次并复用。

角色 TOML 以 `name` 字段识别角色；从实际目录枚举配置文件，解析字段并检查集合，不假定文件名与角色名完全一致。项目技能检查 frontmatter 的 `name`、`description`、目录对应关系及引用。配置可解析、技能可发现、显式创建实例成功和 CLI 自动加载分别举证，不把其中一项当作其余项已通过。

视觉或交互变更按任务卡检查浅深色、桌面与窄屏、键盘导航、焦点恢复。
同时检查 reduced motion 和 overflow，等待必要的动画或异步状态结束。
可重复生成的原始命令日志和浏览器截图默认放在忽略的 `output/ai/`；后续必需的失败复现脚本、必要输入与不可再生关键证据按下节保存到受 Git 跟踪的路径。任务记录简写必要结论、失败事实和边界，不默认生成永久验收归档包、重复报告或轮次流水。
没有运行浏览器时，不能声称已验证视觉或交互。
不为简单文档或可逆改动新增无意义测试。
Vue 测试示例应匹配实际版本；定时器按实际 Vitest API 推进。
`flushPromises` 不保证推进定时器，不以等待 Promise 替代时间推进。
数据库测试只使用任务卡授权的隔离测试库，不接触其他数据库。

## 可恢复检查点

按[自动保存规则](../../../docs/development/agent-team/README.md#自动保存与跨设备恢复)，在阶段结果、交付和长检查前主动暂停保存范围写入，交出必要复现源、harness、脱敏输入及通过/失败/未运行事实，由 root 按各 worktree 独立 WIP commit/push 并确认远端，保存记录见[状态与恢复说明](../../../.agent-state/README.md)。只读任务由负责人安排唯一写者保存仓库内普通文件；WIP 不表示验收通过，子代理不执行本仓库 Git 写操作。

## 阻塞与交付

基础检查后、首次联调、依赖变化和受阻时及时报直接上级；共享接口漂移立即报告并暂停受影响写入，不等整轮完成。范围内工具修正和常规排查自主处理。发现实现 bug 时给出文件、场景和证据，交直接负责人安排原执行角色修复；未决决定/接口、未授权依赖或范围、所有权冲突，或排查无新证据时，按团队流程逐级升级受影响部分。

交付审查文件与实际写入文件，分别列出通过、失败、未验证；每项附稳定输入、实际命令、环境、证据或未执行原因，注明复用结果、剩余风险、阻塞及停止写入状态。只完成局部检查时，不宣称模块已完整验收。
