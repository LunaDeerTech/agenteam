# agenteam 审查与验证

## 适用任务

用于 `verification_worker` 按风险执行独立审查或验证；作者可复用适用检查，但不得把自查声明为独立验收。
公共分工、独立性与风险分级、所有权和交付规则见 [团队流程](../../../docs/development/agent-team/README.md)。先确认卡片为只读审查，还是允许写入指定测试或验证记录；成组文档归位使用 [文档技能](../agenteam-documentation/SKILL.md)。

## 按需读取来源

- 读 [仓库规范](../../../AGENTS.md)、任务卡、共享规格和实际 diff；同一任务后续只补读变化及相关输入。
- 前端影响读 [前端开发基础](../../../docs/development/frontend/README.md) 与 [验证记录](../../../docs/development/frontend/verification.md)。
- 组件验证读 [公共组件接口](../../../docs/development/frontend/components.md) 及任务对应设计文档。
- 写 Vue 测试时读取 [Vue 测试最佳实践](../vue-testing-best-practices/SKILL.md) 的对应参考。
- 后端验证从 [仓库结构](../../../docs/development/repository-structure.md) 和 [系统架构](../../../docs/architecture/README.md) 选择相关来源。
- 浏览器任务使用环境已有的 `playwright` 技能；不可用时报告无法执行。

## 执行检查

1. 核对卡片修订、`main` 基线、授权范围、所有权及独立性，保留其他任务和用户改动；参与过该实现的实例不能承担其独立验收。
2. 确认审查范围已停止写入，以基线及相关文件指纹或明确冻结修订绑定输入；仍变化的范围不能形成有效结论，最终集成也须等待相关写入停止。
3. 审查实际 diff、既定契约和作者证据，按风险覆盖正常、异常及适用的权限、数据、事务、协议、并发和恢复场景，不用快照代替行为验证。
4. 核对已有结果的输入、依赖和环境；未变且适用时复用，相关改变后重跑受影响检查，不无条件重复全量验收。
5. 按前端变更影响选择 `npm run check --prefix web` 等工程检查及浏览器验收；后端先确认实际工程和授权的隔离环境，再执行适用验证。
6. 仅改 docs/config 时，不运行不相关的前端或 Go 测试；文档检查相对链接/fragment、受影响引用和 Markdown 结构。
7. 只写卡片允许的测试或验证记录，不私改产品代码；执行限定本次文件的 `git diff --check`，新增文件也须覆盖格式检查。
8. 记录实际命令、环境、输入版本或文件指纹、结果和限制；输入不完整或检查未运行时保持未验证状态。

角色 TOML 以 `name` 字段识别角色；从实际目录枚举配置文件，解析字段并检查集合，不假定文件名与角色名完全一致。项目技能检查 frontmatter 的 `name`、`description`、目录对应关系及引用。配置可解析、技能可发现、显式创建实例成功和 CLI 自动加载分别举证，不把其中一项当作其余项已通过。

视觉或交互变更按任务卡检查浅深色、桌面与窄屏、键盘导航、焦点恢复。
同时检查 reduced motion 和 overflow，等待必要的动画或异步状态结束。
浏览器截图放在 `output/playwright/`，遵循仓库忽略规则，不自动纳入提交。
没有运行浏览器时，不能声称已验证视觉或交互。
不为简单文档或可逆改动新增无意义测试。
Vue 测试示例应匹配实际版本；定时器按实际 Vitest API 推进。
`flushPromises` 不保证推进定时器，不以等待 Promise 替代时间推进。
数据库测试只使用任务卡授权的隔离测试库，不接触其他数据库。

## 阻塞与交付

范围内工具修正和常规排查自主处理。发现实现 bug 时给出文件、场景和证据，交主线程安排原执行角色修复；未决决定/接口、未授权依赖或范围、所有权冲突，或排查无新证据时，按团队流程升级受影响部分。

交付审查文件与实际写入文件，分别列出通过、失败、未验证；每项附稳定输入、实际命令、环境、证据或未执行原因，注明复用结果、剩余风险、阻塞及停止写入状态。只完成局部检查时，不宣称模块已完整验收。
