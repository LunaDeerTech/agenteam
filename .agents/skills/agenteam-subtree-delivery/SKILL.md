# agenteam 子树交付

用于 `delivery_lead` 及所有层级承担子目标的角色。存在可独立推进的完整结果时，优先同时委派多个下级；收益不足的简单任务直接完成。模型、动态容量、文件所有权、独立性、升级和 Git 权限遵循[团队流程](../../../docs/development/agent-team/README.md)；本技能提供并行调度与收敛方法。

## 输入与产物

输入是已确认目标、当前规格、实际 Git 差异、已接受的前置能力、全树当前可用容量和实际资源约束。先读[当前分支记录](../../../.agent-state/current.md)和目标工作项，再按需检查[开发计划](../../../docs/development/development-plan.md)的依赖，不遍历全部历史。

产物是完整子目标的实现、测试、必要文档及简短交接。拆分和所有权可在派工消息或现有任务记录中维护，不另建永久任务树、哈希清单或层层审批表。

## 从结果拆分

1. 用一个可观察结果定义完成条件，再逆向定位入口、领域服务、存储或外部端口和验证事实。列明本次真正接通的路径与仍未绑定的端口。
2. 对每个依赖核对实际接口和适用验收证据，区分已能消费、只存在契约和缺失实现。只消费已接受子能力的任务可独立推进；生产未绑定依赖不能靠测试替身宣布完成。
3. 按可独立实现和验证的结果切分，列出依赖已满足且所有权、资源已明确的就绪集。每份派工给出输入、预期行为、唯一写者、验收场景和升级条件；局部设计由接收者处理。
4. 先解决跨任务接缝：共享接口、迁移编号、依赖锁文件、根装配、生成物、缓存、端口、数据库及 fixture 的唯一所有者和隔离方式。同一工作树按文件分配写者；测试资源使用任务专属目录、端口、库或 fixture。无法隔离的共享资源明确使用顺序。

## 动态并行派工

1. 各层从就绪集中优先同时分发能独立推进的完整结果。同角色是能力模板，可以用不同 `task_name` 创建多个实例，例如两个 `backend_worker` 分别交付边界清楚的领域结果；每个实例都有独立目标和所有权。
2. [全树容量](../../../docs/development/agent-team/README.md#依赖所有权与并行)动态共享，不按角色或子树预设固定人数。每次交付、阻塞解除或资源释放后，重新核实际可用容量并补派就绪任务；完成一个就安排下一个，必要时复用合适的已有实例。任务结束声明不等于运行时名额已释放。
3. 同时考虑执行与必要独立验证，负责人继续承担设计、整合或排障。没有独立工作可做的中间负责人应合并职责或直接执行，避免等待下级的负责人链占满实际容量。
4. 按真实瓶颈调整并行度：CPU、内存、I/O、构建缓存竞争、端口、数据库连接和 fixture 容量紧张时减少相关并发，资源恢复且仍有就绪工作时增加。不把某次观察到的席位数写成永久规则，也不以巨量创建请求反复撞运行时限制。
5. 无真实空位或资源仍冲突时，复用合适实例或顺序执行受影响工作，并报告具体原因与解除条件；其他就绪结果继续推进。多个负责人共享容量发生冲突时交 root 协调，不为每个正常补派重新逐级申请固定配额。

本树负责人分配和维护局部所有权，跨子树共享文件或资源由 root 协调。切换写者前，原写者暂停相关写入并交出未完片段、差异和仍运行命令，新写者接手后原写者保持只读。只读探索可以并行；正式审查只对已停止写入的片段或可定位冻结修订形成结论，输入变化后补核受影响部分。

## 收敛与验证

收到子任务交付时先核三件事：实现覆盖了哪些行为；哪些真实依赖已经接通；证据实际运行了什么。缺文件、只编译、测试未命中或资源未退出时，把缺口退回相应所有者，保留已有有效结果。

集成先检查接口接缝和共享资源，再运行能暴露组合缺陷的最小场景。例如服务库与 HTTP 分别通过后，仍需适用的真实授权、事务结果与 HTTP 输出组合检查。按风险安排未参与实现的实例独立验证；参与了实现决策的负责人不把自己的复核称为独立验收。

返修消息包含触发输入、实际结果、预期契约和最小复现。原所有者修复后，只补跑影响结论的场景；同输入、同依赖下已有通过证据可复用。跨子树契约冲突、授权范围变化或未决产品含义交直接上级，其余局部排障持续处理。

## 主动保存与交付

形成可恢复片段、准备长检查或交付时，按[自动保存规则](../../../docs/development/agent-team/README.md#自动保存与跨设备恢复)暂停保存范围的写入，向上级提供明确必要文件、已知失败、仍在运行的命令和下一步。源码、harness 与必要输入须是仓库内普通文件，不能只有外部临时路径或符号链接；由 root 自动提交推送 WIP。

最终简报给出完成结果、实际文件、适用验证、未完成接缝和资源终态。WIP 远端保存、子任务完成、独立验证通过与整个模块完成分别陈述；某个前置缺失时只阻塞依赖它的工作。
