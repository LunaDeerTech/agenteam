# 跨设备接续

这里保存继续开发所需的最小状态。[current.md](current.md) 描述当前任务分支上的实际进度；[任务台账](../docs/development/agent-team/tasks.md) 保存总体产品状态。未完成源码和测试优先放正式路径，尚无正式归属的必要脚本或脱敏输入可放 `.agent-state/<task>/`。这些文件进入 Git；原始日志和可重建产物仍放忽略的 `output/ai/<task>/`。

## 自动保存

主线程为任务创建 `ai/<task>` 分支，各级代理在安全边界停止本次范围的写入。完成一个可恢复片段、获得新验证结论、交付子任务、长时间检查或等待前、暂停或回复用户前，都要主动保存；持续有改动时约每 5 分钟在下一个安全边界保存。无需用户说“提交”或“我要换设备”。

更新 `current.md`：任务目标、状态（进行中/阻塞/完成）、实际分支、已完成与未完成内容、必要文件路径、已运行检查及失败、环境恢复命令、下一步。随后执行：

```sh
python3 scripts/ai-checkpoint.py save --message 'wip: task checkpoint' -- path/to/source path/to/test
```

工具依赖 Git 和 Python 3.9 及以上版本，无额外 Python 包。文件参数逐个明确列出，可含新增、修改、删除文件；不能用仓库根目录或整个目录。工具自动纳入 `current.md`（包括首次新增），创建 WIP 提交并推送 `origin` 同名 `ai/` 分支。没有文件变化也会尝试推送尚未同步的提交。未完成源码可以保存；验证状态必须如实记录。若只有状态变化，可以不传额外文件。

工具拒绝受保护分支、分离 HEAD、被忽略的指定文件、符号链接和无关暂存改动，不自动切换分支、不强推。必要材料误放忽略目录时，先移至正式路径或这里，不用 `git add -f` 把日志目录全部提交。必要文件若是指向本机其他目录的符号链接，先把实际内容保存为仓库内的普通文件；只提交链接不能恢复目标内容。不要保存真实凭据、私人配置或可重新下载的依赖。

只有 push 成功才完成跨设备保存。断网、认证或远端冲突时保留本地提交，明确当前未同步，并在下一安全边界和离开前自动重试。其他设备已推送时，先 fetch、检查并整合双方改动，再普通 push；不得强推覆盖。运行中的 agent 负责调用工具，这不是后台守护程序，不能保证突然断电前最后一次保存之后的编辑。

## 新设备恢复

新 agent 自动检查本地改动并执行以下只读发现步骤，不等用户另行要求恢复：

```sh
git fetch origin
git for-each-ref --sort=-committerdate --format='%(refname:short)' refs/remotes/origin/ai/
git show origin/ai/<task>:.agent-state/current.md
```

根据用户当前任务和检查点的进行中/阻塞状态选择分支，不能仅按时间选中无关任务。若有多个无法区分的活动任务，只澄清任务目标。已完成且整合到主分支的检查点不再当作活动任务。确认工作区可安全切换后：

```sh
git switch --track -c ai/<task> origin/ai/<task>
```

已有本地任务分支时切换到该分支并检查与远端的差异；不得丢弃本地未推送提交。默认分支上有未提交工作时，先在新任务分支妥善保存；不能用 reset、clean 或强制切换清场。按检查点恢复依赖，核对实际源码，再从明确下一步继续。设备私有路径、进程、终端会话和内存不能跨设备继承，必须有必要的源码与启动命令。

## 最终交付

WIP 检查点为接续服务，不代表验收通过。验收后将本次 WIP 合并为一个正式结果提交，把实现、测试、必要文档和状态更新一起交付；不另造 `docs archive` 提交或哈希清单。将检查点状态改为完成并指出实际下一步，避免新设备重复执行已完成任务。详细团队规则见[开发团队流程](../docs/development/agent-team/README.md)。
